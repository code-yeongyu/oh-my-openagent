# src/features/hook-message-injector/ — Hook Message Context

## OVERVIEW

Message storage and lookup helpers used by hooks to recover original message context and inject derived system content without coupling every hook to SDK message shapes.

## WHERE TO LOOK

| Task | Location |
|------|----------|
| Public boundary | `index.ts` (re-exports the `injector.ts` surface) |
| Message write path | `message-injection.ts` (`injectHookMessage`), `message-directory.ts` (`getOrCreateMessageDir`) |
| Stored-message lookup | `json-message-lookup.ts` (`findNearestMessageWithFields`, `findFirstMessageWithAgent`) |
| SDK message lookup | `sdk-message-lookup.ts`, `sdk-message-context.ts` (`findMessageContextFromSDK`) |
| Context resolution | `context-resolver.ts` (`resolveMessageContext`) |
| Identifiers and storage constants | `id-generation.ts`, `constants.ts` (`MESSAGE_STORAGE`) |
| Contracts and coverage | `types.ts`, co-located tests |

## CONVENTIONS

- Preserve both stored-message and SDK-message paths; hooks may receive either representation.
- IDs and filesystem paths are generated by the feature helpers, not reconstructed by callers.
- Context lookup is nearest/first by explicit fields and must remain deterministic for sparse histories.
- Tests use Bun and temporary directories; filesystem writes must use the same helpers as production.

## ANTI-PATTERNS

- Do not parse message storage ad hoc in individual hooks.
- Do not inject text before resolving the original message context and tool permission metadata.
- Do not silently reinterpret absent fields as a different agent or session.
