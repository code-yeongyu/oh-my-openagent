# Configuration editor terminal design context

The editor is a keyboard-driven product surface for local configuration declarations. Preserve the established Clack select/text/note/log rhythm, terminal theme and user-selected monospace font. This feature introduces no color, spacing, typography or animation tokens. Shared primitive ownership remains `prompt.ts` (`choose`, `input`, `displayText`), with `@clack/prompts` owning rendering and terminal focus.

The canonical form/validation owner is the terminal-independent `backend.ts` over `session.ts`; prompts stage values and never write directly. Save/discard, backups and concurrent-change errors retain the existing menu contract. Profile CRUD is scoped to the chosen file. The list describes declarations, never claims merged effective settings, model access, price or live activation. Creation/copy returns to that profile's editor; deleting the current profile returns to Shared. Delete defaults to Keep, states its exact file/name and deferred persistence, and requires an explicit second choice. Unsaved staged edits can be discarded through the normal exit flow.

New names reject blank, reserved and terminal control characters. Existing labels and errors use `displayText` before terminal output. Arrow keys and Enter operate selection; Ctrl+C follows the canonical editor cancellation path. Relevant verification is real PTY keyboard interaction at narrow and standard terminal sizes, xterm.js screenshots, resulting configuration inspection, and backend/persistence regression tests. The UI language is English per repository policy; no locale or market-specific business behavior is added.
