# External user-input API

The Senpi adapter exposes an optional in-process extension-event API for
third-party integrations that submit actual user interactions. Integrations
do not need to import adapter internals or know which components consume input.

## Submitting an interaction

Emit `omo:send-user-input` on the host's shared extension event bus:

```ts
const request = {
  sessionId: ctx.sessionManager.getSessionId(),
  send: () => pi.sendUserMessage(content, options),
  handled: false,
}
pi.events?.emit("omo:send-user-input", request)
if (!request.handled) request.send()
```

- `sessionId` is the durable host session ID, obtained from the current session
  manager. It is not an integration's own connection or routing ID.
- `send` submits the interaction through the native host API. The matching
  adapter invokes this callback synchronously, once, inside its attribution
  context. The host can continue processing asynchronously.
- `handled` is the mutable claim flag. A matching active adapter sets it to
  `true` before invoking `send`. A missing event bus/listener, foreign session,
  inactive adapter or malformed request leaves it unclaimed.
- If the request is unclaimed, the producer calls `send` itself. This fallback
  retains normal host behavior; it does not grant user provenance inside OMO.

Use this API only for a real user interaction. Background work and messages
generated by command handlers should use the native API directly.

## Processing guarantees

The adapter installs attribution before component input hooks are registered.
Those hooks see the initiating input as `rpc`, the existing real-user channel.
The actual host event retains its original source. The host still owns input
IDs, async transform chaining, images, skill expansion, queue modes and input
disposition events. Input hooks are not replayed and IDs are not manufactured.

Each submission can attribute only its first real host input ID. Later
programmatic sends inheriting its async context remain extension-sourced.
Overlapping submissions are isolated; other sessions cannot claim the request.
Session shutdown invalidates outstanding submissions and removes the listener.

The event bus coordinates trusted extensions in the same process. It is not a
network endpoint or a security boundary against arbitrary extension code.
