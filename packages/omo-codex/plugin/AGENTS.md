# plugin — vendored Codex plugin bundle (`@sisyphuslabs/omo-codex-plugin`)

**Score 13** (distinct package boundary between the adapter and 13 component dirs; hook packages carry their own guidance).

## OVERVIEW

The shipped Codex plugin namespace `omo` (marketplace `sisyphuslabs`), v5.0.0-beta.51. npm workspaces root for the 10 component packages; owns aggregate hook wiring, MCP declarations, and the build/sync pipeline. Component roster, sync-skills pipeline, and install targets are owned by the package AGENTS.md — not repeated here.

## STRUCTURE

| Path | Role |
|------|------|
| `components/` | 10 workspace components + `bootstrap` (standalone, deliberately outside workspaces), `test-support`, `lcx`. Hook packages own their `AGENTS.md` |
| `hooks/` | 21 hand-maintained aggregate hook JSON files; build updates status labels, not wiring |
| `scripts/` | Build/sync/migration orchestration (own AGENTS.md) |
| `test/` | node:test black-box contract suite (own AGENTS.md) |
| `shared/` | `getCodexOmoConfig()` unified-config loader + startup config migration (`src/config-loader.ts`, `src/config-migration.ts`) |
| `skills/` | GENERATED by `sync-skills.mjs`; gitignored except the two tracked shared copies (`init-deep`, `ulw-plan`) |
| `.codex-plugin/plugin.json` | Aggregate manifest Codex consumes |
| `.mcp.json` | 4 servers: `git_bash`, `lsp` (local stdio) + `grep_app`, `context7` (remote) |

## WHERE TO LOOK

| Task | Location |
|------|----------|
| Add/modify a component hook | Component's `hooks/hooks.json` AND aggregate `hooks/*.json`; register additions in `.codex-plugin/plugin.json` |
| Aggregate hook side | Event/behavior-named `hooks/*.json`; aggregate Windows dispatch uses bootstrap's `node-dispatch.ps1` |
| MCP server enable/paths | `.mcp.json`; install-time rewriting in `../src/install/codex-cache-bundled-mcps.ts` |
| Unified `[codex]` config resolution | `shared/src/config-loader.ts` |
| Build pipeline internals | `scripts/AGENTS.md` |

## CONVENTIONS

- Build order is fixed: `sync-version` → `sync-hook-status-messages` → `build-bundled-mcp-runtimes` → `materialize-shared-upstreams` → `sync-skills` → `build-components` (all via `npm run build`).
- `(OmO <version>)` `statusMessage` stamps are generated by sync scripts; never hand-edit.
- `skills/` is build output: edit component/shared skill sources, then rebuild. The two tracked copies are still overwritten by sync; generated nested AGENTS.md files belong to their source skill, not this aggregate tree.
- Tests run with `node --test`, NOT bun/vitest: root `bunfig.toml` excludes `plugin/**` from the root bun suite.

## ANTI-PATTERNS

- Do not expect `sync:hooks` to create hook registrations or Windows commands; it only stamps existing labels.
- Do not infer every hook filename uses `checking`: loading, matching, recording, enforcing, guarding, and resetting are also shipped.
