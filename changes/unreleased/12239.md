## 2026-11-03 - The architect category implements and debugs instead of only proposing (#12239)

The builtin `architect` category's caller-facing description said "propose designs rather than implement" and its prompt append opened with "NOT an implementer", so callers kept file-changing work away from it and children stopped at a proposal. No tool policy was involved: a category plan carries no agent type or tool list, so the child already had the parent's full tool set. The description now covers design plus broad multi-source debugging carried through to implementation, the append adds a debugging step and a change-and-verify step, and the existing `<Advisory_Mode>` block still turns a task marked advisory-only into a no-edit write-up. The plan-consultant tool list and the guide pages stop calling the category read-only. `requiresModel` and the fallback chain are unchanged.
