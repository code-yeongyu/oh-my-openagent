### Added

- Computer use v3 on Windows: keyboard input through one tagged `SendInput` path and one `PostMessage` path, and the Windows half of the held-key release helper. Typed text never depends on the keyboard layout: in the foreground it goes as Unicode key pairs (a surrogate pair in one batch, a newline as Return), in the background as one `WM_CHAR` per UTF-16 unit. A partial send releases only the keys it pressed. On the posted route a Ctrl, Win or Shift chord on a named key is refused `BACKGROUND_UNAVAILABLE` (`posted_modifier_chord`) with nothing posted, an Alt chord keeps the system-key context bit, and a shifted character is posted as the character itself. Posted input goes to the target thread's focused child, never the frame. The release helper keeps a ledger of the keys the engine pressed, replays it, is spawned to break away from the engine's job, and is read back from the job. Nothing user-visible changes yet; the existing desktop engine is untouched.
