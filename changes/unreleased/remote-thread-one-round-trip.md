Thread ops on another device spend fewer relay round trips: the session's attach is kept across ops, a `session.read` page is answered on this device until anything happens on that session, and a model switch to an exact `provider/id` already in the session's catalog is one `set_model` (a failed set re-reads the catalog, so the answer matches a fresh one). Status and transcript reads (`get_state`, `get_messages`) still go to the device every time, because the engine's in-memory state changes without a record on the attach. A create whose reply names the session's listing key (`session_key`) skips `session.locate`.
