**A thread send now reaches a session that is not running, on this device or on another of your devices, and starts it.** It needs senpi 2026.11.15-2 or later (omo pins it), and device service 0.1.31 or later on both devices for a wake from another device. A reply to a sender on another device reads only that device's sessions instead of the whole account listing; a send to a live session that is paused or holds a Stop answers `queued` with `waiting_on: { kind: "hold", device }`; and `waiting_on.kind` in a `thread_send` result can be `approval`, `hold` or `wake`.

A lease takeover now consults the same allowance a wake does, ending its record when nothing queued allows the open; the runtime answers the carrier's admission ask on the live delivery port, so the startup pending sweep's own wakes are admitted too. - Thread gateway: the delivery consumer listens before it declares itself, so the records the device service hands it right after the acknowledgement are no longer dropped. A failed start closes its port and reports itself, a connection that ends during the startup sweep leaves no stale serving consumer behind, and a connect failure the client reports is logged instead of dropped. ### Changed

- Thread gateway: waking a session that is not running is on (#13037). It runs on senpi 2026.11.15-2 or later (omo now pins it), the release whose session release drops a woken session's retained record. A message from another of your devices wakes a session here once both devices run device service 0.1.31 or later. The local omo daemon (`omo daemon run`, or the device service's cold-wake unit) registers this device's agent dir with the device service and takes deliveries as soon as it starts, with no session open. ([#13599](https://github.com/code-yeongyu/oh-my-openagent/pull/13599))

- Thread gateway: the operator daemon declares the delivery consumer as soon as it loads omo, with no session open (#13037 cold wake). `omo daemon run` sends the daemon it ensured senpi's `warm`, so a daemon the device service starts on demand can be handed deliveries before any session runs. A warm that is refused or unsupported prints one line and the run still exits 0. ([#13596](https://github.com/code-yeongyu/oh-my-openagent/pull/13596))
- Thread gateway: the session wake loads from its own sidecar (`extensions/omo-wake.js` behind `#omo-wake-runtime`): the carrier, the delivery consumer and the device-service client never enter the main `omo.js` bundle, which carries only lazy shells; the ensured host's idle-exit setting is read inside the sidecar. ([#13456](https://github.com/code-yeongyu/oh-my-openagent/pull/13456))
- Thread gateway: waking a session that is not running needs no setting (#13037). A `thread_send` from this machine to a session here that is not running now starts it by default, and the answer is `queued` with `waiting_on: { kind: "wake" }`. `session_wake.same_device` stays in the configuration schema only as an explicit opt-out (`false`), read for the target session's own project. The wake still starts only on an engine at or above the wake engine minimum (senpi#6449), which is not cut yet. ([#13456](https://github.com/code-yeongyu/oh-my-openagent/pull/13456))
- Thread gateway: when no operator host is running, a session that is not running still starts (#13037). Before it opens the session, the carrier asks the engine's own `host ensure --policy never`, from omo's daemon launch spec, on the socket `thread_create` uses. A running host is reused whatever its build; one is started only when nothing answers. The ensured host runs with `omo daemon`'s own host environment: the agent directory is named (`OMO_AGENT_DIR`) and the configured `task.host_idle_exit_ms` rides along (`SENPI_RPC_HOST_IDLE_EXIT_MS`) instead of the launch spec's default, and from a source tree the launch spec resolves to the plugin's tracked copy so the CLI is always handed a file that exists. ([#13456](https://github.com/code-yeongyu/oh-my-openagent/pull/13456))
- Thread gateway: a delivery from another device is no longer gated on the device service's wake switch being told on. While this engine's delivery consumer is served (from its serving acknowledgement, before its startup pending sweep, so a remote row that sweep wakes is never told the gate is off), the carrier opens the session. The consumer itself still serves nothing until the engine minimum (senpi#6449) and the device-service release that carries the wake mark are named, and the consumer no longer reads the wake the service tells: the wake switch it tracked (`wakeAllowed`, the `delivery.wake` event) had no production reader left. ([#13456](https://github.com/code-yeongyu/oh-my-openagent/pull/13456))
- The delivery consumer (design 5.4) is wired beside the carrier, but it serves nothing in this build, for two reasons. The engine minimum for a woken session, `MIN_WAKE_ENGINE_VERSION`, is unset until the engine release that drops a released session's retained record (senpi#6449) exists (A8.1), and that same minimum now gates the carrier as well. The device service's local API does not carry the delivery protocol yet. ([#13455](https://github.com/code-yeongyu/oh-my-openagent/pull/13455))
- The gateway store's schema moves to version 12: three nullable columns on deliveries and a unique index on the new ledger id. The first process on this release migrates the store; any process still on the previous build then reports the store's "schema too new" error on its thread tools and inbox drain until it restarts. ([#13208](https://github.com/code-yeongyu/oh-my-openagent/pull/13208)) ([#13279](https://github.com/code-yeongyu/oh-my-openagent/pull/13279))
- Thread gateway: once a build carrying this store ships, every gateway store open runs the schema step to version 13 (one new table, `woken_sessions`) and raises the store's `user_version` for good. An older build, or a rolled-back one, that shares the same agent directory then refuses to open that store with its "schema too new" error until it is upgraded again. ([#13212](https://github.com/code-yeongyu/oh-my-openagent/pull/13212)) ([#13279](https://github.com/code-yeongyu/oh-my-openagent/pull/13279))
- A reply to a message that came from another of your devices goes to the session on that device that sent it, whether you reply by its session id or by the name it gave. A session on another device, or on this one, that only carries the same id or name no longer receives the reply. ([#13218](https://github.com/code-yeongyu/oh-my-openagent/pull/13218), part of [#13037](https://github.com/code-yeongyu/oh-my-openagent/issues/13037))
