### Changed

- `thread_list` rows of a thread held on this device carry `engine_version`, the version of the engine its host runs (the engine's own version, else an older host's package version), read from the `get_protocol_info` answer the listing connection already opens with. Another device's rows carry none yet. ([#14409](https://github.com/code-yeongyu/oh-my-openagent/pull/14409))

### Fixed

- A thread closed on request is no longer opened by a delivery that another path refused while the close settled it: a row whose `target_closed` refusal lost that race is not counted as queued. A wake that finds a closed session's deliveries all settled now reports their drained marks to the device service at once, instead of at a later carry end or the next start. ([#14402](https://github.com/code-yeongyu/oh-my-openagent/pull/14402), fixes [#14383](https://github.com/code-yeongyu/oh-my-openagent/issues/14383))
- `thread_create` on another device no longer answers `ok` with a thread nothing can address when that device's route does not reach the session its engine opened (for example the Desktop app's host, which the device service does not route): the name was not applied and the first prompt never ran. The create now ends that session where it was opened and answers `host_unavailable` with `details: { device, reason, created }`, so nothing is left behind (`created: false`). ([#14397](https://github.com/code-yeongyu/oh-my-openagent/pull/14397), fixes [#14394](https://github.com/code-yeongyu/oh-my-openagent/issues/14394))
- Advice that forbids ultrawork no longer starts it. "avoid ulw", "no ultrawork", "skip ulw-loop", "without ultrawork" and "don't ulw" are read as advice, the same as "do not use ulw", so pasted guidance and rule lists don't arm the mode. ([#14392](https://github.com/code-yeongyu/oh-my-openagent/pull/14392))
- OmO Native now reads `keyword_detector` from `omo.jsonc`. `"keyword_detector": { "disabled_keywords": ["ultrawork"] }` in a project's `.omo/omo.jsonc` or in `~/.omo/omo.jsonc` turns the `ulw`/`ultrawork` keyword off for every launch, and the key is no longer reported as unknown. The `--omo-senpi-ultrawork-disabled` flag still works for a single launch. ([#14392](https://github.com/code-yeongyu/oh-my-openagent/pull/14392))
- Waking many sessions at once no longer leaves messages to a busy session waiting behind the memory component: a session's repeated settle work now replaces itself instead of piling up, and an unchanged session journal is no longer re-read and rewritten on every settle. (#14351) ([#14379](https://github.com/code-yeongyu/oh-my-openagent/pull/14379))

### Added

- A shipped omo SDK for agent sessions and scripts: in a JS eval cell, `const { createOmoSdk } = await import(`${env("OMO_SDK_ROOT")}/sdk.js`)` gives `account.whoami()`, `devices.list()`, `deviceService.status()` and `config.status()`. Each call answers `{ kind: "ok", value }` or a typed `{ kind: "error", error: { code, message, next_action } }` and never returns a token or key. ([#14374](https://github.com/code-yeongyu/oh-my-openagent/pull/14374))

## 2026-11-19 - engine_version on this device's thread_list rows (#14409)

`live-surface.ts` `requestFrame` hands the host's `get_protocol_info` answer to an optional `onProtocol` callback (rpc_host connections), and `listEndpoint` tags each listed session with `engine_version` from it. For a terminal endpoint the version comes from the `learnTuiCommands` answer, kept per socket. `tools/thread-row.ts` copies the field onto the row.
