### Added

- Thread tools take the first 8 or more characters of a thread value when only one thread starts with them: `thread_send` to `01a1e898` reaches that thread, here or on another device, and a prefix two threads share answers `ambiguous_target` with both as candidates. A reply to a message still resolves only by its sender's exact id or name. ([#14067](https://github.com/code-yeongyu/oh-my-openagent/pull/14067)) ([#14077](https://github.com/code-yeongyu/oh-my-openagent/pull/14077))

### Changed

- OmO now runs on senpi 2026.11.15-4 (from 2026.11.15-2). ([#14077](https://github.com/code-yeongyu/oh-my-openagent/pull/14077))
- Thread tools name a session one way: every input that addresses one is `thread`, and every result that names one carries `thread`, the exact string the verbs take back (still the durable id). `thread_list` rows are `{ thread, name, status, machine?, cwd, created_at, updated_at, link }` plus `device`, `alias`, `surface`, `alive`, `controls` and `error_note` where they apply; `machine` is the display name of the device that holds the thread. Rows no longer show `thread_id`, `sessionId`, `durableSessionId`, socket or session-file paths, or other endpoint internals. `thread_create` and `thread_handoff` answer the thread flat (`thread`, `name`, `link`, ...) instead of a nested `thread` object, and `thread_read`, `thread_send`, `thread_interrupt`, `thread_close`, `thread_rename`, `thread_set_model` and `thread_set_reasoning` answer `thread` instead of `thread_id`. Failures name the session as `thread` too: the `ambiguous_target` and `name_conflict` candidate rows, the `alias_taken` holder, and the `turn_conflict`, `fork_unsupported` and `reply_target_mismatch` details. `thread_send`, `thread_handoff` and the `thread_create` prompt no longer report the endpoint kind (the SDK's send keeps `endpoint_kind`). `omo thread send --json` answers `thread`, and `omo remote open --json` answers the flat shape (#14044 step 4a). ([#14056](https://github.com/code-yeongyu/oh-my-openagent/pull/14056)) ([#14077](https://github.com/code-yeongyu/oh-my-openagent/pull/14077))
- `thread_read` of a thread on another device no longer downloads the whole transcript. The other device sends only its newest session entries in pages; this device projects them the way that device's engine does (the current branch, compaction and branch summaries, custom messages) and keeps them, so a repeat read of an unchanged thread costs one empty page. `next_cursor` and `cursor_stale` work as before, and a branch move or compaction on the other device makes an earlier cursor stale. A device whose engine cannot page, and the `omo thread` CLI, keep the full read. ([#14053](https://github.com/code-yeongyu/oh-my-openagent/pull/14053)) ([#14077](https://github.com/code-yeongyu/oh-my-openagent/pull/14077))
- `thread_read` with `wait_ms` now waits on a thread on this device too, instead of answering `unsupported`: one read shape for every thread, with the same `wait` outcomes (`settled` with the `turn_id` it saw end, `timeout`, `cancelled`, `ended`) wherever the thread runs. ([#14061](https://github.com/code-yeongyu/oh-my-openagent/pull/14061)) ([#14077](https://github.com/code-yeongyu/oh-my-openagent/pull/14077))

### Fixed

- omo now pins device service 0.1.40, which fixes a deadlock where reading a session's history larger than 64 KiB stopped in-order message delivery. ([#14057](https://github.com/code-yeongyu/oh-my-openagent/pull/14057)) ([#14077](https://github.com/code-yeongyu/oh-my-openagent/pull/14077))
- `createThreadSdk()` called without options, or without `agentDir`, throws a TypeError naming the missing fields instead of an unrelated property error. ([#14067](https://github.com/code-yeongyu/oh-my-openagent/pull/14067)) ([#14077](https://github.com/code-yeongyu/oh-my-openagent/pull/14077))
- `thread_read`, `thread_send` and the other thread tools no longer hang when a session on another machine never answers. A command waits at most 120 s for its result and a read at most 30 s; past that, a read answers `host_unavailable` (nothing changed there) and a command that may have run answers `idempotency_uncertain`. ([#14041](https://github.com/code-yeongyu/oh-my-openagent/pull/14041)) ([#14077](https://github.com/code-yeongyu/oh-my-openagent/pull/14077))
