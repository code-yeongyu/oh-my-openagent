### Fixed

- `thread_set_model`, the thread SDK's `set_model` and `omo remote model` now tell a model switch that is in effect from one the session holds until its next compaction (its context fits the new model only after one). The answer carries `model_switch: "applied"` or `"after_compaction"` and `in_effect`, the model and thinking level the session runs on, read back after the switch; a held switch adds `pending`, and a thinking level asked with it (`provider/id:high`) is listed there with `thinking_level_sent: false`, to be set once the switch lands. Before, a held switch with a thinking suffix answered `partial_commit` although nothing had changed, and one without a suffix answered as if the new model were already in effect. `partial_commit` now means only that the model took effect and the level did not, with `details.partial` naming which. A session that answers the switch and shows nothing changed answers the new code `not_applied` (safe to repeat), and one whose state cannot be read back answers `idempotency_uncertain` with `uncertain: true`. A repeat under the same `idempotency_key` after a lost reply answers the held switch again and switches nothing twice. ([#14997](https://github.com/code-yeongyu/oh-my-openagent/pull/14997), fixes [#14939](https://github.com/code-yeongyu/oh-my-openagent/issues/14939))

## 2026-11-25 - set_model outcomes: applied, after compaction, not applied (#14997)

`control/operations.ts` `setModelOn` decides the outcome from the holder's `get_state` read after `set_model` settles (`settleModelSwitch`): the selected model in effect is `applied` (a thinking suffix is then applied and confirmed in a second read); `pendingModelSwitch` naming the selected model is `after_compaction`, and no level is sent while the old model runs (the engine's held switch carries none, senpi#7468); a state naming neither is `not_applied` (new code in `THREAD_ERROR_CODES`, `REMOTE_CODES` and the omo SDK code registry); an unreadable state is `idempotency_uncertain` with the new optional `uncertain: true` on `ThreadToolFailure`. `partial_commit` comes only from a refused level after the model was read in effect, with `details.partial`. `SessionModelState` gains `pendingModel`. Every switch carries an effect id derived from the caller and key (`modelSwitchEffectId`), which the engine's effect ledger replays; `thread_set_model` joins `thread_create` in `RETRIES_UNCERTAIN`, so an uncertain answer under a key runs again instead of replaying.

## 2026-11-25 - omo remote model says when a switch waits for compaction (#14997)

`omo remote model` prints that the session switches at its next compaction, names the model it stays on until then, and says when an asked thinking level was not sent. The `--json` answer carries `model_switch`, `in_effect` and `pending`; a held switch exits 0, `not_applied` and `idempotency_uncertain` exit 1.
