**A thread send can reach a session on another device that is not running, once both device services support it.** With this build: a reply to a sender on another device reads only that device's sessions instead of the whole account listing; a send to a live session that is paused or holds a Stop answers `queued` with `waiting_on: { kind: "hold", device }`; and `waiting_on.kind` in a `thread_send` result can be `approval`, `hold` or `wake`. Finding a session that no engine runs (by reply, alias or bare session id), sending it a message down the wake path, and the new answers (`wake_unavailable`, `session_gone`, `ambiguous_session`, `not_wakeable` and the rest) stay off until a device-service release that carries the wake mark is named in a later change; until then every command keeps its bytes and a session that is not running answers as before. ([#13238](https://github.com/code-yeongyu/oh-my-openagent/pull/13238), part of #13037)
