**Remote turns on after `omo login` on Windows too, and login never waits on the device service install.** When this device has no current device service, login hands the install to a background `omo remote enable` and says so in one line (check it with `omo remote status`); a device whose service already runs is switched on at once as before, and a user who ran `omo remote disable`, even while that background install is still going, keeps remote off (enforced by a background `omo remote bootstrap` when this device has no current service), and the remote-sessions reference is accurate again on Windows.
