**`omo host ensure`, `omo host handoff` and `omo host session open` run through the npm launcher start a host that loads the omo plugin.** Without `--launch-spec` the launcher used to start a bare engine host with none of the plugin's commands, tools or skills, and every later client reusing that host inherited it. It now passes its own plugin spec, as the compiled binary already does; an explicit `--launch-spec` still wins. ([#11345](https://github.com/code-yeongyu/oh-my-openagent/pull/11345), fixes [#10643](https://github.com/code-yeongyu/oh-my-openagent/issues/10643))

## 2026-11-22 - The npm launcher starts omo hosts with its own plugin spec (#11345)

`bin/lib/engine-commands.js` `engineCommandArgs` appends `<plugin>/daemon-launch-spec.json` to `host ensure`, `host handoff`
and `host session open` when the argv carries no `--launch-spec`; `bin/lib/launcher.js` hands one-shot engine commands over
through it. The compiled entry (`compile-args.ts`) already applies the same rule since f2cde592c1. Every other engine command,
including `host status`, `stop` and `gc`, goes over unchanged.
