**`omo host ensure` and `omo host handoff` start a host that loads the omo plugin.** Without `--launch-spec` they used to start a bare engine host with none of the plugin's commands, tools or skills, and every later client reusing that host inherited it. They now use the launcher's own plugin spec; an explicit `--launch-spec` still wins. ([#11345](https://github.com/code-yeongyu/oh-my-openagent/pull/11345), fixes [#10643](https://github.com/code-yeongyu/oh-my-openagent/issues/10643))

## 2026-10-25 - Start omo hosts with the launcher's own plugin spec (#11345)

`bin/lib/engine-commands.js` `engineCommandArgs` appends `<plugin>/daemon-launch-spec.json` to `host ensure`
and `host handoff` when the argv carries no `--launch-spec`. The npm launcher (`launcher.js`) and the compiled
entry (`compile-args.ts` `buildSenpiArgs`) both hand one-shot engine commands over through it, with the plugin
root each already uses for `--extension`. Every other engine command, including `host status`, `stop` and `gc`,
goes over unchanged.
