### Added

- The desktop engine protocol gains an opt-in action-report vocabulary on protocol 1, with no version or ABI change. `engine.hello` lists `features: ["action-report"]`, and a session opened with `reportMode: "object"` gets an `ActionReport` from every mutating request. The report says whether input reached the target and whether retrying is safe: one of seven `{delivery, retry}` pairs. Errors from those requests carry the same `disposition`. Sessions that don't opt in see the same replies as before, apart from the new `features` list. The protocol also gains the error codes `AmbiguousTarget`, `CaptureConsentRequired` and `ProtectedProcess`, the `epoch.changed` notification, and optional window-identity and accessibility-evidence fields that later changes will fill in. Frame ids are now unique per engine process, so a frame id from before a session re-open can never match a new capture. ([#12260](https://github.com/code-yeongyu/oh-my-openagent/pull/12260), part of [#12234](https://github.com/code-yeongyu/oh-my-openagent/issues/12234))
