### Changed

- `omo remote enable` now sets the device up in one command after `omo login`. It installs the OmO device service when none runs, registers this omo's agent dir with it, turns remote sessions on, and installs and starts the always-on session host unit. If you signed in before the device service was installed, it also links that sign-in to the service, so `omo login` then `omo remote enable` leaves the device connected. Running it again changes nothing that is already in place (#13594). ([#13602](https://github.com/code-yeongyu/oh-my-openagent/pull/13602))
- `omo remote status` also shows this device's own units as the service manager reports them: the session host unit (running, enabled, pinned host), the device service's unit, whether the cold-wake entry is in place, and the agent dir omo registers. With `--json` these are a `local` object beside the status fields (#13594). ([#13602](https://github.com/code-yeongyu/oh-my-openagent/pull/13602))

### Fixed

- An omo engine on a device whose device service runs on a non-default `--state-dir` now registers with it: `deviceServiceStateDir` takes a non-empty absolute `OMO_DEVICE_SERVICE_STATE_DIR`, then the `device-service.location.json` discovery file beside the default dir, and only then `~/.omo/device-service` (#13597). ([#13598](https://github.com/code-yeongyu/oh-my-openagent/pull/13598))
- A remote worktree remove refused for an empty reflog now says reflogs may be off in the repository, instead of claiming they are: an expired or deleted reflog looks the same (#13542 follow-up). ([#13546](https://github.com/code-yeongyu/oh-my-openagent/pull/13546))

### Added

- `omo remote bootstrap` and `omo remote enable` install and start one fixed, always-on per-user unit beside the OmO device service that runs the omo session host: the systemd user unit `omo-session-host.service` on Linux (enabled, restarted after every exit) and the LaunchAgent `ai.omo.session-host` on macOS (run at load, kept alive). It runs `omo daemon run --pinned` for the registered agent dir, and the device service's `OMO_RELAYD_SERVICES` table names it (entry `"omo"`) as the only unit it may start for a cold wake. The table keeps its other entries, and the device service restarts only when the table changed. `omo remote disable` disables and removes both, and while remote sessions are off a bootstrap removes them instead of installing them (#13594). ([#13595](https://github.com/code-yeongyu/oh-my-openagent/pull/13595))
- `omo daemon run --pinned` starts the operator host with no idle exit; a task host started from one of its sessions still idles out as usual (#13594). ([#13595](https://github.com/code-yeongyu/oh-my-openagent/pull/13595))
