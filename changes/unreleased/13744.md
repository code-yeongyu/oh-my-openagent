### Fixed

- Device operations run through the bundled fleet SDK (`bunshin` in eval cells) now fail with a typed error, `{ code, message, next_action }` like the thread tools, instead of an internal transport sentence. The message names the operation and the device, and the code tells a wrong argument (`invalid_arguments`) apart from an offline device (`device_offline`), a policy refusal (`scope_denied`) and a lost connection (`transport_closed`). The relay's own op-result codes pass through unchanged and carry `uncertain` when the device may have run the op. The "no transport" error and a failed connect now say what to do next. A fanout that fails as a whole (an unknown or ambiguous target, invalid options, a duplicate target under `dedup: "reject"`) and a target that runs past `timeoutMs` get the same typed error, and a failed `resultOf` names the request instead of treating its op id as a device. ([#13744](https://github.com/code-yeongyu/oh-my-openagent/pull/13744))

### Added

- The re-vendored relay transport brings in new public surface besides the two fixes: `createRelayTransport` takes `retryUnreachableMs` (how long a device whose describe failed is listed unsupported before it is asked again, default 30 s), and the transport it returns has `uploadArtifact(bytes)` and `fetchArtifact`, which carry `pushTree` / `pullTree` archives over the relay. ([#13744](https://github.com/code-yeongyu/oh-my-openagent/pull/13744))
