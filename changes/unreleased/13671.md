### Fixed

- On Linux, signing out (`omo logout`, `omo account forget`) in a session that uses the keyring no longer turns into another account. Before, when the private sign-in file held another sign-in written by a process that could not reach the keyring (cron, `su`, ssh with no session bus), the next command took that file over. Now the sign-out marks the file as kept and names it in one line. It is never migrated or read where the keyring is used, and the session that wrote it keeps using it (#13667).
- On Linux, a private sign-in file holding an older copy of the sign-in the keyring already holds is deleted instead of kept. Its outdated refresh token no longer stays on disk, so a refresh with it can no longer trip token-reuse detection and end the keyring's session (#13667).
