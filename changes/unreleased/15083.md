### Changed

- The `browser` skill (#15066) teaches the BrowserSkill 0.5 shared-control contract: what the `strict` and `target` control policies need per action kind, how to pass `observation` and `expect`, how a false `expect` is refused under each policy, `read` and `extract` in place of `evaluate` when the answer is already in the DOM, and `waitForElement`. `references/commands.md` adds three traps seen in Chromium-based browsers (a frame injected by another extension, a control inside another extension's own frame, clipboard writes in an unfocused Agent Window) and error rows for `observation_required`, `observation_changed` and `control_context_invalid`.

- The browser skill's bundled runtime is omowright 0.3.4 (was 0.3.3): gated actions take `{ context, observation, expect, dependsOn }`, `cooperate("sync", { controlPolicy })` returns the observation id, `read`, `extract`, `waitForElement` and `drag` are typed, `BskClient` is exported for a caller-supplied transport, and a session's first `navigate` recovers by itself when the extension refuses it while the new tab is still blank. `requestHelp` now requires `prompt`, and only `click` accepts a `{ captureId, x, y }` target.

### Fixed

- The attached-engine loop example runs as written on example.com and example.org, whose pages no longer have an `h1`.
