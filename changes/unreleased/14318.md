### Added

- The thread control tools (`thread_read`, `thread_close`, `thread_interrupt`, `thread_set_model`, `thread_set_reasoning`, `thread_rename`, `thread_archive`) accept `<device>/<thread>` and `here/<thread>`. The device part is its id, its name or a unique id prefix of at least 6 characters; the thread part is a thread id, name, alias, listing key or an 8-hex id prefix among that device's threads. One address module (`@oh-my-opencode/thread-address-core` plus `thread/address/`) now owns the grammar, the device resolver and the refusals.

### Fixed

- A thread address that misses while a device did not answer the listing round answers `host_unavailable` with `details.reason: "listing_incomplete"` naming that device, never `not_found`.
- An offline device resolves by id, name or id prefix alike; only a caller that needs it online (thread_create, the control tools) gets `device_offline`, by every form.

## 2026-11-19 - One thread address module (#14318)

New core package `packages/thread-address-core` (dependency-free; vendored by the desktop app) holds `parseAddress`, `resolveDevice`, `normalizeName`, `deviceListing`, row identity (`rowKey`, `rowAddress`, `rowName`, `mergeRows`, `listingKey`, `sameSession`) and the refusals as data. `components/thread/address/` holds `readAccount` (one status, roster and listing read) and `resolveAddress`; `control/locate.ts` loads it lazily from the thread client sidecar. `remote/seams.ts`, `remote/device-address.ts`, `remote/unknown-device.ts`, `remote/plan-create.ts`, `extension/senpi-seams.ts` and `addressing.ts` use the core instead of their own copies.
