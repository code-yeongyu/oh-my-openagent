**A message an agent sends to a session on another device now arrives there exactly as a message between sessions on one device.** The receiving session gets a delivery entry (never a user message) with the same sender line and authority notice a same-device delivery carries, deduplicated under the same key, and it wakes on receipt the same way; a reply is just another send back. Nothing in the delivered text names the device it crossed, and `omo remote send` from a terminal is unchanged. A send from `omo thread send` to a session on another device is refused as data (the engine admits a command-line delivery only from its own machine) and points at `omo remote send`.
