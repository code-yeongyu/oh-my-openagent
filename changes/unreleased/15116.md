### Changed

- The omo SDK root (#15031): the thread core now ships in its own runtime file, `runtime/omo-sdk/threads.js`, which the root loads on the first thread call. A script that never makes a thread call no longer loads the thread core.
  - **The file is missing or cannot be loaded:** every thread call answers `internal_error` with details `{ reason: "runtime_file_unavailable", file: "threads" }`. Account, device and configuration calls keep working. A missing file that is put back loads on the next thread call. A file whose evaluation failed stays failed until the process restarts, and the answer says so.
  - **The file belongs to another build, or lacks what the root uses:** for example, an update replaced the plugin's files while the process ran. Every thread call answers `internal_error` with details `{ reason: "runtime_file_mismatch", file: "threads" }`, and says to restart the process.
  - **The thread core cannot be started:** the call answers `internal_error` with fixed text.
  - In every case the exception itself goes only to the root's local logger port.
  - The installer now requires the plugin's own `package.json`, whose import map resolves the file.
