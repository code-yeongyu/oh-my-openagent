### Fixed

- A delegated task now runs only on the models designated for it (its category's or agent's model chain). It never falls back to the parent session's model, whatever the failure: a usage limit, a missing or rejected sign-in, a content-policy refusal or an overload on every designated model ends the task with `failure_kind: "model_chain_exhausted"` and an error listing each model it tried and why, including any reset time the provider reported. This applies to every category and to workflow nodes. A `categories.<name>.provider_lock` key left in `omo.json` is ignored. ([#12006](https://github.com/code-yeongyu/oh-my-openagent/issues/12006), [#11781](https://github.com/code-yeongyu/oh-my-openagent/issues/11781))

## 2026-11-02 - A child runs only on its designated models; the parent-model rung is gone (#12006, #11781)

`withParentModelRung` (#10750) and the workflow node copy of it (#10783/#11439) are deleted, with `parent_model`, `parent_model_fallback`, `DagRunRecordV1.parentModel`, the `model_note:` line and the `parent-model:` status token. The runtime and start-time walks only ever hop along the record's own `fallback_models`. Each hop appends a `model_refusals` entry (model, reason, first error line, reset); when a recognized refusal ends the chain the task fails with `failure_kind: "model_chain_exhausted"` and lists them (`manager/model-refusals.ts`). Records and runs persisted with the removed fields load unchanged and ignore them.
