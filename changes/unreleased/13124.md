## 2026-11-11 - The senpi barrel is seeded from pi.engine; the restart-required mapping is gone (#13124)

`seedSenpiBarrel(engine)` makes the barrel the engine an extension is running in, for every loader and reader in every bundle copy, and clears the cached host accessors. `seedSenpiBarrelFromExtensionApi(pi)` seeds it from `pi.engine` when the extension API carries one; the member extension calls it first. A seeded barrel never imports `@code-yeongyu/senpi`, so on Node the plugin no longer evaluates a second engine copy next to the bundled CLI (#12965). On an engine without `pi.engine` the barrel imports the engine index as before.

`loadSenpiBarrel()` no longer maps an import that fails with `SENPI_REDACTION_SLOT_INCOMPATIBLE` to `SenpiEngineRestartRequiredError` (#12991); the class is removed. A seeded barrel does not import the engine index in an engine process, so that refusal cannot be reached there.

## 2026-11-11 - Every extension factory seeds the senpi barrel from pi.engine (#13124)

The entry extension (`src/extension/compose.ts`), the task component and the desktop toolkit runtime call `seedSenpiBarrelFromExtensionApi(pi)` first. `components/memory/facts-oversized-child.ts`, `components/task/job-widget-host.ts` and `components/desktop-toolkit/host-tool-execution.ts` read the engine through the senpi barrel instead of importing `@code-yeongyu/senpi`, so they use the engine that loaded the plugin (#12965).
