### Fixed

- Release notes no longer publish references to private repositories. Two layers apply to commit subjects, contributor titles and fragment text in the published release body: an allowlist keeps references and GitHub URLs to allowlisted public repositories and replaces every other repository reference or GitHub URL (including unknown third-party repositories, by design) with "tracked internally"; then a name-based deny pass, fed by the RELEASE_NOTES_PRIVATE_NAMES secret, replaces any link, URL, reference or plain word in which a listed repository name or owner/name occurs, however it is written (percent-encoding, HTML entities, markdown or backslash escapes, repeated slashes or dot segments, a .git suffix, trailing-dot hosts, zero-width characters, HTML comments or tags, fullwidth forms). A name that is also an ordinary word is redacted too, on purpose. A final check re-reads the finished body and the release step refuses to publish when any line still names a listed repository. The scanner is single-pass and linear. The release job and the draft "next" release now refuse to publish or generate notes when that secret is missing or empty.
