## 2026-10-25 - Bound Windows record retries and persist failed spawns (#11274)

Record replacement, mutation and status writes share a 1,270 ms Windows-only exponential backoff for EPERM, EBUSY and EACCES. The record mutex permits that bounded operation to finish. A fenced terminal sidecar prevents permanent prelaunch write failures from remaining pending, including when target deletion is also refused.

Terminal sidecars retain the error code, errno and sanitized file path; live records rejected by the sidecar fence retain their name and waiters. Temporary cleanup retries without masking the original write error. Cached reads validate the selected sidecar directly, and transition audits follow the successful record write.
