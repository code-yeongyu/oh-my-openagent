### Changed

- omo now runs on senpi 2026.11.28-1 (from 2026.11.23); the bundled plugin and the service-auth table are regenerated for it. What changes through the engine:
  - A terminal that speaks OSC 7577 learns each session's resume command, so a restored terminal can reopen the session it was showing. omo's compiled entry loads that hand-off first, ahead of every other module.
  - A message another session sends while the previous message's turn is still starting joins that turn, so messages sent together arrive in one turn, in order.
  - A peer message stopped by the per-session turn cap is answered as held, and Resume continues a capped session. A resumed session shows the model every held message in the order it arrived, and a paused session holds at most 64 of them.
  - Two starts of the same session at once no longer both write to it: one is admitted, and the other is refused or offered take-over.
  - On macOS, a find or grep started from the home folder no longer reads Desktop, Documents, Downloads or the other privacy-protected folders, so it no longer raises macOS privacy prompts.
  - Settings that name an executable or a command line are honoured only from global settings or a trusted project, and they stay ignored after a reload.
  - A long session on a shared engine host uses less memory: a compacted session no longer keeps its old bookkeeping records in memory, and restoring tools after an extension reload no longer rereads the whole session file.
  - The todo widget no longer shows an item as in progress while the session is idle.
  - A question reattached after a reload shows its prompt again.
  - On a shared session host, telemetry is decided per caller, and a decline by any caller removes the attribution headers.
  - JavaScript eval cells run `using` blocks, TypeScript cells and scoped cleanup.
