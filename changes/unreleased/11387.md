**A workflow node whose child resumes on its own now follows that child's resumed run.** A node whose child finished its turn and then woke up again (its background job or monitor fired) stayed `completed` even when the resumed run failed, so the run summary counted it as completed ("5 completed, 0 failed"). The node now goes back to running when its child resumes and takes the resumed run's outcome, including when the resume starts before the first outcome is folded. A failure marks the node failed, the run summary counts it, and dependents that had not started yet are skipped. Dependents that already started on the earlier completion keep their own result with a diagnostic flag. Infrastructure failures on resumed runs remain failed outcomes rather than restarting the node. ([#11387](https://github.com/code-yeongyu/oh-my-openagent/pull/11387), part of [#10487](https://github.com/code-yeongyu/oh-my-openagent/issues/10487))

## 2026-10-26 - A DAG node re-watches its task after task_self_resumed (#11387, part of #10487)

`reopenSelfResumedTurn` moved a settled task back to `running` under the next run epoch, but the
DAG scheduler had already dropped the node's attachment when it folded the first outcome, and the
only path that re-watched a finished node was an explicit `send` revival. A resumed run's later
error therefore never reached the node, the run summary, or the parent's wake.

`TaskManager.subscribeSelfResumed(taskId, listener)` (optional on the contract; the concrete
manager implements it through `createSelfResumedListeners` in `manager/self-resumed-turn.ts`)
announces a reopen after the record is back to `running`. When the scheduler creates a task
attachment it subscribes for that node's task before calling `waitFor`. An announcement before
the first fold supersedes that attachment: the stale completion is discarded and the resumed
run is reattached, even if it has already failed. On a later announcement, while the run is still
`running` and the node is still `completed` with that task, it journals `completed -> running` (reason
`resumed`) and re-attaches the task to the settle loop, which folds the resumed run's outcome
like any other. Dependents already admitted, including their admitted descendants, keep their
outcome and receive a `dag.diagnostic.added` `node_flag` when that input is invalidated; pending
dependents wait for the node again and are skipped by the quiescent cascade if it fails.
Later admissions through an already-flagged dependent inherit the invalidation flag transitively,
with the original failed node recorded in `invalidatedBy`; unrelated diagnostic flags do not propagate.
Every settlement attachment registers its child for cancellation, including pre-fold self-resumes.
Infrastructure-class errors on a self-resumed run are intentionally final node failures: they
do not invoke automatic infrastructure retries, reset the node, or un-skip dependents. Initial
attempt infrastructure failures retain the existing bounded retry policy. Watches are disposed when the
run settles or the scheduler is suspended: a terminal run stays settled evidence (#7412), and the
task's own resumed-turn notification still reaches the parent.

Tests: `dag/scheduler.test.ts` (real scheduler + fake manager) covers the incident shape (node A
completed, B admitted, A resumes and errors: A failed, run failed with 1 completed / 1 failed) and
a pending dependent skipped after the re-opened node fails, a deterministic pre-fold resume while
frontier admission is gated, resumed infrastructure failure without retry, and diagnostic flags
on already-admitted dependents, cancellation after pre-fold reattachment, and pending/blocked
descendants flagged only when admitted through multiple generations; `manager/manager-self-resumed-turn.test.ts`
asserts the announcement fires after the reopen and not for a cancelled task.
