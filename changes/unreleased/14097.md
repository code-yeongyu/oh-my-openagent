### Added

- `omo sync enable` and `omo sync recover` can use a recovery phrase on the terminal itself: words appear only on the controlling terminal, never in output or logs, and the flow refuses under an agent harness, CI or without a terminal. Creating a phrase still needs the client flag, and the CLI asks the service whether it accepts phrase keys before each creation. ([#13337](https://github.com/code-yeongyu/oh-my-openagent/pull/13337))

### Fixed

- Memory sync: a join, enable or passkey recovery that already pinned the account is no longer reported as failed when the follow-up root-change check cannot read the local retired pins. The check is reported as skipped instead of passing silently: `omo sync enable` prints it with the error code, the desktop's enable result carries an optional `rootCheck: { kind: "skipped", reason }` beside `rootChanged`, the in-app warning goes to the memory component's log rather than the terminal, and recovery emits `sync.trust.root_check_skipped`. ([#13641](https://github.com/code-yeongyu/oh-my-openagent/pull/13641), fixes [#12382](https://github.com/code-yeongyu/oh-my-openagent/issues/12382))
- Memory sync: creating a recovery phrase now checks the sync service's own answer on whether it accepts recovery-phrase keys, read fresh through the signed-in session for every creation. Before this the host never wired that check, so a recovery phrase could not be created even where the service accepts one. A refused, absent, unreadable or signed-out answer still refuses before any words are shown or anything is written. ([#13646](https://github.com/code-yeongyu/oh-my-openagent/pull/13646), fixes [#13631](https://github.com/code-yeongyu/oh-my-openagent/issues/13631))
- Memory sync works again after a recovery phrase is set up. The sync engine's requests (batches, objects, uploads, sync state and the event stream), the device-list read and the account reads now declare the client contract version and the recovery-phrase capability, as the account and pairing requests already did. Before this, the service refused every one of them with "client update required" for an account with a recovery phrase, so no device synced (#13691). ([#13693](https://github.com/code-yeongyu/oh-my-openagent/pull/13693))
- Memory sync no longer stops for good when its first start fails. A start that fails (for example another omo process holding the account's credential lock past the 15 s wait) or gets stuck is retried on the same backoff as a waiting start, 15 s doubling to five minutes. A stuck start is named in the log, and the first successful start logs "memory sync started", so a log shows whether sync is running (#13701). ([#13706](https://github.com/code-yeongyu/oh-my-openagent/pull/13706))
- Memory sync: a device that has turned sync on and joined the account now receives the account's memory without writing anything first. Its memory repository is created through the same first-write path a memory write uses, only for a joined device with sync on; a device that has not joined, a device with sync off and every read still create nothing. ([#14096](https://github.com/code-yeongyu/oh-my-openagent/pull/14096), fixes [#14094](https://github.com/code-yeongyu/oh-my-openagent/issues/14094))
