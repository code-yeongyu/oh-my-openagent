### Added

- Memory sync can be turned off on one device. `omo sync disable` turns it off for the device it runs on: that device stops sending and receiving memory, memory already on it stays, and the account's other devices keep syncing. `omo sync enable` turns it on again without a new approval. An OmO session already running on that device stops syncing when its sync next reports a change, or at its next start, and a process that turns sync on again starts the engines it had stopped right away. For the desktop, the engine answers `omo.memory.sync.disable` with `{ kind: "off" }` or a typed problem, and lists `"disable"` in `omo.memory.sync.features`; turning off from the desktop app needs an app release that carries the matching request. ([#14121](https://github.com/code-yeongyu/oh-my-openagent/pull/14121))
- The memory sync status can say how many memories changed while this device was offline: `status.sync.appliedWhileOffline` is the number of memories the catch-up updated after the device was away (OmO was closed, or sync could not reach the service), `0` when nothing changed, and absent when the latest changes arrived while it was online. ([#14121](https://github.com/code-yeongyu/oh-my-openagent/pull/14121))

## 2026-11-17 - Memory sync: disable verb and offline-applied count (#14093)

- **Turn sync off on this device (#14093)**
  - `memory-core` `src/sync/account/pairing-http.ts`: `PairingHttp.disableDeviceSync` asks the service for its typed confirmation (`POST /v1/confirm`, action `sync.disable_device`) and spends the token on `PUT /v1/devices/:id/sync`; a 4xx is `{ ok: false, code }`, anything else throws.
  - `memory-core` `src/sync/account/device-switch.ts`: `disableSync` (service first, then a mark under the pin directory), `turnDeviceSyncOn` (used by `enableSync`, removes the mark) and `isDeviceSyncOff`. `openAccountSession` answers the idle reason `sync_off` before it reads the pin or the network. The trust pin and local memory are not touched.
  - `src/components/memory/sync-rpc-contract.ts`, `sync-rpc-coordinator.ts`, `sync-rpc-registration.ts`: the `omo.memory.sync.disable` verb (`{ kind: "off" }` or a `SyncRpcProblem`; the service's refusal code goes to the log only) and the `"disable"` feature.
  - `src/components/memory/sync-runner.ts`: `idleTurnedOff()` closes the engines of a device that was turned off, reports each as a status change (the footer and the desktop snapshot drop its last status) and keeps their repos held but idle; an engine whose device was turned off by another process goes idle at its next status change, before the change is reported. `resumeIdle()` starts a fresh engine for every held repo that runs none; the sync RPC calls it (`resumeSync`) when `enable` ends `joined` or `first_device_created`, so Turn off then Turn on in one engine process resumes sync without a rebind. `device-session/resolver.ts` gives each session its `turnedOff` reader. `sync-status-surface.ts`: a repo that has no status any more is not announced as recovered.
  - `src/components/memory/desktop-sync/desktopSyncAccountPorts.ts`: the desktop channel sends one `disableDeviceSync` service op; the confirmation token stays in desktop main. A main that does not know the op fails the request and the verb answers `unavailable`.
- **Offline-applied count (#14093)**
  - `memory-core` `src/sync/engine/engine.ts`: the engine tracks an offline gap (it starts over a journal that has synced before, or its status shows `offline`) and writes the memories the catch-up updated to the journal's `updatedWhileOffline` when a refusal-free cycle closes the gap; entries received with no gap clear it, a cycle that receives nothing keeps it. `EngineStatus.synced.updatedWhileOffline` is optional.
  - `src/components/memory/memory-rpc-sync.ts`: `MemoryRpcSync.appliedWhileOffline`.
