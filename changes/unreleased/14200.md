### Fixed

- `thread_create` (and `omo remote open`) on another device now opens the thread only on that device's own engine (the primary engine endpoint its device service names), never on the first endpoint listed. Before this, a thread could land on an owner shard or on another registered agent dir's older engine, which then refused every cross-device `thread_send` as unsupported (`method_unclassified`). When the device names no primary, because its own engine is not listed, the create now fails `host_unavailable` with reason `no_primary_endpoint` before anything opens, even if only one other endpoint is listed. The next action says to start or restart omo on that device, and to update the device service on both devices if that does not help (a device service older than 0.1.11 cannot name a primary; behind such a local service a device's lone endpoint is still used). ([#14200](https://github.com/code-yeongyu/oh-my-openagent/pull/14200), fixes [#14195](https://github.com/code-yeongyu/oh-my-openagent/issues/14195))
