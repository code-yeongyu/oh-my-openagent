### Fixed

- `thread_create` (and `omo remote open`) on another device now opens the thread on that device's own engine (the primary engine endpoint its device service names), never on the first endpoint listed. Before this, a thread could land on an owner shard or on another registered agent dir's older engine, which then refused every cross-device `thread_send` as unsupported (`method_unclassified`). A device with a single engine endpoint works as before. A device that lists several engine endpoints but names none as its own now fails `host_unavailable` with reason `no_primary_endpoint` before anything opens, and the next action says to start or restart omo on that device, then update the device service on both devices if that does not help. This also covers a device reached through a device service older than 0.1.11, which cannot name a primary. ([#14200](https://github.com/code-yeongyu/oh-my-openagent/pull/14200), fixes [#14195](https://github.com/code-yeongyu/oh-my-openagent/issues/14195))
