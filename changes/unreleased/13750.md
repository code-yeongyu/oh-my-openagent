### Changed

- The remote module gains its client factories, one per kind of caller (a person, including `omo remote`; a session; a connector; the thread SDK's own principal; the device service's bootstrap entry), and its public entry. Its alias operations work when the caller hands in the account's alias registry, naming each session by the same durable id the thread tools use, and a device that does not answer is reported as offline rather than as having no such session. Nothing calls them yet, so no command or tool behaves differently.
