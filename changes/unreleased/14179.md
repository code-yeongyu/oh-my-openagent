### Fixed

- `thread_create` reopens a closed thread on another device again. It failed with `EISDIR`: the account listing names a session's working folder, never its session file, and that folder was sent to the other device as the file to open (a row with no path sent its working folder too). The reopen now opens the file the close was told by that device, or else asks the device which file carries the thread's id; a device that cannot say answers a typed refusal naming it (`unsupported` for an engine without the lookup, `not_found`, or `ambiguous_target`). A thread this device closed no longer lists as `live` while the listing catches up, and a reopen answers `ok` only once the reopened session can be reached, so the next tool call no longer answers `not_resumable`. ([#14179](https://github.com/code-yeongyu/oh-my-openagent/pull/14179), fixes [#14170](https://github.com/code-yeongyu/oh-my-openagent/issues/14170))
- `thread_send` to a thread on another device that is not running, and that this device cannot wake there, answers `not_resumable` at once, naming the reopen as the next step. It used to wait about 60 seconds and then answer `unsupported` (`daemon_unavailable`). A device without the wake capability counts as unable to wake. The device holding the thread is asked first, so a thread reopened elsewhere since this device last listed it is still delivered to. ([#14179](https://github.com/code-yeongyu/oh-my-openagent/pull/14179), fixes [#14184](https://github.com/code-yeongyu/oh-my-openagent/issues/14184))

## 2026-11-18 - Reopen a closed thread on another device from its file (#14179)

- **Never open a listing row's path (#14170)**
  - `src/components/thread/remote/ports.ts`: `RemoteSessionRow.path` is the session's working folder as relayd lists it (`cwd`, else `"unknown"`), never its file; the new `session_file` carries a file the device itself named.
  - `src/components/thread/remote/find-session.ts` `sessionFileOf`: a remote reopen opens `session_file`, else asks the device `find_session { durableSessionId }` (senpi#6429) and opens the file it names. `method_unclassified` or an unknown command is `unsupported`, `unknown` is `not_found` and `ambiguous` is `ambiguous_target`, each with `device` and `thread`; nothing is opened.
  - `src/components/thread/remote/plan-create.ts`: every remote reopen of a thread that is not live checks the device online and takes that file. `tools.ts` drops the old `ended`-and-no-path guard.
- **The listing lags a close and a reopen**
  - `src/components/thread/remote/closed-rows.ts` `withClosedRows`: one ledger per sessions port. A thread these tools closed lists `ended` with the file its `unload_session` reply named (`control/relay-control.ts`) until the listing shows newer activity; a thread they reopened lists under the key its device located it by. `remote/ports.ts` gains the optional `closed` / `reopened` members.
- **A reopen is ok only when the session can be reached**
  - `src/components/thread/control/relay-session-host.ts`: a reopen asks for and locates the reopened session's key, as a create does, instead of keeping the cached row's key; a key that does not resolve is `not_resumable`.
- **A send to a thread that is not running fails fast (#14184)**
  - `src/components/thread/remote/relay-transport.ts`: an `ended` row with no wake path (a port without `canWake` included) asks its device `find_session` first (`remote/find-session.ts` `runsNow`): a session an engine runs there clears the closed mark and is delivered to as usual; any other answer is `not_resumable` before any session command is sent (the attach to its old key waited out the device's deadline).
