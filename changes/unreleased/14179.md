### Fixed

- `thread_create` reopens a closed thread on another device again. It used to fail with `EISDIR` when the account listing named no session file for the thread (a thread listed before its file existed, a cached snapshot, or a session found only by its id): the empty path reached the other device, which read its own working folder. That device is now asked which file carries the thread's id and opens it; a device that cannot say answers a typed refusal naming it (`unsupported` for an engine without the lookup, `not_found`, or `ambiguous_target`). A thread this device just closed no longer lists as `live` while the listing catches up, and a reopen answers `ok` only once the reopened session can be reached, so the next tool call no longer answers `not_resumable`. ([#14179](https://github.com/code-yeongyu/oh-my-openagent/pull/14179), fixes [#14170](https://github.com/code-yeongyu/oh-my-openagent/issues/14170))

## 2026-11-18 - Reopen a closed thread on another device from its file (#14179)

- **No empty `sessionPath` (#14170)**
  - `src/components/thread/remote/find-session.ts` `sessionFileOf`: a remote row with `path: ""` asks its device `find_session { durableSessionId }` (senpi#6429) and opens the file it names. An engine that answers it as an unknown command is `unsupported`, `unknown` is `not_found` and `ambiguous` is `ambiguous_target`, each with `device` and `thread`; nothing is opened.
  - `src/components/thread/remote/plan-create.ts`: an existing remote thread that is not live is checked online and has its file found first when its row names none. `tools.ts` drops the `ended`-only guard, so a row in any state takes that path.
- **The listing lags a close and a reopen**
  - `src/components/thread/remote/closed-rows.ts` `withClosedRows`: one ledger per sessions port. A thread these tools closed lists `ended` with the file its `unload_session` reply named (`control/relay-control.ts`); a thread they reopened lists live under the key its device located it by. The listing counts again once it shows the change or newer activity. `remote/ports.ts` gains the optional `closed` / `reopened` members.
- **A reopen is ok only when the session can be reached**
  - `src/components/thread/control/relay-session-host.ts`: a reopen asks for and locates the reopened session's key, as a create does, instead of keeping the cached row's key; a key that does not resolve is `not_resumable`.
