### Changed

- OmO now runs on senpi 2026.11.12 (from 2026.11.10-2). Senpi's own zod pin moves to 4.6.7, which fixes GHSA-mrhx-c7xc-m3w5 for that copy. OmO's own bundles are regenerated at the release train top, so this entry does not claim every zod copy is clean.
- From senpi 2026.11.10-3 (#6342, with a follow-up in 2026.11.11): a session follows the permission setting of the machine it runs on whatever the origin of the work. Work sent from another device of the same account, which the relay states as such, no longer asks for approval, and one remote command no longer makes every later automatic turn on that session ask. Devices of another account still ask.
- From senpi 2026.11.11 and 2026.11.12: a goal that is waiting out a usage limit no longer spends its continuation budget, a status-only 429 counts as a limit wait, and a goal whose subscription accounts are all limited keeps waiting for the reset, re-checks a limit that named no reset, and resumes on its own after its session restarts or a config reload. An account blocked for a usage limit serves again once its named reset has passed, without a re-login.
- From senpi 2026.11.11: a rate-limited Opus 5.5 turn falls back to Fable 5.2 first, then Opus 5.

### Added

- The senpi `contextFiles.globalPath` setting loads the global context file from an explicit file or directory (for example `~/.agents/AGENTS.md`). It is read from global settings only, and an unset value keeps the current behavior.

### Fixed

- From senpi 2026.11.10-3: the footer names the account actually serving the session when the pinned account is blocked, pinned Ultrafast variants no longer warn that Ultrafast is undocumented, provider error text is value-redacted in the model configuration error event, the assistant message and the transcript, every fallback-log field goes through redaction, and after a mid-session model switch the context usage no longer shows the previous model's token count against the new model's window.
- From senpi 2026.11.11 and 2026.11.12: startup no longer fails when the agent's extensions directory is read-only (a sandboxed review child), Claude connection tests keep the redacted provider error and HTTP status and bind each result to the credential they tested, `show_html_page` called from an eval cell is refused instead of silently reaching no reader, and task hosts started from the compiled binary no longer exit with `EBADF` seconds after spawn.
