**macOS sign-in gets the client side of its signed keychain owner.** New modules check the keychain helper's Developer ID signature (an unsigned or ad-hoc copy is never run), find a verified copy, talk to it under the session lock, and keep one approval per process; sign-in uses them through the keychain store below. ([#11586](https://github.com/code-yeongyu/oh-my-openagent/pull/11586), part of [#11262](https://github.com/code-yeongyu/oh-my-openagent/issues/11262))

**Session locks can be handed to a child process for one call.** `withLock` now gives its callback a lease: `handOver(pid)` makes a child the lock's live holder and `restore()` takes it back, aborting the critical section if the lock changed meanwhile. The macOS keychain helper uses it so no other writer can enter while a keychain change is landing. ([#11578](https://github.com/code-yeongyu/oh-my-openagent/pull/11578), part of [#11262](https://github.com/code-yeongyu/oh-my-openagent/issues/11262))

**macOS sign-in stops asking for keychain access again and again.** With OmO's signed keychain helper installed, the sign-in item moves to the helper the first time a token is used, after which reads need no dialog; an item another app created asks at most once per machine with a plain dialog, never a password dialog. Windows and Linux are unchanged. ([#11589](https://github.com/code-yeongyu/oh-my-openagent/pull/11589), part of [#11262](https://github.com/code-yeongyu/oh-my-openagent/issues/11262))

**`omo doctor` checks the macOS keychain helper.** It reports a missing or damaged helper as a warning (sign-in keeps working through the previous path), and an item the OmO desktop app created is now moved to the helper by the app itself before the CLI would ask for keychain access. ([#11613](https://github.com/code-yeongyu/oh-my-openagent/pull/11613), part of [#11262](https://github.com/code-yeongyu/oh-my-openagent/issues/11262))
