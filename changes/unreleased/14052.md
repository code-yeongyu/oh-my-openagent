### Fixed

- A reply to a peer on another device no longer answers `not_found` when the delivery that brought the peer's message carries no device attestation (an `rpc:local/<id>` or bare delivery id). If this device holds no session by that id or stated name, the reply is looked up account-wide. It is delivered only to the session the sender's durable id names; another match is `reply_target_mismatch`.

## 2026-11-17 - Replies reach a remote sender whose delivery names no device (#14052)

- `src/components/thread/tools.ts` `locate`: a reply to a consumed sender without an attested device first resolves on this device as before. When that resolution is `not_found`, the reply runs `resolveAcross` instead. A row on another device is accepted only when its durable id is the sender's id, and is refused `reply_target_mismatch` otherwise. Senders with an attested device (`device:<device>/<id>`) are unchanged.
