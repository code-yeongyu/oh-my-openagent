### Fixed

- A task child whose open was still connecting when its parent released it no longer stays attached to the task host: the open is refused and its connection closed. ([#15069](https://github.com/code-yeongyu/oh-my-openagent/pull/15069))

- A thread message sent with `omo thread send` (or through the thread SDK) to a session that is not running now wakes it, as a message from another session already did, instead of waiting until someone opens it. ([#15024](https://github.com/code-yeongyu/oh-my-openagent/pull/15024))

- Several thread messages sent at once to an idle session no longer lose one or split into a second turn when they race the turn starting: each one joins the turn that is running. ([#15017](https://github.com/code-yeongyu/oh-my-openagent/pull/15017))

- A thread session that is idle or woken with several deliveries queued now takes them all in its first turn, in send order, instead of starting on the first one and running the rest as later turns. ([#14980](https://github.com/code-yeongyu/oh-my-openagent/pull/14980))

- A same-device thread wake that fails is now logged with the session id and the cause, and retried by the carrier's sweep, instead of leaving queued deliveries waiting with no trace. ([#14975](https://github.com/code-yeongyu/oh-my-openagent/pull/14975))

- `omo remote enable` renders the session-host unit for the omo that ran it - the compiled binary or the npm launcher running the verb - instead of an older runtime's OMO_BIN left in the environment, and the launch-time refresh now also upgrades a unit naming an older omo-versions install (#14258). ([#14710](https://github.com/code-yeongyu/oh-my-openagent/pull/14710))

- `omo logout` no longer waits on the credential store twice when a stalled or locked keyring fails its read: it makes one store call, clears nothing, and exits 9 as store-unavailable (the same code as `omo account`). An unreadable stored sign-in is still cleared, as before. ([#14711](https://github.com/code-yeongyu/oh-my-openagent/pull/14711))

- On Windows, a local monitor or thread path written with mixed separators (`C:\\a/b`, `\\\\server\\share/x`) or as a drive-relative path (`C:dir`) is recognised as local instead of being refused as a remote target. ([#14743](https://github.com/code-yeongyu/oh-my-openagent/pull/14743))

- A thread tool given the bare id of a closed thread on another device (`thread_create({ thread })`, `thread_send`, `thread_read`, the control tools) reaches it as `<device>/<thread>` does. When every device is asked at once, a device that answers its own lookup in time could pass the 3.5 s cap and be counted silent, so the call answered `host_unavailable`. Now, when that first round finds no holder, each device that stayed silent is asked again alone, one at a time, with no other lookup of that device service in flight. A retry is made only when the earlier lookups finish in time and the call has enough of its time budget left, so `host_unavailable` can still name a device that was not asked again, as well as one that did not answer on its own. ([#14754](https://github.com/code-yeongyu/oh-my-openagent/pull/14754))

- Closing a remote client now releases the attaches its sessions held, so no idle attach timer outlives the client and fires later against a closed or replaced session ([#14812](https://github.com/code-yeongyu/oh-my-openagent/pull/14812))

- A thread looked up by name on disk in the caller's workspace no longer matches sessions from a sibling directory whose path extends the workspace's (`<root>-tmp`) (#14893). ([#14898](https://github.com/code-yeongyu/oh-my-openagent/pull/14898))

## 2026-11-23 - Release held remote attaches when the client closes (#14812)

A remote client's sessions ports borrowed its connection and only cleared their held attaches when that connection reported closed. Closing the client now closes each port, which clears every held attach and its ten-minute idle timer at once.

## 2026-11-26 - A detach during an in-flight open ends that open's connection (#15069)

`HostSessionClient.detach()` could not reach a client the open had not bound yet, so the open went on, bound a live host connection and opened the session on a client its owner had already released. The open now checks for a detach before binding; if one happened it stops the new client and rejects with `HostSessionDetachedError`.
