### Changed

- Creating a thread on another of your devices (`thread_create` with `device`, `omo remote open`) is faster. The create used to make four round trips over the relay: it looked up the device's engine endpoint, opened the session, attached to it, and named it. Now it makes two. The endpoint is looked up once per device, nothing attaches to the new session, and the name goes straight to it. ([#13889](https://github.com/code-yeongyu/oh-my-openagent/pull/13889), part of [#13404](https://github.com/code-yeongyu/oh-my-openagent/issues/13404))

## 2026-11-16 - a remote create crosses the relay twice, not four times (#13889)

`components/remote/port/device-service.ts` (the thread tools' device-service port):
- `endpointCommand` keeps each device's engine endpoint key from the last endpoint command and sends the next one there (`device-service-core` `endpointCommand` takes `options.endpoint` and names the key it used). Only the refusal of a kept key the device no longer lists (this device's service answers `unsupported` with no command id, or the device answers `route_unlisted`) forgets it and sends the record once more on a fresh `session.endpoints` lookup. An open the engine ran and failed, or an uncertain one, is never sent again.
- `locate` answers a key the open reply already named (`located`) as is, with no attach.
- `sessionCommand(..., { direct: true })` sends the record to the session through `device-service-core` `sessionCommand` (`session.command {session: "<device>.<key>"}`), with no attach.

`control/relay-session-host.ts` names a created session that way. Tests: `remote/device-service.test.ts` ("relay round trips per thread op").
