### Fixed

- Memory sync: a sign-out now retires the trust pin of the account it signs out of, so `omo account show --account <id>` no longer answers `joined` once that sign-in's keys are gone. Plain `omo account forget` (the desktop's sign-out of a CLI-item session) used to retire nothing. It now reads the stored sign-in first to find its account. A stored sign-in that cannot be read is still deleted and its pin is left; one warning line is printed only after the delete succeeds. A forget that fails on a locked store reports only that error (#12308, #12384). ([#13642](https://github.com/code-yeongyu/oh-my-openagent/pull/13642))
- Memory sync: some sign-ins earned their pin before `omo sync` recorded their account. On a refused refresh, plain `forget`, `forget --device` and `adopt --replace`, omo now asks the service for that account, as `omo logout` already did, and retires the pin when the service names it. It asks only while a live pin exists and the access token has not expired; on a refused refresh, the token may still be valid in the 30 s before expiry, when the refresh runs. An expired token is never sent, and a pin the service does not name stays: it can only refuse a reset with `pin_conflict` and never grants trust (#12383). ([#13642](https://github.com/code-yeongyu/oh-my-openagent/pull/13642))
