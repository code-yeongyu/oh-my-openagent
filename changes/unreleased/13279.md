### Added
- Thread gateway: the store can take in a delivery that another device's service attested for a session on this device that is not running (the intake row of #13037). The row is committed in the same transaction as a same-device delivery, keeps the sender's delivery id, text and display text, is rate-limited per sending device, and is admitted later under the engine's own ledger key, so the engine counts it once even if the same delivery also arrives live. A repeat of a delivery id from the same device is answered with the first answer. A reply to such a delivery continues its chain. Nothing in this release calls the intake yet, so no delivery takes this path. ([#13208](https://github.com/code-yeongyu/oh-my-openagent/pull/13208))
- Thread gateway: the store keeps a record of each session a wake asked for or opened (#13037): one row with its state, a lease and a generation that fences every write, at most 4 such sessions past `requested` per agent directory, and a transient open failure that returns the row to `requested` with its attempts and the time of the next one (the third deletes it). A wake primitive resolves a durable id to its one session file, refuses child and worker sessions, ensures the host and sends one plain `open_session` frame (no `attended`, no permission preset). Nothing calls the wake yet. ([#13212](https://github.com/code-yeongyu/oh-my-openagent/pull/13212))
- Thread gateway: the pieces that will let a message from another of your signed-in devices reach a session that is not running on this device are in place but not yet active: the delivery consumer, the carrier that opens such a session in its own working directory and hands it back when its turn is done, and the pending sweep (#13037). Nothing in this release starts them, so a message to a session that is not running is handled as before. ([#13220](https://github.com/code-yeongyu/oh-my-openagent/pull/13220))

### Changed
- The gateway store's schema moves to version 12: three nullable columns on deliveries and a unique index on the new ledger id. The first process on this release migrates the store; any process still on the previous build then reports the store's "schema too new" error on its thread tools and inbox drain until it restarts. ([#13208](https://github.com/code-yeongyu/oh-my-openagent/pull/13208))
- Thread gateway: once a build carrying this store ships, every gateway store open runs the schema step to version 13 (one new table, `woken_sessions`) and raises the store's `user_version` for good. An older build, or a rolled-back one, that shares the same agent directory then refuses to open that store with its "schema too new" error until it is upgraded again. ([#13212](https://github.com/code-yeongyu/oh-my-openagent/pull/13212))

### Fixed
- Thread gateway: a delivery id that the same device repeats after its 30-day receipt expired, while its row is still in the store, is answered from that row as deduplicated instead of failing with a raw unique-constraint error (the review of #13208). ([#13212](https://github.com/code-yeongyu/oh-my-openagent/pull/13212))
- Thread gateway: a session whose file header cannot be read, or names a session kind this build does not know, is never started or reopened unattended. It is refused like a child or worker session instead of being treated as an ordinary interactive one (#13037). ([#13279](https://github.com/code-yeongyu/oh-my-openagent/pull/13279))
