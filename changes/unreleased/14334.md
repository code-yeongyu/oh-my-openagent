### Fixed

- A thread send that names no delivery mode steers the receiver's running turn and starts an idle one on every surface: `thread_send`, `thread_create`'s first prompt, `thread_handoff`, the thread SDK, `omo thread send` and `omo remote send|open` all read the one `DEFAULT_THREAD_DELIVERY` (`auto`), which the `delivery` schema now declares as its default. `follow_up` queues only when a caller asks for it.
