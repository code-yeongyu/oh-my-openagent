**A reply to an agent on another device now reaches it by the id in the message header or by its name, with no prompt on the same account.** One resolver now finds a thread across this device's threads and the account's other devices: an exact durable id, then an account alias, then the name ladder judged over every entry (two devices sharing a name are an ambiguous_target naming both devices, never a silent pick). `thread_send`, `thread_handoff`, the control tools, `thread_create` (open or fork) and the `omo thread` CLI all use it. A reply to the sender of a delivery the run took in is approved from that delivery alone - by the sender's durable id or the name it stated - and must resolve to that sender, else it is refused as `reply_target_mismatch` without sending. The id shown for a thread on another device is its durable id; the relay listing carries it when the device publishes one. The `omo remote` verbs still dispatch by the id you type as the device's session key, so pass the id the device lists under until that path moves onto the shared resolver.

**A send to an agent on another device now reports the same facts as one on this device.** `thread_send` and `thread_handoff` answer `delivery_id` and `effective_mode` for a target on another device too, so a caller reads the delivery's id and the lane it took the same way whichever device holds the thread; `message_seq` and `endpoint` stay the facts of a gateway row on this device, and `device` names another one. The reply allowance (a run answering the agent whose delivery it took in, by that agent's id or stated name, with no prompt) is proved identical for a same-device and a cross-device delivery, and one parity table now runs every send assertion against both legs, so a rule that reads the transport fails the build instead of reaching a user.
