### Security

- Thread tools and gateway deliveries prove each RPC host's identity before changing a session: the client runs the endpoint key's challenge-response, then attaches the selected session by its routing and durable ids on the same connection, so a replacement host that reused a routing id cannot receive a mutation meant for another session. Raw task-host warm and liveness requests authenticate the same way, reading keys from the same agent dir the thread client resolves (`~/.omo/agent`, the flat `~/.omo`, or `~/.senpi/agent`; `SENPI_RPC_KEY_ROOT` overrides). Hosts without these capabilities, terminal control sockets and Windows pipes keep their existing requests. ([#10712](https://github.com/code-yeongyu/oh-my-openagent/pull/10712))
- A draining host's attach refusal surfaces as a transient `host_draining` error and a missing connection as `session_not_attached`; neither aborts or closes the session. A missing key record for an enforcing host surfaces as `auth_required` with the `SENPI_RPC_KEY_ROOT` remedy. Once a mutation has taken effect its result is returned, even when releasing the attachment fails, and the grace-period and release notices go to the omo log once instead of to the terminal. ([#10712](https://github.com/code-yeongyu/oh-my-openagent/pull/10712))
