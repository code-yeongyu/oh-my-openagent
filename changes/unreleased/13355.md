### Added

- Computer use v3: the takeover gate and the session state. Input waits while the user works in the target window, the screen is locked or the machine sleeps, and the user always wins a race: a stop pressed in the middle of a text ends it before the next character, physical input in the target ends a send between its units, and input just before a send holds it. Object-mode replies name the session state they acted under, and the display stays awake only while the session acts. Nothing user-visible changes yet; the existing desktop engine is untouched.
