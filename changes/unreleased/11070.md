**`omo update` on the release binary now installs the update.** It used to only print a curl-and-mv command, although `omo update --help` says only `--dry-run` / `--print` print. It now downloads the release asset, checks it against the release's published SHA-256 before writing or running it, confirms the download reports the target version, and swaps it in by rename, keeping the binary's file mode; `--dry-run` and `--print` still only print. If the directory is not writable, or the download, checksum, version check or swap fails, the installed binary is left in place (on Windows a failed swap puts the previous binary back), and the command exits 1 with the reason and the manual command. Package-manager installs are still refused as before. ([#11070](https://github.com/code-yeongyu/oh-my-openagent/pull/11070))

## 2026-11-02 - Compiled omo update installs the release (fixes #11062)

`compiledUpdate` takes a `replaceBinary` seam; the compiled entry passes `downloadAndSwapBinary` from `compiled-update-swap.ts`. `swapReleaseBinary` refuses an unwritable directory first, then downloads `SHA256SUMS` and the asset into memory and compares the asset's sha256 before anything touches the disk, writes it under a random `<binary>.new-<hex>` name with the installed binary's mode, runs its `--version` (dropping an inherited `BUN_BE_BUN`) and renames it over the binary; on win32 the old binary moves to `.old` first and is renamed back when the second rename fails. The platform steps are injected (`SwapSteps`), so the win32 branch and its rollback run under test on every OS. Probe output echoed in an error is one line of at most 200 printable characters. Must not break: nothing is written or executed before the checksum matches, and `--dry-run` / `--print` / the package-manager refusal still never install.
