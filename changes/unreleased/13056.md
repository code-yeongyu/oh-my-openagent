**A delivery message without a valid id no longer inherits the previous sender's reply allowance.** A `session_control_delivery` whose `delivery_id` is not a string is malformed: it now starts work with nobody approved, instead of passing as a turn the engine started (which kept the earlier group's allowance and hop). The same-account bound of the reply allowance is stated where the rule runs (`component.ts` `noteInput` and the thread `AGENTS.md`), not only in the release notes.
