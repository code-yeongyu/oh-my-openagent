### Changed

- OmO now runs on senpi 2026.11.19-3. A running thread that is sleeping between provider retries now lists `waiting_on` (senpi#7027), and a message from another session to an idle terminal starts its turn even while a draft sits in the composer, leaving the draft untouched (senpi#7045).
- The thread send default is now one shared constant, `DEFAULT_THREAD_DELIVERY` (`auto`: steer a running turn, start an idle one). `thread_send`, `thread_create`'s first prompt, `thread_handoff`, the thread SDK, `omo thread send`, `omo remote send|open` and the gateway engine all read it instead of keeping their own copy. The `delivery` schema now declares `default: "auto"`, and its description says that `follow_up` is only for a message that must wait for the receiver's current turn. ([#14334](https://github.com/code-yeongyu/oh-my-openagent/pull/14334), part of [#14333](https://github.com/code-yeongyu/oh-my-openagent/issues/14333))
- `omo remote send|model|interrupt|close|attach` resolve their target through the shared address module: a thread id, a listing key, an alias, a name or an 8+ hex id prefix, alone or behind `<device>/`, where the device is its id, `here`, its name or a 6+ character id prefix. Before, only a thread id and `<device>/<session>` were accepted. An ambiguous name or prefix is refused with its candidates and nothing runs, a device that missed the listing round answers `host_unavailable` instead of a plain miss, and `model`, `interrupt`, `close` and `attach` refuse an offline device as `device_offline` by every form. ([#14331](https://github.com/code-yeongyu/oh-my-openagent/pull/14331), part of [#14305](https://github.com/code-yeongyu/oh-my-openagent/issues/14305))
- `omo remote` session verbs on `<device>/<thread>` now read one filtered session listing of that device before the command, so a mistyped thread is a typed `not_found` with nothing sent; on dev the text went to the device unread. A thread id or listing key that device does not list yet is asked of the device itself only when this device's service is 0.1.31 or later; an older service answers `host_unavailable` (`wake_unavailable`) and sends nothing, where dev sent it straight to the device. ([#14331](https://github.com/code-yeongyu/oh-my-openagent/pull/14331))
- `omo remote` session verbs: a thread this device holds answers `not_found` with nothing sent, whatever form reached it, and an ambiguous device, name or prefix prints its candidates one per line. ([#14331](https://github.com/code-yeongyu/oh-my-openagent/pull/14331))
- `omo remote attach` checks the relay before it attaches, as the other session verbs do: a device service that is off, signed out, not set up, waiting for sign-in, still connecting or on a plan without remote sessions now answers `host_unavailable` (or the plan refusal) naming its state, and nothing is attached; before, attach had no relay check. ([#14331](https://github.com/code-yeongyu/oh-my-openagent/pull/14331))
- `omo remote sessions --device` names the candidates when the device it was given is ambiguous. ([#14331](https://github.com/code-yeongyu/oh-my-openagent/pull/14331))
- `omo account devices revoke` takes a device by id, name or unique id prefix. A name or prefix two devices share is refused with both candidates (in `--json`, the `candidates` ids) and nothing is revoked; `here` and this device keep the "that is this device" refusal. ([#14331](https://github.com/code-yeongyu/oh-my-openagent/pull/14331))
- Thread tools: a send to a name or id that no device lists, while a device missed this listing round, now answers `host_unavailable` (`listing_incomplete`, naming that device) instead of `not_found`. A reply to a sender whose delivery names no device reads the account listing once instead of twice. In `ambiguous_target` candidates, a thread on this device carries this device's id as `device` (and an `address` that resolves as written) instead of `"here"`. A thread named on an offline device that its last listing does not show answers `device_offline`, and nothing is sent to that device. ([#14328](https://github.com/code-yeongyu/oh-my-openagent/pull/14328))
- A caller's `deadlineMs` now covers a whole remote `sessions.resolve` or `attach` call: the roster read, the listing and the attach (or a session member's call) share one deadline instead of each taking it in full. A spent budget answers the typed `timeout`, whose `details.deadline_ms` is what was left of it. ([#14327](https://github.com/code-yeongyu/oh-my-openagent/pull/14327))
- The thread SDK and `omo thread` resolve every address (`read`, `send`, `bind`, `rebind`, `bindings --session`, `report`, `locate`) through the shared thread address module, so they accept the same forms as the thread tools, `<device>/<thread>` and `here/<thread>` included, with or without the account's devices. ([#14322](https://github.com/code-yeongyu/oh-my-openagent/pull/14322))
- A `send` to a name only another workspace of this device holds answers `scope_denied` unless `--all-scope`, as `read` does, where it answered `not_found`. ([#14322](https://github.com/code-yeongyu/oh-my-openagent/pull/14322))
- A chat connector that delivers a message through a closed binding, or through a binding that takes no inbound messages, is now told to deliver through the binding the gateway keeps for that chat. Before, it got the steps meant for a reporting session. ([#13994](https://github.com/code-yeongyu/oh-my-openagent/pull/13994))

### Added

- Thread tools: `thread_send`, `thread_handoff` and `thread_create` take every address form the shared address module resolves, including `<device>/<thread>` (device by name, id or id prefix; thread by id, name, key or id prefix), `here/<thread>` and `<this device>/<thread>`. A device-qualified thread id reads only that device, and a listing row that publishes no thread id is addressed by its listing key. ([#14328](https://github.com/code-yeongyu/oh-my-openagent/pull/14328), part of [#14305](https://github.com/code-yeongyu/oh-my-openagent/issues/14305))
- The remote client (thread SDK `remote`) accepts a device by its name (any Unicode form, case or inner spacing), `here`, or a unique id prefix of at least 6 characters in `sessions.resolve`, every session member and `attach`; the device part goes through the shared address module's resolver. ([#14327](https://github.com/code-yeongyu/oh-my-openagent/pull/14327))
- The thread control tools (`thread_read`, `thread_close`, `thread_interrupt`, `thread_set_model`, `thread_set_reasoning`, `thread_rename`, `thread_archive`) accept `<device>/<thread>` and `here/<thread>`. The device part is its id, its name or a unique id prefix of at least 6 characters; the thread part is a thread id, name, alias, listing key or an 8-hex id prefix among that device's threads. One address module (`@oh-my-opencode/thread-address-core` plus `thread/address/`) now owns the grammar, the device resolver and the refusals. ([#14318](https://github.com/code-yeongyu/oh-my-openagent/pull/14318))
- `bun run qa:rpc-relay-parity` measures the engine's RPC methods on a pair of signed-in devices: the same record locally and through the relay, compared and classified `same`, `differs` or `missing`. The local-versus-relay parity table (docs/reference/rpc-relay-parity.md) now records a measured verdict for 113 of the engine's 128 methods: the 15 `connection_local` methods are excluded by design, and the 36 rows marked `unsafe-to-probe` were probed only in a harmless form, with each row giving the answer both legs returned. ([#13895](https://github.com/code-yeongyu/oh-my-openagent/pull/13895))

### Fixed

- A remote session member or `attach` no longer sends an unresolved session part to its device: only a thread id, a routing id `rpc-N` or a 22-character listing key passes through unlisted (a session opened a moment ago); any other text no listing resolves answers `not_found` with `details.kind: "session"`. ([#14327](https://github.com/code-yeongyu/oh-my-openagent/pull/14327))
- A remote miss on an online device that did not answer the listing round answers `host_unavailable` with `details.reason: "listing_incomplete"` naming it, in `sessions.resolve`, the session members and `aliases.resolve` / `set` / `clear`; `device_offline` is only for a device the roster says is offline. A device-qualified miss is never blamed on another device's silence. ([#14327](https://github.com/code-yeongyu/oh-my-openagent/pull/14327))
- `bind`, `rebind`, `bindings --session`, `report` and a bound send resolve on this device first; a session only another device holds answers `unsupported` with `details.reason: "session_on_other_device"`, where it answered a bare `not_found`. ([#14322](https://github.com/code-yeongyu/oh-my-openagent/pull/14322))
- A thread address that misses while a device did not answer the listing round answers `host_unavailable` with `details.reason: "listing_incomplete"` naming that device, never `not_found`. ([#14318](https://github.com/code-yeongyu/oh-my-openagent/pull/14318))
- An offline device resolves by id, name or id prefix alike; only a caller that needs it online (thread_create, the control tools) gets `device_offline`, by every form. ([#14318](https://github.com/code-yeongyu/oh-my-openagent/pull/14318))
- `thread_list` and `omo thread list --json` say when one of this device's engines did not answer the listing. The result carries `listing: "incomplete"` and `unanswered_endpoints`, and this device's row reads `incomplete`. Threads held by that engine keep `error_note: "live_unresponsive"` instead of reading as ordinary closed threads. ([#14309](https://github.com/code-yeongyu/oh-my-openagent/pull/14309))
- `thread_list` no longer reports a device as `listed` when the listing round did not hear back from it in full (the relay's page cap, a timeout, an undelivered request). Such a device is now `incomplete`. This device's row carries `dropped`, and the result carries `inactive_dropped`: the number of inactive threads the listing left out. ([#14304](https://github.com/code-yeongyu/oh-my-openagent/pull/14304))
- `thread_read` shows the error text of an assistant message that ended with a provider error, instead of `[]`. A thread stuck in rate-limit retries no longer reads as a run of empty replies. ([#14283](https://github.com/code-yeongyu/oh-my-openagent/pull/14283))
- `thread_list` rows of a running thread whose engine is sleeping between provider retries carry `waiting_on: { kind: "retry", reason: "rate_limit" | "retry", until, attempt, max_attempts }`, so the thread reads as waiting rather than working. This needs an engine that publishes the wait (senpi#7025); older engines list no wait. ([#14283](https://github.com/code-yeongyu/oh-my-openagent/pull/14283))
- Following or attaching a session on this same device when its engine is not running, or when the engine does not accept the connection, now says that this device's engine is the problem and to start or restart omo on this device, instead of reporting that the device service did not answer. ([#13975](https://github.com/code-yeongyu/oh-my-openagent/pull/13975))
- Reopening a closed thread keeps its name, and a name given at reopen is applied (checked for conflicts when the thread reopens on another device), where a reopened thread lost its name. ([#14282](https://github.com/code-yeongyu/oh-my-openagent/pull/14282), fixes [#14274](https://github.com/code-yeongyu/oh-my-openagent/issues/14274))
- A closed thread's session file is found on any engine its device lists when that device's primary engine predates `find_session`, so reopening or reading it no longer fails there; the lookup names why it failed when no engine has the file. ([#14276](https://github.com/code-yeongyu/oh-my-openagent/pull/14276), fixes [#14271](https://github.com/code-yeongyu/oh-my-openagent/issues/14271))
- The Kibitzer `tool_result` hook starts recall delivery without waiting for it, so a steer or a ledger write that never settles no longer holds the PostToolUse hook and the rest of the turn. `whenIdle()` still waits for that delivery. ([#13077](https://github.com/code-yeongyu/oh-my-openagent/pull/13077))
- A thread message that starts a turn on an idle session now reports `effective_mode: "start"` in the tool result and `effective=start` in the delivery header the receiving session reads. It used to report `follow_up`, which looked as if the message had been queued. The lanes are now `start`, `steer` and `follow_up`, on this device and on another device alike: the result names the lane the receiving session's answer proves, so a message that queued is never reported as a start, and a session woken while it is held or waiting on an approval reports `follow_up`. An explicit `follow_up` to another device no longer fails when the state read before it is lost. The gateway store moves to schema v15 so it can record `start`; an older omo build refuses a v15 store with the existing `gateway_schema_too_new` error. ([#14339](https://github.com/code-yeongyu/oh-my-openagent/pull/14339), part of [#14333](https://github.com/code-yeongyu/oh-my-openagent/issues/14333))

## 2026-11-19 - The remote client on the shared address module (#14327)

`components/remote` resolves device parts with the core's `resolveDevice` (`resolve.ts` `resolveRemoteDevice`) and judges a silent device with `deviceListing` (`listingIncomplete`). Removed: `sessions.ts` `resolveSessionTarget` and `targetOf`, `aliases.ts` `sessionOf`, `resolve.ts` `deviceNamed`. `attach.ts` resolves its device part before it opens; `follow` and `wait` open through it.

## 2026-11-19 - The thread SDK resolves through the address module (#14322)

`thread/sdk.ts` calls `thread/address` `resolveAddress` for every address instead of its private paths, with or without a remote surface; an id this device's gateway store owns skips the lookup, and a send lists the host once. The store-only operations resolve over this device's book first and consult the account only on a local `not_found`. `tools/internals.ts` `resolveStoredSession` is deleted (its last caller moved).

## 2026-11-19 - One thread address module (#14318)

New core package `packages/thread-address-core` (dependency-free; vendored by the desktop app) holds `parseAddress`, `resolveDevice`, `normalizeName`, `deviceListing`, row identity (`rowKey`, `rowAddress`, `rowName`, `mergeRows`, `listingKey`, `sameSession`) and the refusals as data. `components/thread/address/` holds `readAccount` (one status, roster and listing read) and `resolveAddress`; `control/locate.ts` loads it lazily from the thread client sidecar. `remote/seams.ts`, `remote/device-address.ts`, `remote/unknown-device.ts`, `remote/plan-create.ts`, `extension/senpi-seams.ts` and `addressing.ts` use the core instead of their own copies.

## 2026-11-19 - this device's listing reports an engine that did not answer (#14309)

`tools/read-ops.ts` `listThreads` counts the endpoints that failed without being known dead (a socket that is gone or refuses is `dead`) and reports `listing: "incomplete"` with `unanswered_endpoints`. `remote/cross-device.ts` `deviceRows` reads it for this device's row. `address-book.ts` `assembleAddressBook` no longer lets the workspace disk scan's copy of a session file (no endpoint) replace the record of the endpoint that claimed it, so a timed-out engine's threads keep `live_unresponsive`.

## 2026-11-19 - thread_list partial devices and dropped counts (#14304)

`remote/port/device-service.ts` `listing()` adds every device whose round state is not `answered` to `incomplete`. `disk-list.ts` returns the durable ids of the session files it did not read (`unread`). `tools/read-ops.ts` `listThreads` counts the inactive threads among them that no endpoint lists (`inactive_dropped`, only when the filter shows inactive threads). `remote/cross-device.ts` `deviceRows` puts that count on this device's row as `dropped`.

## 2026-11-19 - thread_read error text and the retry wait on thread_list rows (#14283)

`tools/read-item.ts` is now the one message-to-item builder for both the live path and the session-file path of `read-ops.ts`. It appends `{type: "error", text}` (capped at 500 characters) when `stopReason` is `error`. `tools/thread-state.ts` `retryWait` turns senpi#7025's `waiting` on a running session's list_sessions row into `waiting_on`. It ignores a thread that is not running, a closed or archived one, and any wait whose shape this build does not know. `internals.ts` `summary()` and `thread-row.ts` carry the field.

## 2026-11-17 - Connector next actions on the inbound path (#13994)

- `src/components/thread/gateway/relay.ts` `inbound`: the `binding_inactive` and `unsupported` refusals carry a connector next action instead of the session-facing defaults, as the default table's comment already says a connector-only refusal does. Codes, messages and details are unchanged.
