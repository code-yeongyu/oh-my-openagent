### Changed

- The macOS live QA pool may use a host with a logged-in console user (R-S4-1): the guest it starts there is a headless clone with clipboard bridging off (`run --no-graphics --no-clipboard`), `--up` prints `console host <user|none>: headless no-clipboard guest`, and the run keeps zero host-input legs because every leg runs inside the guest. Each scenario carries the host's 1-minute load sampled while it ran, and the SET line records the highest leg load, the core count and the p99 of the legs that ran (`hostLoad=`, `cores=`, `p99Ms=`) beside a new `degraded=` count. A pass under a load above the core count, or under a load that could not be read, reads `DEGRADED` on its line and never counts in `pass=`, and a set whose passes are all degraded exits 3, never green. The scenario runner that samples the host load for each leg lands with part 2 of the macOS live tier.
