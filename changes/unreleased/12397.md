**omo-senpi sessions on macOS no longer wake for every file write in HOME.** The config watch added a "a `.omo` may appear here" target for the cwd and every parent up to and including HOME, and a directory watch on macOS receives every change beneath it, so each session handled every write in HOME. Those creation targets now stop at the project root (the first parent holding `.git`), and never include the user config directory's parent (HOME, which the user-config target already covers), any directory that contains it, or the filesystem root. `.omo` directories that already exist are still watched up to HOME; a brand-new `.omo` above the project root is picked up at the next session start. ([#12397](https://github.com/code-yeongyu/oh-my-openagent/pull/12397))

## 2026-11-04 - Config-watch creation targets stop at the project root (#12397)

`resolveOmoConfigWatchTargetResolution` bounds the ancestor list used for creation targets with `creationAncestors()`: it stops after the first ancestor holding `.git`, and before any ancestor that contains the user config directory's parent or is the filesystem root. The walk for existing `.omo` config targets is unchanged. Measured on macOS: a session's CPU during 12 s of HOME writes went from 1.69-1.78 s to 0.03-0.04 s.
