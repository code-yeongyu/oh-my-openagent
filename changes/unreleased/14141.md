### Changed

- **Thread tool rows in the TUI now read like a status line instead of a JSON dump.** Each `thread_*` tool shows one call line (the verb, the target thread's name or short id, and the message's first line) and one outcome line with a few short details: `-> planner  follow-up delivered (turn 306)`, `planner: 12 messages (latest: ...)`, `3 threads in this workspace` with the first few threads, `created scratch`. Delivery ids, message sequence numbers and full uuids stay out of the collapsed row; a failure shows its code, message and next step; the expanded view (ctrl+o) adds the full result. What the model receives is unchanged. ([#12997](https://github.com/code-yeongyu/oh-my-openagent/pull/12997))

### Fixed

- A `thread_send` to a busy thread on another device that was queued there as a follow-up now answers `queued` with its `delivery_id` and `effective_mode`. It used to answer `idempotency_uncertain` ("accepted the message but did not report where it waits") even though the message was delivered and answered. The receiving engine's `queued` admission is its receipt, and its pending-message count does not include admitted deliveries. ([#14013](https://github.com/code-yeongyu/oh-my-openagent/pull/14013), fixes [#14012](https://github.com/code-yeongyu/oh-my-openagent/issues/14012))
- A reply to a peer on another device no longer answers `not_found` when the delivery that brought the peer's message carries no device attestation (an `rpc:local/<id>` or bare delivery id). If this device holds no session by that id or stated name, the reply is looked up account-wide. It is delivered only to the session the sender's durable id names; another match is `reply_target_mismatch`, and an id that more than one device lists is `ambiguous_target` with nothing sent. ([#14052](https://github.com/code-yeongyu/oh-my-openagent/pull/14052))
- `thread_create` with a `prompt` gives the new thread that prompt as its own first user message, with the creator's authority, instead of a relayed peer message under the gateway header. A later `thread_send` from any session, the creator included, keeps the relay header. ([#14058](https://github.com/code-yeongyu/oh-my-openagent/pull/14058))
- `omo -p` exits again after the run calls a thread tool. The device-service connection a thread tool opened is now closed when the session shuts down, so it no longer keeps a finished print-mode run alive. ([#14062](https://github.com/code-yeongyu/oh-my-openagent/pull/14062))
- The thread tools' descriptions now name each tool both directly and in its eval form (for example "thread_list (tool.thread_list() in an eval cell)"), so they read correctly in a session that has no eval tool, where the thread tools are ordinary direct tools. ([#14070](https://github.com/code-yeongyu/oh-my-openagent/pull/14070))
- `thread_list` no longer reports the sessions of a device that is offline or did not answer as live. Their rows come from the relay's cached snapshot and are now listed `resumable`; opening one with `thread_create` asks that device to reopen it, and answers `device_offline` while the device stays offline. A listed thread with an empty title shows its folder's name instead of an empty name; that label is for display only and is not an address. ([#14084](https://github.com/code-yeongyu/oh-my-openagent/pull/14084))
- `thread_read` and the thread control tools no longer answer `not_found` for a session that another device of the account holds but runs nowhere, when it is addressed by session id. `thread_read`, `thread_interrupt`, `thread_rename`, `thread_set_model` and `thread_set_reasoning` answer `not_resumable`, and `thread_close` answers `closed: false` with reason `not_live`, as on the device that holds it. A name still answers `not_found` there, and `thread_read` does not read that device's transcript. ([#14087](https://github.com/code-yeongyu/oh-my-openagent/pull/14087))

### Removed

- A session that calls one of the removed chat-binding tools (`thread_bind`, `thread_unbind`, `thread_rebind`, `thread_bindings`) now gets a plain unknown-tool answer; the hint about them is gone. ([#14042](https://github.com/code-yeongyu/oh-my-openagent/pull/14042))

## 2026-11-18 - Release train 2 top: thread tool fixes (#14141)

- **No hint for the removed chat-binding tools (#14042)**
  - `src/components/thread/tools/relay-tools.ts`, `tools.ts`: `REMOVED_RELAY_TOOL_HINTS` and its registration are removed. The relay SDK, the gateway store and the `omo thread` CLI are unchanged.
- **Replies reach a remote sender whose delivery names no device (#14052)**
  - `src/components/thread/tools.ts` `locate`: a reply to a consumed sender without an attested device first resolves on this device as before. When that resolution is `not_found`, the reply runs `resolveAcross` instead. A row on another device is accepted only when its durable id is the sender's id, and is refused `reply_target_mismatch` otherwise. When this device's entries and the account listing together put that id on more than one device, the reply is refused `ambiguous_target` naming them, whatever order the listing returns (`unattestedSenderAmbiguity`). `tools/reply-target.ts` `replyTargetFailure` is the refusal `replyTargetMismatch` returns. Senders with an attested device (`device:<device>/<id>`) are unchanged.
- **Thread_create's first prompt carries the creator's authority (#14058)**
  - `src/components/thread/gateway/types.ts`: `DeliveryEnvelope.authority` (`"creator"`), stored in the envelope JSON.
  - `src/components/thread/tools.ts`: only thread_create's first prompt to the thread it made sets it.
  - `src/components/thread/gateway/{transport,local-transport,engine,store-ops}.ts`, `remote/relay-transport.ts`: both transports carry it.
  - `src/components/thread/gateway/provenance.ts`: a creator delivery renders as the body, then one line naming the creator session; its display text is the body.
- **Close the thread remote surface on session_shutdown (#14062)**
  - A thread tool call that reaches the device service (`thread_list` with `all_scope`, any cross-device read or send) opened the default remote surface's own device-service connection, and nothing closed it. Its socket is referenced, so a print-mode engine stayed alive after its last session ended (#14054). `createThreadComponent` now closes the surface it built on `session_shutdown`, next to the gateway store it already disposes there. A later call reconnects lazily. A component test spawns an engine-shaped process against the conformance fake device-service owner and asserts it exits by itself after `thread_list` and `session_shutdown`.
- **Read and controls find a session another device holds but runs nowhere (#14087)**
  - `src/components/thread/control/locate.ts` `locateControl`: resolves with the account-wide session-id lookup (`resolveAcross(..., "exact", true)`, #13037 A4.3.3) that a send, a reply and a hand-off make. A session id that this device and the account listing both miss is probed once on each online device. The holder's `ended` row takes the existing `not_live` branch, so `thread_read`, `thread_interrupt`, `thread_rename`, `thread_set_model` and `thread_set_reasoning` answer `not_resumable`, and `thread_close` answers `{ closed: false, reason: "not_live" }`, on both legs (part of #13215). The tools never make the probe for a name or alias, or when this device's service lacks the capability.
