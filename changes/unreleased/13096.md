**`omo login` no longer registers a second device for a computer that already has one.** Before any code, browser tab or new key, it checks the stored sign-in and the device the computer's OmO device service holds (parked included). A held, uncertain, locked or unreadable state refuses a new device and keeps the existing one, instead of adding an "omo CLI on <host>" row beside the desktop's. When the service advertises machine identity, both sign-in flows send a hashed hardware id (`SHA256("omo-machine-v1" + id)`; the raw id never leaves the computer), and a `machine_exists` refusal ends the sign-in without removing or taking over any device.
