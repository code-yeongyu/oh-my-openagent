### Changed

- `thread_send` and `thread_handoff` to a session on another device no longer read the session's state before the prompt: the prompt goes out first as a follow-up, and the other device's engine decides whether it starts a turn or waits behind the running one. On today's engines a send takes two sequential relay round trips instead of three: the prompt, then one state read for the started turn's id (idle session) or for the queue position (busy session). A send that starts a turn drops to one round trip once the other device's engine carries senpi#6135 (which fixes senpi#5999). A send that arrives while the other session has claimed a turn but not yet started it now answers `queued` instead of failing as `unsupported`. A steer still reads the session's state first.
