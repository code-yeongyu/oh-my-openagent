### Fixed

- The local launcher installer no longer replaces or deletes a compiled `omo` at `~/.local/bin/omo`. Ownership is decided from the file's header, anchored at its first bytes and read with a bounded read, instead of searching the whole file for a marker the compiled binary itself contains. A symlink, a file larger than any shim, and a file carrying the header anywhere but at the start are left alone, by install and by uninstall; a shim installed before this change is still replaced and removed. `omo.cmd` follows the owned `omo` and never replaces a wrapper the installer did not write. The installer's report now names every launcher file it left alone (`omo` and, on Windows, `omo.cmd`, each judged on its own) and why; for `omo.cmd` it says that the command `omo` still resolves to the file left alone.

## 2026-11-12 - Launcher ownership is the file header, not a substring (#13258)

`src/install/launcher-ownership.ts` answers `absent`, `owned` or `foreign` with a reason: `lstat` first (a symlink is foreign and its target is never followed), a 64 KB bound, then one `readSync` at offset 0 compared against the two owned headers (the new `// omo-local-launcher v2:` line and the unversioned one every shim in the field carries). `installLocalLauncher` and `uninstallLocalLauncher` use it; `omo.cmd` is owned only when its bytes are exactly the wrapper. `runSenpiInstaller` and `runSenpiUninstaller` report `launchersLeftAlone`, one entry per launcher file left alone (`file`, `path`, `reason`); `runSenpiInstaller` passes its `platform` option through to the launcher install. The ownership functions take an optional last `io` argument (`readPrefix`), a test seam no production caller passes.
**Why:** the compiled `omo` embeds the installer's source, so it contains the marker and the whole header text; the old `includes(MARKER)` check claimed it. Install overwrote a 212 MB binary with a shim and uninstall deleted it (#13254, after #13253).
**Must not break:** both header forms stay owned, or shims already installed become unremovable; ownership must stay anchored at offset 0 and bounded, never a search; `plugin/scripts/install.mjs` is generated from these inputs and is regenerated whenever they change.
