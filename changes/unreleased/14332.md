### Fixed

- A `thread_send` to a busy thread on another device no longer fails with `unsupported` and "Update omo on that device". When that device refuses the steer because its turn just changed (`turn_conflict`, `not_steerable`), a default-mode send now delivers once as a follow-up (`effective_mode: "follow_up"`), and an explicit steer answers `turn_conflict` or `not_steerable`. ([#14326](https://github.com/code-yeongyu/oh-my-openagent/pull/14326))
- `monitor({ type: "rpc", target })` accepts the addresses `thread_send` accepts (a `thread_list` thread value, alias, unique name or id prefix) and `<device name>/<thread>` as well as `<device id>/<thread>`; a target that resolves to nothing is refused at registration with a typed reason (`not_found`, `device_offline`, `ambiguous_target`) instead of starting a watch that can only time out (#14294). ([#14307](https://github.com/code-yeongyu/oh-my-openagent/pull/14307))
- On the Claude subscription path, the `task` tool description no longer loses its spawn rules (batch-wide `run_in_background`, model only for `subagent_type`, English prompts, the plan-reviewer one-shot rule) to Claude Code's 4096-char MCP description cut: the rules now come before the agent and category catalogue (#14291). ([#14292](https://github.com/code-yeongyu/oh-my-openagent/pull/14292))
- `thread_send` to a session held by a person's Stop, an interrupted run or its parent's run hold no longer answers `idempotency_uncertain`. It answers `queued` with `waiting_on: { kind: "hold" }`: the message is kept and runs once the hold is released, so do not send it again. ([#14287](https://github.com/code-yeongyu/oh-my-openagent/pull/14287))
- Thread tools: a reply to a session on another device no longer fails as "not listed on device" while that session is live. The sender's device listing is read once more before any refusal, and each refusal names its reason (`host_unavailable` with `listing_incomplete`, `remote_unavailable`, `wake_unavailable` or `lookup_unavailable`); `not_found` is answered only when the device answered that it lists no such session and its probe found none. ([#14285](https://github.com/code-yeongyu/oh-my-openagent/pull/14285), fixes [#14280](https://github.com/code-yeongyu/oh-my-openagent/issues/14280))
- `omo update` now updates the install your PATH actually runs when omo lives in a side-by-side versions layout (`~/.omo/omo-versions/<version>` with `current` pointing at the live one). It installs the new version beside the old one with bun, checks it runs, switches `current` in one step and keeps the previous version for rollback. It no longer runs `npm i -g` into a copy PATH never uses and then reports a false "update failed". If another omo earlier on PATH still answers with the old version, `omo update` says which install it updated and which path PATH still resolves, and exits non-zero. ([#14256](https://github.com/code-yeongyu/oh-my-openagent/pull/14256))
- A thread_create whose first prompt is not delivered because this omo build is older than the agent dir's gateway store now answers dev's typed `gateway_schema_too_new` refusal (naming both schemas and the update command, with the new thread's id in details) instead of `internal_error`; the message says the thread was created and how to send its first prompt after updating (#13927). ([#14228](https://github.com/code-yeongyu/oh-my-openagent/pull/14228))

## 2026-11-19 - a refused steer conflict is the same race as reply data (#14326)

`remote/relay-transport.ts` `send` reads a steer conflict in both forms the receiver can answer: reply data (`data.kind: "turn_conflict"`) and a refused command (`reason: "turn_conflict"` or `"not_steerable"`). `auto` on the steer lane re-sends once on the follow-up lane for either form under the same delivery id; a second refusal is answered with its own code. An explicit steer maps the refusal through `REFUSAL_CODES`. `remote/outcome.ts` `outcomeFailure` maps both reasons to their own codes instead of the `unsupported` fallback (#14320).

## 2026-11-19 - the held admission kind (#14287)

senpi 2026.11.19-2 (senpi#7014) answers `admit_external_message` and `wake` with `kind: "held"` and `holds[]` when an idle session sits under a hold a peer cannot release. `gateway/adapter.ts` `ExternalAdmissionKind` and `gateway-replies.ts` `EXTERNAL_ADMISSION_KINDS` gain `held`. `remote/relay-transport.ts` maps it, on the live admit path and on the wake path, to `queued` with `waiting_on: { kind: "hold", device }` instead of `idempotency_uncertain`; `gateway/result.ts` maps a same-device row whose `admission_kind` is `held` the same way. No new `ThreadDelivery` kind.

## 2026-11-19 - omo update for the side-by-side versions layout (#14256)

- `versioned-install.js`: `findVersionedInstall` recognises `<versions>/<ver>/node_modules/omo-ai` with `<versions>/current` linking into `<versions>`; `updateVersionedInstall` bun-installs the same package.json shape into `.stage-<ver>-<pid>`, rewrites the `omo` wrapper to the new dir, renames it to `<ver>`, runs it, writes `.complete`, then renames a fresh symlink over `current`. A failed install or a dir reporting another version never becomes `current` (`.failed-<ver>-<ts>`).
- A target dir another writer already installed is adopted when it runs the target (no reinstall, `.complete` added); a live `.stage-<target>-<pid>` of another installer stops the update; `versioned-leftovers.js` keeps the 2 newest `.failed-*` and removes stages whose pid is gone. The `omo` wrapper is generated from its template for the new dir.
- `path-omo.js`: the first executable `omo` on PATH and its `--version` line; a mismatch after the switch exits 1 naming both paths (#12022).
- `self-update.js` chooses the versioned layout before the npm/bun target; `RunOptions` gains `cwd`.
