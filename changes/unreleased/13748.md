### Added

- A new thread can be started with its model, thinking level, approval mode and first message in one step, on this device or on another of your devices: `thread_create` takes `model`, `reasoning`, `permission_preset`, `prompt` and `delivery`, and `omo remote open` takes `--model`, `--thinking`, `--worktree` (with `--branch` and `--base`) and `--prompt`. A model the device cannot run now refuses the create and leaves no session behind, instead of opening one on the default model; an agent can keep or narrow its own approval mode for the thread it creates, never widen it. ([#13748](https://github.com/code-yeongyu/oh-my-openagent/pull/13748))

## 2026-11-16 - thread_create carries the launch profile and the first prompt (#13748)

`contracts/create-params.ts`: `model` (exact provider/id), `reasoning`, `permission_preset`, `prompt`, `delivery`, all for a new thread only (`control/create-launch.ts` refuses them with `thread`, a `delivery` without `prompt`, a model that is not provider/id, and a `permission_preset` wider than the creator's, before anything opens). The model and level ride on the `open_session` frame as senpi's launch profile (`provider`, `modelId`, `thinkingLevel`) on both legs (`SessionOpenRequest`, `ThreadHost.openSession`), so senpi's `model_unavailable` refusal (open-session-model.ts) creates nothing; `control/open-reply.ts` `modelRefusal` maps it to `model_not_found` with `details.reason: "model_unavailable"` on the relay leg and from the local host's thrown text (worktree discarded first). `contracts/permission-presets.ts` holds senpi's preset list and `presetWithin`, the allows-no-more order (full-access > workspace > accept-edits > read-only > ask; auto only between full-access and ask; an unknown creator may ask only for ask). `tools.ts` `firstPrompt` delivers `prompt` through `deliverThrough` to the created thread itself (device + durable id, never a name lookup, #13001) under `<create key>:prompt`; a replayed create answers its stored result, so it is sent once per key. The result's `prompt` is the delivery or `{ error }`; the thread stays created. Test: `control/thread-create-options.test.ts`.

## 2026-11-16 - omo remote open takes the launch profile, a worktree and a first prompt (#13748)

`remote-session-args.ts`: `--model provider/id` (checked), `--thinking`, `--worktree [--branch B] [--base REF]` (needs `--project`), `--prompt TEXT [--steer|--follow-up]`. `remote-session-verbs.ts` `openOn` passes them to `createRelaySessionHost().open`, the same create path as `thread_create`, and no longer sends a `set_model` after the open, so a refused model leaves no session. `personDelivery` is the person pipeline `send` used, now shared with `open --prompt`. `remote-permission-preset.ts` re-exports the preset list from omo-senpi's `permission-presets.ts`.
