### Fixed

- A workflow run whose host process was killed (a crash, a reboot, a terminal restart) no longer stays shown as running after the session reopens. The reopened session takes the run over: a child that is still alive is reattached, a finished one is folded, one that died with its host fails its node, dependents start, and the parent is woken when the run settles (#15125).
- A session never takes over, pauses, retries or cancels a workflow run that another live process is still running (including one still shutting down), cancelling a run that lost its scheduler really stops its node children, and closing a session while it is still taking a run over leaves that run paused with no later takeover (#15125).

## 2026-11-27 - Recovery claims a run its host left running; the lease is the scheduling gate (#15125)

A host that dies without writing the shutdown pause leaves its DAG run `running`. `claimPausedRun` now claims that run as it claims a paused one when `isRunHeldInProcess` is injected and reports no scheduler in this process, and its holder is gone. A live holder still yields `live_lease`, and `pauseRunsForShutdown` no longer pauses a run another live process holds. A claim stays reserved until its run is installed or released, so overlapping sweeps install it once. Holder resolution lives in `run-lease.ts`: every scheduler records its run's lease before its first admission (`takeDagRunLease`), and retry and amend re-entries take it before their first write (`acquireReentryLease`, refusing `run_not_owned`). The lease leaves the record only in the write that ends this host's holding (`leaseAfterEvent`: terminal, park, user Stop; the shutdown pause hands it over as `previousLeaseHolderPid`), never when a scheduler is merely retired. `runHolder` (lease, then previous holder, then for records naming neither the live foreign process owning a node's current, unfinished child) is the one resolver for the claim (`recovery-claim.ts`), the unheld cancel, the shutdown pause and every lease take (`takeDagRunLease` refuses whenever it names another live process, including a still-draining previous holder). The amend guard no longer counts this process as another live lease. A scheduler that finds active nodes whose children it does not hold journals `dag.run.paused` with reason `unattached_nodes` (`DAG_UNATTACHED_NODES_PAUSE_REASON`), returns, and stops listening for commits; retry refuses such a run with `run_still_active` (`refuseUnheldActiveNodes`).

## 2026-11-27 - The DAG runtime schedules only runs it holds or that are still pending (#15125)

`ensureScheduled` (now in `dag-scheduler-registry.ts`) builds a scheduler only for a run this runtime holds or one still `pending`, and records the run's lease before the first admission; a `running` run it does not hold goes to recovery, including when a same-key `start` reuses it. `pauseForShutdown` closes recovery and lease watches (`dag-recovery-sweeps.ts`), waits for any sweep still installing a claimed run, then cancels the watches; `attach` reopens them. Only a running or installed scheduler means the runtime holds a run (`holdsRun`); a verb's controller never registers. Cancelling a run no scheduler here holds ends its nodes' current children first, or refuses with `run_not_owned` while another live process holds it; amend refuses a parked run with `run_still_active`. The runtime logs an error when a run is parked as `unattached_nodes`. The admission task-manager view moved to `dag-admission-task-manager.ts`.
