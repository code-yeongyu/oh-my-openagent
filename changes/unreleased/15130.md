### Fixed

- A workflow run whose host process was killed (a crash, a reboot, a terminal restart) no longer stays shown as running after the session reopens. The reopened session takes the run over: a child that is still alive is reattached, a finished one is folded, one that died with its host fails its node, dependents start, and the parent is woken when the run settles (#15125).

## 2026-11-27 - Recovery claims a run its host left running (#15125)

A host that dies without writing the shutdown pause leaves its DAG run `running`. `claimPausedRun` now claims that run as it claims a paused one when `isRunHeldInProcess` is injected and reports no scheduler in this process, and its holder is gone: the recorded lease, or for a first-generation run, which records none, the live foreign process that still owns its attached children. A live holder still yields `live_lease`. A scheduler that finds active nodes whose children it does not hold journals `dag.run.paused` with reason `unattached_nodes` (`DAG_UNATTACHED_NODES_PAUSE_REASON`) and returns, where it used to throw and leave the run `running`.

## 2026-11-27 - The DAG runtime never schedules over attached children (#15125)

`ensureScheduled` builds a scheduler only for a run it already holds or one whose nodes have no child attached; attached children are reattached by recovery alone. The runtime logs an error when a run is parked as `unattached_nodes`. The admission task-manager view moved to `dag-admission-task-manager.ts`.
