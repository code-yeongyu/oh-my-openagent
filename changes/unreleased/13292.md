## 2026-11-12 - model_profile home refusal: directory outage and project-shipped lookup tools (#13292)

`runPasswdLookup` maps getent exit 2 to "no such account" only when the `passwd:` line of `/etc/nsswitch.conf` names local sources alone (`files`, `systemd`, `altfiles`; `compat` is not local), and never maps macOS `id -P` "no such user" to it, because both tools give that answer when a directory service is unavailable. A missing nsswitch.conf or passwd line counts as local only when `/etc/passwd` has no `+`/`-` line, since older glibc then defaults to `compat`, which reads NIS through those lines; an unreadable file counts as a failed lookup. This account's own missing entry is handled like a failed lookup: folders at or above HOME are refused. The lookup binary comes from `/usr/bin`, `/bin`, `/usr/sbin`, `/run/current-system/sw/bin` or `/nix/var/nix/profiles/default/bin` first, then from absolute PATH entries whose real path is outside the current directory and the folder being checked (`untrustedFolders`), so a direnv `PATH_add bin` or `<project>/node_modules/.bin` entry is skipped (`findOnPath` option `absoluteOnly`; the claude-code callers keep their behavior). Must not break: a bind-mounted project below HOME stays allowed; another account's home is still refused when its entry is found.
