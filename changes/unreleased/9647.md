## 2026-10-06 - Opt-in fresh-session restart when context compaction fails

A long session normally survives through senpi's automatic compaction. When compaction itself fails the session is stuck: every turn overflows or compacts again without getting smaller. The new `context-handoff` component (off by default; `context_handoff.enabled`) leaves healthy compaction alone and acts only on a failure: a `session_compact_failed` event, a compaction rejected because it cannot shrink the context (`would-overflow`, `circuit-breaker`, `per-turn-cap`), usage still at or above `threshold_percent` (default 85) right after a compaction, `compaction_repeat_limit` compactions (default 3) within `compaction_repeat_window_minutes` (default 10), or a run that ends in a provider context-overflow error. It never acts while a compaction is running. On a failure it shows a warning and asks the agent once to write a handoff to `.omo/handoffs/<session-id>.md`; when the file exists omo submits its own `/omo-context-handoff <path>` command, which starts a fresh session (`newSession` with the old session as parent, same cwd) seeded with the handoff, the old session file, and any open goal objective. If the agent cannot write the handoff (its request errors, or 3 settled runs pass) omo writes one from the session record and switches anyway. A session started from a handoff hands off again only after its usage has been below the threshold once, so it cannot loop. Persistent monitors end with the old runtime, so the handoff lists their re-arm commands. `/omo-context-handoff [file]` runs the switch manually.

Tests (`components/context-handoff/index.test.ts`): a disabled feature and a healthy high-usage compaction send nothing; each failure kind (compaction error, each rejection cause, over limit after compaction, repeated compactions inside the window but not spread wider, overflow error but not an unrelated provider error) requests the handoff exactly once; a running compaction or a user-aborted run defers it; a written file dispatches the command; a failed handoff run and an exhausted wait each produce a fallback handoff from the session record; the seeded-session loop guard holds; and the carry-over case seeds known facts, an open goal, and the parent session file into the fresh session through the real command handler.
