### Changed

- Thread tools name a session one way: every input that addresses one is `thread`, and every result that names one carries `thread`, the exact string the verbs take back (still the durable id). `thread_list` rows are `{ thread, name, status, machine?, cwd, created_at, updated_at, link }` plus `device`, `alias`, `surface`, `alive`, `controls` and `error_note` where they apply; `machine` is the display name of the device that holds the thread. Rows no longer show `thread_id`, `sessionId`, `durableSessionId`, socket or session-file paths, or other endpoint internals. `thread_create` and `thread_handoff` answer the thread flat (`thread`, `name`, `link`, ...) instead of a nested `thread` object, and `thread_read`, `thread_send`, `thread_interrupt`, `thread_close`, `thread_rename`, `thread_set_model` and `thread_set_reasoning` answer `thread` instead of `thread_id`. Error details that name a session say `thread` too. `omo thread send --json` answers `thread`, and `omo remote open --json` answers the flat shape (#14044 step 4a).
