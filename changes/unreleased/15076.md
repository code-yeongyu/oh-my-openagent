### Fixed

- The thread tools accept the argument names agents predict instead of refusing them (#15073). A census of every fleet machine found 192 refused calls in 77 sessions, 139 of them `thread_read` with `limit`. `thread_read` now takes `limit` (the newest N messages; also `tail`, `lines`, `count`, `last`); a `limit` above 200 is read as 200 and the answer's `reduced.limit` says so. `limit_bytes`/`bytes` name `max_bytes`, and `wait_ms: 0` reads at once (`wait.outcome: "not_waited"`). `limit` with `cursor` or with `delivery_id` is refused by name. `thread_list` takes `query` (also `search`) and `limit`, which narrow the threads, not the devices. `thread_set_model` takes `reasoning`, and `thread_create` takes `all_scope: true`. `mode` names `delivery` on send and handoff, `message` names `prompt` and `title` names `name` on create, and `title` names `name` on rename. A required field keeps its one name (`message` on send and handoff, `level` on set_reasoning); a call that names `text` or `reasoning` there is refused with the field it meant. A field a tool still does not take is refused, and the refusal shows the corrected `tool.<name>({...})` call; an alias given with a different value than its field is refused naming both.

### Changed

- The SDK parity registry declares each thread tool alias on the branch that reads its field, and the gate checks that an alias maps to a field the branch reads, never shadows a real field, answers like its field, and is refused when it disagrees with it. An `unresolved.json` entry can carry `toolAhead` (a tool ahead of its SDK call until a named slice): in the pull request that adds it, the gate admits only new optional fields it lists, fields it lists as widened whose new schema accepts everything the old one did, and declared aliases, and reports them as TOOL AHEAD for the reviewer.
