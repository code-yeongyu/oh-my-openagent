**Remote session views stop receiving each streamed delta twice, and `omo remote open --model` stops failing.** `open_session` for a remote create, open, or fork now goes on the endpoint dialer (a fresh connection per call, closed once it settles), instead of sharing the long-lived connection the later `session.attach` rides on; opening on the shared connection had attached the host's delegated engine connection to the session as well, so the engine wrote every delta twice. A connection a caller lends is now named borrowed, so the CLI's one shared connection survives the open and the follow-up `locate` and `setModelOn` no longer answer `refused: closed`. ## 2026-11-11 - Remote open_session rides the endpoint dialer, and borrowed connections stay open (#13075)

`endpointCommand` in `device-service.ts` dials through `dialEndpoint` (a fresh owned connection per call by default) and closes it in `finally` only when owned; a borrowed connection (the CLI's shared one, `owned: false`) is left open for its owner. The attach that follows still rides the long-lived connection, which then carries one copy per delta. `device-service.test.ts` pins the split: the open leaves a borrowed connection open for the model set that follows. `device-service-watch.test.ts` pins the duplicate: one copy with the per-call dialer, two without it.
