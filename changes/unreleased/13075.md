**Remote session views stop receiving each streamed delta twice.** `open_session` for a remote create, open, or fork now goes on its own short-lived device-service connection, closed once it settles, instead of sharing the long-lived connection the later `session.attach` rides on; opening on the shared connection had attached the host's delegated engine connection to the session as well, so the engine wrote every delta twice. ## 2026-11-11 - Remote open_session rides a short-lived connection (#13075)

`endpointCommand` in `device-service.ts` opens a fresh connection per call and closes it in `finally` once the record settles; the attach that follows still rides the long-lived connection, which then carries one copy per delta. `device-service.test.ts` pins the split: the open's connection is closed afterwards, the command's is a different, still-open one.
