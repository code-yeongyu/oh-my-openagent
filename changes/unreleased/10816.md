**The git-master skill records why a commit was made and checks what was actually written.** Commit messages now give the reason for a change when it is known, with a ticket reference taken from the branch or the request, and a commit convention the repo declares (template, commitlint, commit-msg hooks, CONTRIBUTING) wins over one guessed from history. After committing, the agent reads back the full stored message instead of the subject alone. When you ask for bisectable history, each commit is built in a temporary worktree and reported one by one. Before a force-push, the agent checks which commits are already on the upstream and asks when they are or when it cannot tell. The setup commands it runs first now depend on the kind of request, so a read-only question no longer runs the full set ([#10816](https://github.com/code-yeongyu/oh-my-openagent/pull/10816)).
