**Computer use v3 on Linux: the AT-SPI accessibility backend.** Linux windows can be read and driven through accessibility. Focus is tracked from the bus's events instead of a search over every application. A window is matched to its accessibility frame by process, exact title and position; when two frames could match, the target is refused instead of guessed. A button press resolves to the one action the control offers, and a control with none is refused before anything is sent. A focused password field withholds the whole tree. Menus are listed and selected by their exact labels. Apps are listed and opened from their desktop entries, without a shell and without the agent's activation token. ([#13831](https://github.com/code-yeongyu/oh-my-openagent/pull/13831))

## 2026-11-16 - v3 AT-SPI accessibility backend (#13831)

`omo-computer-backend-atspi`: `bus.rs` is the D-Bus/AT-SPI seam (`live/` over one accessibility connection with per-call slices, `fake/` a scripted bus that counts every round trip). `backend/` keeps focus and the application roster from events, joins frames to native windows (`owner.rs`), walks through the core `AxReader`, re-identifies refs from the cached snapshot and resolves `press` through the action ladder. `settle.rs` implements the core `SettleSource` (events, A4 `busy`, notification banners), `menus.rs` reads core `MenuNode` trees and selects through `menus::prove`, `secure.rs` classifies secure fields from the shipped protected-target table, and `apps/` lists and opens XDG desktop entries without a shell. Live legs (`--ignored`) press a GTK4 button and select a GTK3 menu item under `dbus-run-session` + Xvfb.
