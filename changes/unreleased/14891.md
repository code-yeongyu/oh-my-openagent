### Fixed

- Memory sync says why the service refused it (#12123). Settings -> Memory -> Sync across devices showed "The service refused this sync request." for every refusal. A refusal whose code is on the service contract's closed list (`not_available`, `entitlement_required`, `access_not_open`, `device_revoked`, `reauth_required`, `account_deleted`, `client_update_required` and its aliases `client_upgrade_required` and `update_required`) now carries that code on the `refused` problem with OmO's own wording, so the app can tell "not available yet" from an account or device problem. Any other code keeps the generic refusal with no code, and the service's message text never reaches the app. ([#12155](https://github.com/code-yeongyu/oh-my-openagent/pull/12155))

- `omo sync enable` on Linux and Windows can now create a recovery phrase for the first device whenever the service accepts phrase keys for the account. The hidden `OMO_MEMORY_SYNC_PHRASE_GENESIS` switch is gone. When the service names devices that must update first, the CLI and the desktop engine say which ones ("Update OmO on <device> first, then run `omo sync enable` again"). ([#14433](https://github.com/code-yeongyu/oh-my-openagent/pull/14433))

- `omo sync recover` now turns memory sync on for the recovered device. Before this fix, a recovered fresh device reported sync as on, but the service refused every sync read. ([#14454](https://github.com/code-yeongyu/oh-my-openagent/pull/14454))

- When the OmO sync service requires a newer client (HTTP 426 `client_update_required`), memory sync now says "Update OmO on this device to keep syncing; sync is paused until then" instead of claiming it retries on its own. It also stops retrying on every edit and stream reconnect, and rechecks every 15 minutes instead. ([#14488](https://github.com/code-yeongyu/oh-my-openagent/pull/14488), fixes [#14483](https://github.com/code-yeongyu/oh-my-openagent/issues/14483))

- Memory sync: signing out of one OmO account and into another on the same computer no longer leaves memory sync stuck. Every push on the new account used to fail with `unverified_base`, because the memory repository resumed the previous account's sync state. Each account now keeps its own: switching accounts sets the previous account's synced memories and sync state aside (switching back restores them), and the new account starts from its own. Memory synced by an older OmO version is kept only when the signed-in account's sync service confirms it synced that memory; if that service shows it belongs to another account, it is set aside rather than uploaded and comes back when that account signs in again. When the service no longer keeps the history that would tell, memory sync says so, uploads nothing and keeps that memory on this device; while the check cannot reach the service, nothing is uploaded or set aside. A switch interrupted by a crash is finished at the next start (#14481). ([#14491](https://github.com/code-yeongyu/oh-my-openagent/pull/14491))

- A memory edit reaches your other signed-in devices sooner. The device that made the edit now sends it 300 ms after the commit instead of 2 s, and skips a check with the sync service when nothing new has been announced. The receiving device skips one more request when the service has already said what changed. When the update stream is refused, sync keeps checking every 10 s instead of going quiet, and the reason is logged. A stream the service closes on schedule reconnects at once without missing an update. ([#14493](https://github.com/code-yeongyu/oh-my-openagent/pull/14493), part of [#14476](https://github.com/code-yeongyu/oh-my-openagent/issues/14476))

- Memory sync: after an account switch, cleaning up the old sync journal no longer drops which account the journal belongs to, so the next sync on that device keeps the account boundary instead of treating the journal as unowned.

### Changed

- Memory sync sends a small edit to the sync service in one request instead of three when the service supports it, so it reaches your other devices about 2 s sooner. ([#14496](https://github.com/code-yeongyu/oh-my-openagent/pull/14496), part of [#14476](https://github.com/code-yeongyu/oh-my-openagent/issues/14476))
- A device's second and later memory edits in a row reach the sync service with one request fewer: the device keeps the record of what it just sent instead of reading it back from the service. ([#14519](https://github.com/code-yeongyu/oh-my-openagent/pull/14519), part of [#14476](https://github.com/code-yeongyu/oh-my-openagent/issues/14476))
