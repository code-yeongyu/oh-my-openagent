## 2026-11-01 - Recover reflection merges after the parent moved (#12076)

On a conflicting finalize merge, the writer-locked integration aborts it, proves the parent clean (no `MERGE_HEAD`, empty status; otherwise `parent_dirty`), rebases the run's validated tip onto the parent HEAD in the run worktree, resolves only conflicts where both sides appended whole lines to a common base that is empty or ends with a newline (an identical append is kept once), re-runs `validateCompletion` on the rebased tip (refusing any path outside the validated set) and merges it, bounded to two rebases. The finalizer checkpoints the rebased tip to the run ledger before merging, so the `Omo-Run` receipt probe matches the tip that landed; a finalize that crashed before that checkpoint (or mid-rebase) resumes by resetting the run worktree to the checkpointed tip and rebasing again, and refuses when the worktree is dirty or holds commits made after validation. The `merge_conflict` detail lists the unmerged paths, since git prints its CONFLICT lines on stdout, and every git stderr and path list in a failure detail is capped by the same bounded formatter.
