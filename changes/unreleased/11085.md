## 2026-10-23 - The init-deep advisor waits for the first real prompt (#9904)

`components/init-deep-advisor/component.ts` no longer runs on `session_start` with reason `startup`. Every senpi RPC `open_session` reports exactly that with `hasUI`, so a host app's background sessions (model-discovery probes, auth or control sessions, prepared drafts) spawned `git rev-parse`, stat'ed the onboarding marker, and could open a dialog in a session nobody sees. The advisor now registers on `before_agent_start` as preview-safe and arms once per session on the first turn whose `trigger` is `"prompt"` and that is not a preview; the preflight also requires `sessionKind === "interactive"`, the onboarding entry rule from the #2197 fix (#9907). A background session that opens and closes with no prompt runs no advisor work at all, and the run stays deferred off the dispatch path so the dialog never blocks the prompt that armed it. Component tests cover the background open-and-close case, the first-interactive-prompt offer, the preview / worker / extension / delivery / headless exclusions, and the once-per-session latch.
