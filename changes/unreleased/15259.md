### Fixed

- OmO Native no longer asks the first-run telemetry consent question in an RPC session. On 5.1.84 the question was asked whenever a session's UI had a `confirm`, which an RPC session's forwarded UI also has, and `session_start` waited for an answer that no client could give while the session was opening. Every `open_session` on a multi-session RPC host, and every process-mode `task` child, hung until it timed out. The question is now asked only in an interactive TUI session; RPC, print and json sessions ask nothing and write nothing, as the 5.1.84 notes already stated (#15213, #15196).
