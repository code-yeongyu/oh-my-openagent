## 2026-11-27 - ps-lstart start identity is read in UTC under its own scheme (#15260)

On darwin/freebsd without `bun:ffi` (a Node runtime), the memory-core process-start identity falls back to `ps -o lstart=`, which prints local time in the reader's timezone and locale. Two processes with different `TZ` (or `LC_ALL`) settings read the same pid as the same scheme with different bytes, `startIdentitiesConflict` counted that as pid reuse, and a live owner read as dead, breaking memory-core stale-lock recovery and the memory run-liveness check. `readPsLstartIdentity` now runs `ps` with `TZ=UTC`, `LC_ALL=C` and `LANG=C` through an injected exec seam and records `ps-lstart-utc:`; a record an older reader wrote as `ps-lstart:` is a different scheme, so during a mixed-version upgrade it is kept, not reclaimed. The bundled extensions and the omo-native reflection-lock and service-auth bundles are regenerated. Covered by `process-identity.ps-lstart.test.ts`, which reads the same live pid with the real `/bin/ps` under two timezones and against a legacy local-time record. Supersedes #12531.
