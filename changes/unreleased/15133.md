### Fixed

- A workflow node whose child finishes and then resumes on its own is followed again: the node returns to running and folds the resumed turn's outcome, where the run used to keep the first result and ignore the rest (#12134). Cancelling the workflow also cancels such a resumed child, including one that wakes while the cancel is under way (even after an earlier cancel found it finished) or that resumed while the session was restarting. A resumed turn that already ended while the session was down is folded when the workflow is recovered, instead of the workflow continuing on the earlier result. A node that was waiting for a free child slot does not start on the earlier result: it waits for the resumed turn and is skipped if that turn fails.

## 2026-11-27 - A DAG node re-watches a child that resumes on its own (#12134)

The scheduler subscribes to a completed node's task through the optional `TaskManager.subscribeSelfResumed` and re-attaches it when the child reopens its turn, so the resumed outcome folds onto the node. One rule decides who may re-open a node: the scheduler holding a still-running run, for the node's current task under the same `execAttempt`, owned by that run and node (`scheduler-self-resume.ts`). A reopen during cancellation attaches the task, and cancellation drains attached tasks until every attached task's current run epoch was asked once, each request fenced with `expectedRunEpoch` (a finished child answers `noop` and can still reopen). Recovery re-opens a completed node whose task's latest run is self-resumed (`resumed_run_epoch === run_epoch`) and ended non-completed, or completed with an answer other than the persisted node output, and hands the task to the scheduler to fold; no new persisted field. A scheduler watches every completed node's task when it starts running (recovery, re-entry) and follows one already live under a self-resumed epoch. Each admission pass revalidates residency-denied nodes against their dependencies; one whose dependency is no longer completed returns to `pending` (reason `resumed`, the shape recovery uses for an unadmitted scheduled node), and a scheduled node without an attached task never counts as having consumed a dependency's output. A host that does not implement the subscription keeps the previous behaviour. Port of #11387.
