### Fixed

- A workflow node whose child finishes and then resumes on its own is followed again: the node returns to running and folds the resumed turn's outcome, where the run used to keep the first result and ignore the rest (#12134). Cancelling the workflow also cancels such a resumed child, including one that wakes while the cancel is under way (even after an earlier cancel found it finished) or that resumed while the session was restarting. A resumed turn that already ended while the session was down is folded when the workflow is recovered, instead of the workflow continuing on the earlier result. A node that was waiting for a free child slot does not start on the earlier result: it waits for the resumed turn and is skipped if that turn fails.

## 2026-11-27 - A DAG node re-watches a child that resumes on its own (#12134)

The scheduler subscribes to a completed node's task through the optional `TaskManager.subscribeSelfResumed` and re-attaches it when the child reopens its turn, so the resumed outcome folds onto the node. The decision is the one `selfResumeVerdict` that #15135's self-resume fence also asks (the node's current claim of a run neither settled nor being cancelled): the scheduler re-opens a node only when that verdict allows and it holds the running run, so a turn started during cancellation is refused and never followed, and a turn allowed while the run is paused is followed by the scheduler that next holds it. Stacked on #15134 and #15135, it has no cancellation drain of its own: #15135's run-wide stop covers a resumed child, asking a child again when it is live after an answer that found it stopped. Recovery re-opens, through the attach/fold gate every recovered node passes, a completed node whose task's latest run is self-resumed (`resumed_run_epoch === run_epoch`) and ended non-completed, or completed with an outcome other than what the node persisted (output and run_stats sidecar, both derived by the same `dagNodeResultContents` the fold writes with), and hands the task to the scheduler to fold; when a stale claim of the node cannot be stopped, the node fails closed (`stale_attempt_alive`) and the dependents that consumed its earlier output are flagged by the same `flagConsumedDependents` a folded resumed failure uses. No new persisted field. A persist without `run_stats` now removes an earlier fold's stats sidecar. A scheduler watches every completed node's task when it starts running (recovery, re-entry) and follows one already live under a self-resumed epoch. Each admission pass revalidates residency-denied nodes against their dependencies; one whose dependency is no longer completed returns to `pending` (reason `resumed`, the shape recovery uses for an unadmitted scheduled node), and a scheduled node without an attached task never counts as having consumed a dependency's output. A host that does not implement the subscription keeps the previous behaviour. Port of #11387.
