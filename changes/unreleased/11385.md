**Cancelling or amending a DAG run now stops every child the run owns, and an amended node never adopts its old child.** A completed node's child that resumed on its own (its background work woke it) kept running after the run was cancelled, because cancel stopped only the children it was still attached to. When the run was then amended to change that node, re-admission attached the old live child as the new attempt, so the amended model, category and prompt never ran while the old child kept writing in the node's worktree. Cancel now stops every live child owned by the run, including an earlier attempt's child that resumed after the next attempt's task started. Before a re-entered run admits anything, every live child of an earlier attempt of a node (an amend or retry raised its attempt) is cancelled, so the new attempt starts fresh. If that child cannot be stopped, the node fails with the retryable `stale_attempt_alive` instead of being attached or run beside a second child. An automatic infrastructure retry that finds the failed attempt's child running again stops it the same way before failing the node. A live child of the same attempt is still adopted as before (#7412). ([#11385](https://github.com/code-yeongyu/oh-my-openagent/pull/11385), fixes [#11381](https://github.com/code-yeongyu/oh-my-openagent/issues/11381))
Legacy child records without an execution-attempt field are stopped only when their stored fingerprint proves an earlier attempt, including fingerprints from the run's amendment history. An unrelated amendment therefore preserves a live child of the current attempt, even when that attempt was retried before the upgrade.
