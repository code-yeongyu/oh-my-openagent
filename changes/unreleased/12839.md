### Changed

- Task children ask through the parent session instead of being refused: a child's permission prompt (and its other select, confirm, input and editor dialogs) is raised on the parent's UI, so Allow runs the child's call and Deny does not. A child the parent turn is waiting on asks on the connection that started that turn; a background child asks every attached client that may answer. Secret inputs and permanent grant selections are never forwarded. Children in their own process or on the task host open in the parent's approval mode and follow every later change of it, one change at a time and always ending on the latest; a child that could not follow is reported to the parent session. ([#12839](https://github.com/code-yeongyu/oh-my-openagent/pull/12839))
- `omo remote open` and the thread tools' create and fork on another device name the approval mode the new session runs in: the creating session's own mode, or for `omo remote open` the new `--permission-preset` flag, else this device's own setting; a setting that cannot be read is a usage error rather than the loosest mode. ([#12839](https://github.com/code-yeongyu/oh-my-openagent/pull/12839))

### Fixed

- Memory facts extraction records facts again with senpi 2026.11.6-3: the facts child (also used by onboarding's understand step) keeps the approval mode its own settings give it and may run only its own record tools without asking, instead of being refused as a child whose parent is gone.
- Concurrent memory account resolves on a desktop host share one open, so the app sees one `descriptor` request instead of one per caller; a failed open is retried by the next resolve (carried from #12717, which this PR supersedes).
