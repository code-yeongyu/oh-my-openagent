**Computer use v3 on Linux: X11 input groundwork.** On X11, apps are classified by toolkit from what they actually expose, and a Qt app running on xcb without the accessibility bridge reads as unavailable in the background instead of failing later. Synthetic XTEST input is only allowed while the agent holds the foreground lease, and keys you are physically holding are never released by the agent. Typed text resolves in the keyboard layout group that is active right now; a character with no key in that group is refused as `unresolvable` with nothing typed, and the agent pastes instead unless you opt into a temporary scratch-key remap, which restores your keymap afterwards. Window moves and resizes report the geometry the X server actually applied, and apps are listed and opened through the desktop's XDG entries. ([#13900](https://github.com/code-yeongyu/oh-my-openagent/pull/13900))

## 2026-11-16 - v3 X11 input units (#13900)

`omo-computer-backend-x11` adds `toolkit.rs` (evidence-based toolkit classification; Qt xcb without the accessibility shim -> background-unavailable), `input/xtest.rs` (XTEST admitted only under the foreground lease), `input/holds.rs` (user-held keys are never released), `input/keys.rs` (graphemes resolve in the active XKB group only; no keycode -> `unresolvable` with nothing sent and a paste as the default next step; the opt-in scratch-keycode remap restores the keymap, and a refused remap also answers `unresolvable`), `frame_verbs.rs` (geometry read back from `ConfigureNotify`) and `apps.rs` (XDG resolver for apps list/open). Refusals use the typed `Reason`. Wiring into `Backend::post_input`, row 27's route table and row 48's AT-SPI apps is owed to a later head of this row.
