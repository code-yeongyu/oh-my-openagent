**Computer use v3 on Linux: X11 input.** On X11 the agent now clicks, types, scrolls and holds keys through XTEST, but only while it holds the foreground lease. Keys you are physically holding are never released by the agent. If the engine dies mid-hold, a small helper process releases whatever it left down. Typed text goes through the keyboard layout group that is active right now. A character with no key in that group is refused as `unresolvable` with nothing typed, and the agent pastes instead, unless you opt into a temporary scratch-key remap, which always restores your keymap. Background clicks and keys go only to apps whose toolkit really accepts them (Xt/Motif, Tk). GTK, Qt without the shim, Chromium, Electron, Firefox, LibreOffice, xterm and unknown apps are refused with the toolkit named, never silently dropped. Return into a chat composer you listed in `computer.send_on_enter` is refused before it can send. Window moves and resizes report the frame the window manager actually applied, and apps open through the desktop's XDG entries. ([#13900](https://github.com/code-yeongyu/oh-my-openagent/pull/13900))

## 2026-11-27 - v3 X11 input wired (#13900)

`omo-computer-backend-x11` routes `Backend::post_input` through `input::X11Input`. Every X request (XTEST, XKB `GetMap`/`GetState`, `QueryKeymap`, `ChangeKeyboardMapping`, `XSendEvent`, the EWMH client messages, `ConfigureNotify`) goes through the `InputServer` trait, with a recording fake for tests and an x11rb `InputConnection` (features `xtest`, `xkb`, `res`) that has its own connection.

- `Route::ForegroundHid` (the session's lease route) is the only path to XTEST. The background routes take `XSendEvent`, gated by `toolkit::background_route`.
- A `Call` drop guard releases a call's strokes and restores the scratch keycode on every exit path, panics included. Dropping the input releases every engine hold, warping each button to its press origin first.
- `release_helper` (`omo-computer-engine --x11-release-helper`, its own process group) is told each hold before it is pressed, and releases a dead engine's holds when its pipe closes (L5). `capabilities().release_helper` reports it.
- Typing is per grapheme (`unicode-segmentation`), with C0 controls mapped to their keysyms. An `InvalidKey{unresolvable}` refusal carries `data: {group, grapheme}`, and the error table owns the next call. The scratch keycode must be free in every group and level and in the modifier map.
- Toolkit evidence comes from `/proc` maps, child command lines, the exe and `resources/app.asar`, plus the X-Resource client pid. `WM_CLASS` is used only as an exact key of row 27's route table.
- Refusals are typed: `BackgroundUnavailable{toolkit|chromium_electron|canvas_gl|pointer_hw}` with `data.toolkit`.
- `pointer()` and `user_held_keys()` only read. `set_frame` / `set_minimized` use `_NET_MOVERESIZE_WINDOW`, `WM_CHANGE_STATE` and `_NET_ACTIVE_WINDOW`, with the read-back translated to root coordinates.
- The send-on-enter guard of row 26 matches the focused client's exact `WM_CLASS` and fails closed on an unknown role.
- `apps.rs` only delegates to row 48's `AtspiBackend` resolver.
