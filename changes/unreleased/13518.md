### Fixed

- `bun run test:fast` releases the serial quarantine's process group only when that phase finished normally. While a shutdown is in progress the PGID is retained, so the SIGKILL escalation still reaches a descendant that ignored the signal — the orphan case the registry exists to prevent. The child registry gained an explicit `release` for a finished group and the serial spawner uses it; a test also pins that no `ROOT_TEST_SERIAL_QUARANTINE` path falls inside the `opencode-memory` or `senpi` group scopes, so the split's disjointness is checked rather than assumed.
- All three `test:fast` groups now pass the canonical per-file budget, read from `POSIX_TEST_TIMEOUT_MS` in `script/root-test-serial-quarantine.ts` — the same definition the serial phase and the full command use, with no second copy of the value. Without it only the first file of each group got the preload default and every later file fell back to Bun's built-in budget, so a slow file could fail on the budget rather than on its own behaviour. A test asserts the argv actually spawned for each group name, including Bun's flag order for the `--config` invocation. Any file counts cited for this change are measured at this head (#12031).
