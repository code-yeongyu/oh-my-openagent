### Fixed

- `bun run test:fast` releases the serial quarantine's process group as soon as that phase exits, instead of retaining its PGID for the whole parallel phase where a later signal could reach an unrelated process that reused the id. The child registry now has an explicit `release` for a group whose work is finished, and the serial spawner uses it; the retention that shutdown escalation needs is unchanged. A test also pins that no `ROOT_TEST_SERIAL_QUARANTINE` path falls inside the `opencode-memory` or `senpi` group scopes, so the split's disjointness is checked rather than assumed.
- All three `test:fast` groups now pass the canonical per-file budget, `--timeout 20000`, taken from the same definition the serial phase and the full command use. Without it only the first file of each group got the preload's default and every later file fell back to Bun's 5000 ms, so a slow file could fail on the budget rather than on its own behaviour. A test asserts the argv actually spawned for each group name, including Bun's flag order for the `--config` invocation (#12031).
