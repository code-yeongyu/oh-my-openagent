### Changed

- The thread SDK and `omo thread` resolve every address (`read`, `send`, `bind`, `rebind`, `bindings --session`, `report`, `locate`) through the shared thread address module, so they accept the same forms as the thread tools, `<device>/<thread>` and `here/<thread>` included, with or without the account's devices.
- A `send` to a name only another workspace of this device holds answers `scope_denied` unless `--all-scope`, as `read` does, where it answered `not_found`.

### Fixed

- `bind`, `rebind`, `bindings --session`, `report` and a bound send resolve on this device first; a session only another device holds answers `unsupported` with `details.reason: "session_on_other_device"`, where it answered a bare `not_found`.

## 2026-11-19 - The thread SDK resolves through the address module (#14322)

`thread/sdk.ts` calls `thread/address` `resolveAddress` for every address instead of its private paths, with or without a remote surface; an id this device's gateway store owns skips the lookup, and a send lists the host once. The store-only operations resolve over this device's book first and consult the account only on a local `not_found`. `tools/internals.ts` `resolveStoredSession` is deleted (its last caller moved).
