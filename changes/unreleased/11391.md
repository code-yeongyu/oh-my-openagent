**A permission denial or a refusal by the user is final for what the refused call was meant to do.** Every model route of Sisyphus, Sisyphus-Junior, Hephaestus and Atlas now ends its prompt (before any `prompt_append`) with one rule: never reach a refused result with another tool, command, path or host; ask the user. Every ultrawork variant (default, Gemini, GLM, GPT, Codex, planner) and the todo and boulder continuations carry the same rule. A test enumerates every prompt route, so a new route without the rule fails. The continuations say "Proceed without asking whether to continue" instead of "Proceed without asking for permission". Computer-use telemetry still counts a refusal as a permission denial when senpi adds guidance after its first sentence. ([#11371](https://github.com/code-yeongyu/oh-my-openagent/pull/11371), part of [code-yeongyu/senpi#4309](https://github.com/code-yeongyu/senpi/issues/4309))

**Bug reports reach the OmO team again.** Every report sent from `/bug`, `/feedback` or the desktop's in-app report was refused by the report service, which the app showed as a connection problem. Reports now carry the exact-body SHA-256 and length and a semantic redactor version, as the service requires, and terminal reports use your `omo login` account when you are signed in; signed-out reports still work, and an expired or unusable sign-in sends the report without your account instead of blocking it. In the terminal, each refusal the service can answer is now named: sign-in refusals point to `omo login`, a request the service rejects shows its error code and request ID, a service-side failure says to try again later, and only a send with no answer is reported as a connection problem ([#11194](https://github.com/code-yeongyu/oh-my-openagent/issues/11194), [#11213](https://github.com/code-yeongyu/oh-my-openagent/pull/11213)).

### Fixed

- Bundled skills no longer ship `test`, `tests`, `__tests__`, or `*_test` folders nested below a skill's top level (such as ultimate-browsing's `engine/tests`), so a test module can no longer run inside the installed app and write caches there. Top-level `test/` and `tests/` resources still ship. ([#11377](https://github.com/code-yeongyu/oh-my-openagent/pull/11377), part of [#11373](https://github.com/code-yeongyu/oh-my-openagent/issues/11373))
- Running a bundled skill no longer writes files inside the installed app, so OmO Desktop no longer reports its files as changed and stops its local server after the coding-agent-sessions, ultimate-browsing or frontend skills run their Python scripts. A manual ast-grep install now downloads into a user cache folder instead of the skill folder. Python the agent runs now keeps its compiled bytecode in an OmO cache folder instead of next to the script, so your projects still start fast without `__pycache__` folders appearing in them; if you set `PYTHONDONTWRITEBYTECODE` or `PYTHONPYCACHEPREFIX` yourself, OmO leaves both alone. Thanks to @minerva32 for the report. ([#11376](https://github.com/code-yeongyu/oh-my-openagent/pull/11376), fixes [#11373](https://github.com/code-yeongyu/oh-my-openagent/issues/11373))
