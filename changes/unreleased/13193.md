A write needs the folder to be trusted, refuses a file that does not parse, and refuses a value that is neither a profile id nor a `provider/model` pin. ## 2026-11-12 - Read and set a folder's model_profile over RPC (#13193, fixes #13188)

`model-profile/project-model-profile-rpc.ts` registers `omo.project.model_profile.get` / `.set` through `pi.rpc.handle`; a client reaches them as `extension_request`, which the engine classes `device_admin`. The model-profile component records the session's cwd and its `isProjectTrusted()` inside its existing `session_start` handler (the component keeps exactly one `session_start` handler). A set writes only `model_profile` through omo-config-core's `updateOmoConfig` (atomic, comment-preserving, refuses symlinks) and answers the file as read back; `null` removes the key. It refuses, writing nothing: an untrusted folder (`project_not_trusted`), a file that does not parse (`project_config_parse_error`), a value that is not a builtin or configured profile id or a literal `provider/model` pin (`invalid_model_profile`), and a call with no bound session (`no_session`). Must not break: no other omo.jsonc key is ever written by these verbs, and `settings.json` `defaultProvider`/`defaultModel` stay "last used" (`index.ts`), not a pin.
