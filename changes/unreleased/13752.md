### Changed

- The device service client takes one injectable clock for its handshake, request, endpoint-command and attach waits, so each of those deadlines can be tested on fake time. Real timers stay the default and no wait changed. ([#13473](https://github.com/code-yeongyu/oh-my-openagent/pull/13473))
- Remote access now has its own module (part 4a-1 of the one remote module design): typed results, one code list, a deadline table and a clock seam, with the service, devices and session list members. Nothing uses it yet, so no command or tool behaves differently. ([#13498](https://github.com/code-yeongyu/oh-my-openagent/pull/13498))

### Fixed

- `omo remote` now prints the credential store's own message when it cannot read your sign-in, such as the `omo account forget` hint for an invalid stored sign-in or the note that the OS credential store is locked or unreachable, instead of only the generic notice. ([#13644](https://github.com/code-yeongyu/oh-my-openagent/pull/13644), fixes [#13638](https://github.com/code-yeongyu/oh-my-openagent/issues/13638))
- A host the compiled `omo` binary starts now reports the same runtime build id as the `omo host ensure` that started it. The binary added its own plugin folder to the host's command line on top of the launch spec, so with no spec, or with a copy of the spec, the host and the CLI disagreed: the desktop app judged its own engine a build mismatch and every handover's replacement host exited. ([#13700](https://github.com/code-yeongyu/oh-my-openagent/pull/13700))

## 2026-11-16 - A spec-launched host keeps its own extension list (#13700)

`compile-args.ts` `buildSenpiArgs`: a socket host child (`--mode rpc --multi-session --listen` with `--extension` paths from its launch spec) is returned unchanged, like a `--no-extensions` caller, so the host's `runtimeBuildId` and `launch_profile` match what `host ensure` predicts from the spec. `host ensure`, `host handoff` and `host session open` without `--launch-spec` get this runtime's `plugin/daemon-launch-spec.json` (when it exists), as `omo daemon` already passes it, so a spec-less ensure still starts a host with the plugin. New test: `test/compiled-host-runtime-id.test.ts` computes both ids with the installed engine's own functions.
