### Changed

- On Linux with no keyring (no Secret Service on the session bus, or a Bun without `Bun.secrets`), `omo login` and `omo account` keep the shared sign-in in a private file, `~/.omo/account-state/omo-cli-<id>.json` (directory 0700, file 0600), instead of failing with `store-unavailable`. A locked keyring or a keyring whose store fails still reports its own error and never falls back to the file. When a keyring runs later, the sign-in moves into it, and the file is deleted only after the keyring returns exactly what was written. On Linux, the errors no longer say "Credentials are never saved to a file."; macOS and Windows are unchanged.
- `omo account show` and `omo account adopt` answer an additional `storage` field, `"keyring"` or `"file"`, naming where the shared sign-in is kept.

### Fixed

- The Linux keyring probe reports a missing Secret Service only when gdbus says so: no session bus, or nothing owns `org.freedesktop.secrets`. Other gdbus failures, such as a Secret Service with no default collection, keep asking libsecret.
