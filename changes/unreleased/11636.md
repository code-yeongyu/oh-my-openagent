### Fixed

- A `task` call that is not isolated no longer fails when a model fills the optional isolation fields: without isolation, `apply: false` and a `merge` equal to the effective default are accepted and ignored, while `apply: true` or a different `merge` is refused with a message naming the field, its value, and that isolation must be enabled. Batch items follow the same rule, including values inherited from the top level, and the refusal names the item. Thanks to @bkutasi (bazsi1__ on Discord) for the report ([#11628](https://github.com/code-yeongyu/oh-my-openagent/issues/11628)).

## 2026-10-28 - Accept no-op isolation fields on non-isolated task calls (#11628)

Without isolation, `apply: false` and a `merge` equal to the effective default (`task.isolation.merge`, else `patch`) are no-ops: accepted and ignored. Only a behaviour-changing value (`apply: true`, or a different `merge`) is refused, with a message naming the field, its value, and that isolation must be enabled. Batch items follow the same shared rule, including values inherited from the top level, and the refusal names the item. Thanks to @bkutasi (bazsi1__ on Discord) for the report.
