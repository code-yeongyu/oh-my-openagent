**A process child whose provider has no usable sign-in now moves on to the next provider instead of failing.** When the engine refuses a child's first prompt with `provider_credentials_missing` or `provider_credentials_expired`, the task skips the remaining models on that provider and starts on the next provider in its fallback chain, ending on the parent session's model when nothing else is left. Each hop is recorded as a `task_model_fallback` event naming the provider. An engine that does not send these codes behaves exactly as before. Every other refused first prompt in process mode now also carries the engine's validated error code as `cause_code` in its `task_start_failed` event and in the start-failure message (for example `host_refused: host_memory_pressure`); this is diagnostic only and does not change what the task does. ([#11440](https://github.com/code-yeongyu/oh-my-openagent/pull/11440), part of [#10806](https://github.com/code-yeongyu/oh-my-openagent/issues/10806))

**A queued steer to a subagent keeps its own id across the child boundary, and a lost acknowledgment is checked before anything is sent again.** A message queued for a child that is still starting reaches it under the id it was queued with, so a drain repeated after a restart replays instead of delivering a second copy. When the child's acknowledgment is lost, omo asks the child whether it holds that id (`get_pending_inputs`): held settles it, not held resends the same id, and an unreadable answer keeps it uncertain instead of guessing. ([#11427](https://github.com/code-yeongyu/oh-my-openagent/pull/11427), part of [sisyphuslabs/omo-desktop-app#2838](https://github.com/sisyphuslabs/omo-desktop-app/issues/2838))

**Model-profile notices no longer reach the model.** A notice such as "model profile ... has no available model" was sent as part of the conversation, so the model read it ahead of your first message, and on a slow start it could cost an extra model request. The notice now stays out of the conversation: when there is something to do, the desktop app shows it as a notice with the next step (sign in from Provider authentication settings, or choose a model in the composer), and a headless run logs it. ([#11365](https://github.com/code-yeongyu/oh-my-openagent/pull/11365)) A stored login that failed while a working provider was used instead still reaches you as a notice naming the provider to re-authenticate, and a profile model the registry no longer finds is reported with the step to choose another model.

**Memory read grants now check the file a raw-string tool actually opens.** Containment follows native filesystem traversal before normalizing paths, so a directory symlink followed by `..` cannot redirect a project-memory grant to another identity. Built-in tools retain their resolved-path behavior, missing notes remain readable through their existing canonical ancestor, and case aliases of the same directory remain accepted. ([#11339](https://github.com/code-yeongyu/oh-my-openagent/pull/11339))

**Completed Momus review verdicts are now persisted as numbered Markdown artifacts next to the plan file.** Each `.omo/plans/{plan}.reviews/NNN-okay.md` or `NNN-reject.md` artifact captures the verdict, timestamp, model, plan sha256, review duration, reviewer session id, and the verdict block (the reasoning that precedes the verdict is not stored), so a finished review survives the end of the session. A `.gitignore` written next to the plans keeps the `.reviews` directories out of the user's own staging area. Momus itself stays read-only; persistence happens entirely on the orchestrator side after the review result returns. ([#11237](https://github.com/code-yeongyu/oh-my-openagent/pull/11237), fixes [#3002](https://github.com/code-yeongyu/oh-my-openagent/issues/3002)) Thanks to [@surlymochan](https://github.com/surlymochan) for this contribution.

**Release binaries may be up to 200 MiB, and 5.1.49 was not published.** omo 5.1.49's Linux binaries came out over the 182 MiB size budget (linux-x64 200.0 MB, linux-arm64 198.2 MB), so that release stopped before anything was published; 5.1.50 is the next release. The growth is the Bun 1.4.4 runtime itself: an empty compiled Bun program grew from 90.8 MB to 109.1 MB between Bun 1.4.3 and 1.4.4, while everything omo added since 5.1.48 is about 0.46 MB. The budget moves from 182 MiB to 200 MiB so releases keep shipping the Bun version CI tests. ([#11491](https://github.com/code-yeongyu/oh-my-openagent/pull/11491))

## 2026-10-27 - Workflow category nodes keep the parent model as their last rung (#11439)

A DAG run records the parent session's model at start (`DagRunRecordV1.parentModel`), and scheduler admission, node retry and crash/resume recovery pass it as `parent_model`, so `withParentModelRung` adds the same last rung a task child gets (#10750). Runs persisted before this change behave as before.

## 2026-10-27 - A queued steer reaches the child under its own id; a lost acknowledgment is read before any resend (desktop #2838 step 4) (#11427)

`drainPending` sends each `pending_steering` entry with `{ clientMessageId: entry.id }`, and every handle
layer (`ManagedChildHandle` and both adapters, the in-process handle, both RPC runners, `input-delivery`)
passes that identity to the engine; `input-effects` sends a caller's own id as it is and mints one only when
none is given. A drain repeated after a lost acknowledgment or a parent restart therefore replays the same id
on the child instead of delivering a second copy.

An unacknowledged input is resolved through the child's `get_pending_inputs` read (senpi#3549) before
anything is sent again: `admitted` settles it, `not_admitted` resends the same id, a failed read keeps it
uncertain. An earlier run's uncertain input is still never sent into a later run, but it now fails as
`superseded_by_new_run` only when the read says it was not admitted; admitted settles it and a failed read
keeps it uncertain. The run an uncertain input was sent in is stored on it (`run_epoch`), since a queue
entry's id carries no epoch. A child that cannot answer the read keeps the previous same-id resend.

Not in this change: TTL/terminal retention of queued entries (T45/T46) and the engine's custody receipt on
`steer`/`prompt` answers (senpi#4383).

An error answer other than an unknown command, and an id the child leaves out of its answer, both count as unreadable, so nothing is sent on them.

## 2026-10-26 - model-profile outcomes leave the conversation (#11365)

`components/model-profile/index.ts` records every outcome with `pi.appendEntry(<type>, { content, details }, { startupBookkeeping: true })` instead of `pi.sendMessage`. senpi's `convertToLlm` turns every custom message into user text in the next provider request (its context-exclusion predicate is false for every type), so the notice reached the model, and one sent while the first prompt streamed was delivered as a steer. The three custom types and their `details` are unchanged; only the entry kind moved from `custom_message` to `custom`. An outcome that leaves the profile unapplied also goes to `ctx.ui.notify`: `warning` for a chosen profile that no available model serves, an unknown profile name or a stored login that failed, `info` when the unset default falls back to the session's own model. `notice.ts` names the next step per host (rpc: Provider authentication settings or the composer; headless: `/login` or `--model`). ## 2026-10-26 - Align project-memory grants with raw file reads (#11339)

Suffix-classified external file tools no longer receive a grant for a different file when a symlink is followed by `..`. Built-in resolved reads remain supported, and the missing-note exception is limited to ENOENT with plain missing segments: a missing path such as `missing/../note.md`, `a/./b` or `a//b` is not granted. Real filesystem tests cover grants, the soft guard, temporary HOME detection, and native case aliases. A missing remainder under a file is refused on every platform (Windows reports ENOENT there, not ENOTDIR), and the temporary-HOME check judges HOME the way the install id is written (lexically resolved), so a HOME like `<tmp>/link/../home` that writes inside the temp root counts as temporary, and a lexical HOME that does not exist yet counts as temporary too (telemetry stays off).

## 2026-10-26 - Admit sessions before host reconciliation (#11335)

The task event bridge restores local pause and transition state, attaches RPC and workpools, then lets the existing durable recovery chain finish asynchronously. Its abort signal fences the recovery tail on a newer start, switch or shutdown. The lifecycle carries its own disposal and shutdown generation through host probes, admission and revival; stale probe completions cannot claim newer ownership, and late respawn handles use fenced suspension. Endpoint groups reconcile independently while the shared admission lease still enforces per-session capacity. Deterministic regressions cover blocked probes, disposal, shutdown, newer same-process claims, independent hosts and late handles.

## 2026-10-26 - Native path traversal before containment (#11339)

The shared containment helper sends the original child and parent paths to native realpath before lexical normalization. Project-memory grants preserve that component sequence, resolve the deepest existing ancestor for missing notes and append the missing segments verbatim, refuse a missing remainder that holds a `.`, `..` or empty segment, and reject non-missing lookup failures. The external-tool soft guard uses the raw target while built-ins keep the resolved target they open. Regression coverage includes the temporary-HOME caller and existing Windows path semantics.
