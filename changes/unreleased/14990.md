### Fixed

- `ThreadSdk.send` to a thread on another device answers the `delivery_id` of the prompt it sent, as `thread_send` answers its delivery's. ([#13016](https://github.com/code-yeongyu/oh-my-openagent/issues/13016))
- A script's `ThreadSdk.send` steer without `expected_turn_id` to a session on this device steers its running turn, as the same call to another device does; a session's steer must still name the turn on every leg. ([#15007](https://github.com/code-yeongyu/oh-my-openagent/issues/15007))

### Added

- The omo SDK root's `devices.resolve` names a device as every device address does: its id, `here`, its name (case and width folded), or a unique id prefix of six or more characters. A name or prefix several devices share answers `ambiguous_target` with the candidates, each `{ device, name, online }` (an agent session's candidates carry `{ device, name }`) (the remote client's `devices.resolve` answered a shared name with `{ id, name }` candidates and its own message before; it now answers as the device resolver does, with `{ device, name, online }` and the resolver's message). An agent session's answer holds the device id only. ([#13016](https://github.com/code-yeongyu/oh-my-openagent/issues/13016))

### Changed

- The thread tools, `ThreadSdk`, the monitor target and `omo remote` resolve a thread address through one shared function with one policy (replies, the reply grant, workspace scope, `self`, text with a slash). Answers are unchanged. ([#13016](https://github.com/code-yeongyu/oh-my-openagent/issues/13016))
