### Fixed

- `omo setup` no longer repeats a malformed credential or config file's contents in its notices. When OpenCode's `auth.json`, the engine's `models.json`, an OpenCode `opencode.json[c]`, an oh-my-pi or gajae-code `agent.db`, or the engine's model list cannot be read, the warning names the file and says what kind of failure it was (`not valid JSON` with a line and column when the runtime gives one, `SQLite: <reason>`, a filesystem code) instead of the runtime's error text, which could quote the file around a bad token. ([#15247](https://github.com/code-yeongyu/oh-my-openagent/pull/15247), fixes [#10983](https://github.com/code-yeongyu/oh-my-openagent/issues/10983))
