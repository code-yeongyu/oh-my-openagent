### Changed

- When another device lists no engine of its own (`no_primary_endpoint`), the thread tools now give the steps that fix it in order: run `omo host ensure` on that device; if it refuses, save its output and `omo host status --json`, stop only that device's primary host and ensure again (an omob build, which has no `omo host` command, is restarted instead); if it still names no engine, update the device service on both devices. The answer's machine-readable remedy is `host_ensure_restart_or_update_device_service`.
