**A monitor command runs through the shell, so loops and pipes work.** `monitor_start` split the command into argv and spawned it directly, so `for i in 1 2 3; do ...; done` failed with `Executable not found in $PATH: "for"` and `tail -f log | grep ERROR` passed `|` to `tail`. The command now runs through the same shell OpenCode's `bash` tool uses. Bash permission is asked for each simple command in the line, so a deny rule for one program also catches it after `;`, `&&`, `|`, inside a loop body or behind a comment; command substitutions, subshells, `case` and `function` are denied. On the allowlist fallback, every program in a pipeline or list must be listed, and compound commands, redirects, and substitutions are denied.
