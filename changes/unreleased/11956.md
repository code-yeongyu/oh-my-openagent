### Added

- Add the engine CA importer's launcher trust stage: verify and adopt an inherited generation, or acquire a private generation and exec once with an independent hop bound. A failed import keeps only explicit extras and leaves implicit default inputs closed; child environments regain their original values. This is the launcher increment of the staged rollout, not the transport-error, background-refresh, trust CLI or desktop integration. ([#11956](https://github.com/code-yeongyu/oh-my-openagent/pull/11956), part of [#10762](https://github.com/code-yeongyu/oh-my-openagent/issues/10762))

Distrusted intermediate certificates under an allowed root are not yet blocked; tracked upstream.

Engines started by the OmO desktop app, or by an OmO server you start yourself, no longer read `SSL_CERT_FILE` or `SSL_CERT_DIR`. If your root certificate is only in such a file, install it in your operating system's certificate store, or add it in the desktop app under Settings, Extra CA certificates. A server you start yourself also keeps honoring `NODE_EXTRA_CA_CERTS`.

On Linux, OmO now trusts only your distribution's generated certificate bundle. A root placed directly in `/etc/ssl/certs` or `/etc/ssl/cert.pem` without running `update-ca-certificates` or `update-ca-trust` is no longer trusted; install it with that tool. If OmO cannot read your operating system's certificates, the failed request says why and what to do.

The last sentence describes the completed rollout; its transport-error explanation is a later increment and is not enabled by this launcher-only change. This change merges after the 5.1.53 freeze.
