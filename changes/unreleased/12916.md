**`thread_send` steers by default.** A message to a session that is running a turn now lands inside that turn (senpi's steering queue, picked up at the turn's next tool boundary) instead of waiting behind it; an idle session starts a turn and an offline one takes the message when it comes back, as before. Pass `delivery: "follow_up"` to queue behind the running turn instead. The result's `effective_mode` reports the lane the target actually used (`steer` or `follow_up`) and `delivery.kind` the admission (`steered`, `queued` or `started`). Messages arriving through a chat binding whose `inbound_mode` is `auto` follow the same rule. ([#12916](https://github.com/code-yeongyu/oh-my-openagent/pull/12916))

## 2026-11-09 - thread_send steers a running turn by default (#12916, fixes #12914)

`thread/gateway/decision.ts` `decideDelivery`: `auto`, the default mode, admits every busy target (`mid_turn`, `waiting_question`, `compacting`) as a steer at the turn epoch the drain read in the same pass; `idle` still starts a turn, `offline` is still `queued_offline`, and `follow_up` still queues. An explicit `steer` is unchanged (needs the caller's `expected_turn_id`, refuses idle/compacting/question-waiting targets as `not_steerable`). senpi admits a steer in every busy phase (`external-admission.ts`: an enqueue into the steering queue, consumed at the next tool boundary), so the earlier `not_steerable` cells for `auto` were the gateway's own policy. `thread/gateway/drain.ts`: when senpi answers `turn_conflict` for an `auto` row (the turn ended between the drain's claim and its admission), the row is requeued with its lane cleared instead of refused, so the chained turn-end wake decides it against the new state. `contracts/fields.ts` `ThreadDeliveryMode` and `contracts/params.ts` `inbound_mode` describe the behaviour.
