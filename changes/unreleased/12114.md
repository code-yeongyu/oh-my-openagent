**A stuck session can ask a stronger model for a hint on its own.** The new `advisor` block in `omo.json` (off by default) watches the session's recent activity; every few tool results a decision model is asked whether the agent is stuck or wandering, and when it says yes, a short tool-less child on the model you pin (or a category chain) reads the same activity and its hint reaches the session as a hidden steer. The decision endpoint, its model, the environment variable holding its key, the threshold, the interval, the cooldown and a per-session cap are all settings. ([#12112](https://github.com/code-yeongyu/oh-my-openagent/issues/12112), [#12114](https://github.com/code-yeongyu/oh-my-openagent/pull/12114))

## 2026-11-02 - advisor component: decision-model gate asks a configurable advisor model when a session wanders (fixes #12112)

New omo-senpi component `advisor` (`packages/omo-senpi/src/components/advisor/`) and `advisor` config block (`packages/omo-config-core/src/schema/advisor.ts`, regenerated `assets/omo.schema.json`). Hooks keep a bounded per-session window; every `check_every` tool results `decision-gate.ts` posts it to `advisor.decision_url` in the `/v1/decisions` shape (`state` + one `noul` question) with the bearer key from the variable named by `advisor.api_key_env`, and at or above `advisor.threshold` `advisor-child.ts` runs one tool-less in-process child on `advisor.model` (else the `advisor.category` chain via `resolveKibitzerSidecarModel`) with `advisor.timeout_seconds` as its bound. The hint is sent as a hidden `omo-advisor:advice` steer; each gate call appends an `omo-advisor:gate` entry. Off by default; no key means no request; failures only log.
