**A stuck session can bring in a stronger model on its own.** The new `advisor` block in `omo.json` (off by default) watches the session's tool calls; a cheap decision model judges after each one whether the agent is stuck and how (repeating a call, re-reading something unchanged, polling, an error streak, wandering), and only when it says so a stronger model (Claude Opus 5.5 at high thinking by default) reads the task and the recent calls and writes a plan with the root cause, the target state, exact steps and how to verify. The plan reaches the session as a hidden steer. The decision endpoint, its model, the environment variable holding its key, the thresholds, the advisor model, a cooldown and a per-session cap are all settings. ([#12112](https://github.com/code-yeongyu/oh-my-openagent/issues/12112), [#12114](https://github.com/code-yeongyu/oh-my-openagent/pull/12114))

## 2026-11-02 - advisor component: decision-model gate brings in a stronger model when a session is stuck (fixes #12112)

New omo-senpi component `advisor` (`packages/omo-senpi/src/components/advisor/`) and `advisor` config block (`packages/omo-config-core/src/schema/advisor.ts`, regenerated `assets/omo.schema.json`). Hooks keep a bounded per-session window of tool calls; from `advisor.min_calls` on, every `advisor.check_every` tool results `decision-gate.ts` posts the last 8 calls as a `state` object to `advisor.decision_url` with two questions (`stuck` noul, `kind` choice) and the bearer key from the variable named by `advisor.api_key_env`. When `stuck >= threshold`, the kind is not `none` and its confidence reaches `kind_confidence`, `advisor-child.ts` runs one tool-less in-process child on `advisor.model` at `advisor.thinking` (falling back to the `advisor.category` chain via `resolveKibitzerSidecarModel`) with the ROOT CAUSE / TARGET STATE / DO THIS / VERIFY coaching prompt, bounded by `advisor.timeout_seconds`. The plan is sent as a hidden `omo-advisor:advice` steer; each gate call appends an `omo-advisor:gate` entry. `scripts/qa/advisor-e2e.mjs` is the live proof (real senpi, mock providers, mock decisions server). Off by default; no key means no request; failures only log.
