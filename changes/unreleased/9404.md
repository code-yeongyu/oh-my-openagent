## 2026-10-01 - The assistant-tail recovery turn is no longer appended to tool rounds (#9404)

Contributed by @Nowaker. The OpenCode edition's messages transform appended a synthetic recovery turn ("[internal] Continue from the previous assistant state.") whenever the request ended on an assistant message after a compaction continuation, or on any round for prefill-rejecting models. OpenCode sends an assistant step that holds a tool call as the call followed by its tool result, so on tool rounds the request already ended on a tool result. The appended text sat next to that result and moved on the next round, which made every earlier turn look edited, broke prompt caching (about 1,447 full replays and 464M extra cache-write tokens over three days in the reporter's measurement), and gave the model a pointless "continue" each round. In `packages/omo-opencode/src/plugin/messages-transform.ts`, `ensureUserTurnAfterAssistantTail` now returns early when the last step that reaches the wire carries a client-executed tool part, matching OpenCode's conversion, which turns completed, error, pending and running tool parts into tool results. A text or reasoning tail, and a provider-executed tool (which produces no tool result), still get the recovery turn. Four tests in `messages-transform.test.ts` cover the tool tail after a compaction continuation, every tool state on a prefill-rejecting model, a text step after an earlier tool step, and a provider-executed tool.
