### Fixed

- A task whose child ends its turn while its own async work is still pending (a detached eval cell, a background terminal job) is no longer recorded `completed` with its progress note as the result. All three runners (process, shared host, in-process) hold that turn on the engine's own report of the child's pending work and complete it with the answer of the turn the work's completion starts. Work that stops progressing for an hour, or that finishes without anything waking the child (an in-process child), ends the task as a visible `async_work_pending` failure that names the work. ([#12133](https://github.com/code-yeongyu/oh-my-openagent/pull/12133), fixes [#10487](https://github.com/code-yeongyu/oh-my-openagent/issues/10487); thanks @Bearmancer for #10532)

## 2026-11-02 - A completed turn with the child's own async work pending is held in every runner (#12133)

`runners/pending-async-work.ts` reads `SessionLifecycle.waitingOn` (`background` sources and the `children` count): the engine's own record of the work a session owns, pushed as `session_lifecycle`, answered by `get_state`, and exposed in process as `AgentSession.lifecycle`. It already folds the producers that publish only on the engine's internal bus (the background-terminal job), which the `wake_source_state` extension-event ledger from #10532 never saw. That ledger stays as the fallback for an engine that reports no lifecycle. A team member's on-duty source (`senpi-task-member`) is residency and is excluded.

`runners/async-work-hold.ts` holds a completed outcome from `agent_idle` (RPC runners, through `runners/rpc/turn-tracking.ts`) or from `prompt()` resolution (in-process, `runners/in-process/async-work-turn.ts`). Each confirmation re-reads the session state and the pending work: a work-started turn replaces the held outcome with its own, drained work on an idle session settles the held completion, and work that stays unchanged with no child activity for `asyncWorkStaleLimitMs` (60 min) settles as the typed `async_work_pending` failure naming the work. An in-process child runs in print mode, where senpi-codemode delivers no completion notification, so drained work with no wake turn settles as the same failure. While held, `pending()` reports that failure, so an exit or park never records the progress note. `async_work_pending` is a new `TaskStartFailureKind`, persisted as `failure_kind` and not an infrastructure retry.
