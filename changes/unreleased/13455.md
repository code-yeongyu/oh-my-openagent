### Added
- Thread gateway: the session wake of #13037 now runs in production, but only on an engine at or above the wake engine minimum `MIN_WAKE_ENGINE_VERSION` (A8.1): the first engine release that drops a woken session's retained record (senpi#6449). That release has not been cut, so in this build no engine starts a carrier at all and a `thread_send` naming a session that is not running answers as it did before the wake existed (`queued_offline` with `reason: "wake_unavailable"`). Where the minimum is met, every `tui` or `rpc` engine (never a task child, never under CI) starts one carrier per agent directory on its first session start: it opens the session by path on the operator host that `thread_create` opens on, sends the engine's `wake`, and hands it back quietly once it has finished; the answer is then `queued` with `waiting_on: { kind: "wake" }`. It still follows `session_wake.same_device`, read for the target session's own project, which stays off by default.
- Thread gateway: the carrier sweeps its woken rows on a timer only while the table holds a row (design A3.1.4: an empty table leaves no timer), and it shares the thread component's own gateway store: a running wake never opens a second store of the agent directory.
- Thread gateway: a session's own inbox drain admits nothing while a carrier is opening it (A3.1.5). It asks the device service whether a row's sending device is admitted before it takes in a delivery from another device (5.6).

### Changed
- The delivery consumer (design 5.4) is wired beside the carrier, but it serves nothing in this build, for two reasons. The engine minimum for a woken session, `MIN_WAKE_ENGINE_VERSION`, is unset until the engine release that drops a released session's retained record (senpi#6449) exists (A8.1), and that same minimum now gates the carrier as well. The device service's local API does not carry the delivery protocol yet.
