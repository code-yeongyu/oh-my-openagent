### Added
- Thread gateway: the session wake of #13037 now runs in production. Every `tui` or `rpc` engine (never a task child, never under CI) starts one carrier per agent directory on its first session start. When a `thread_send` names a session on this device that is not running, the carrier opens it by path on the operator host that `thread_create` opens on, sends it the engine's `wake`, and hands it back quietly once it has finished. The answer is then `queued` with `waiting_on: { kind: "wake" }`. This build still follows `session_wake.same_device`, which stays off by default, so the answer is unchanged until it is turned on.
- Thread gateway: a session's own inbox drain admits nothing while a carrier is opening it (A3.1.5). It asks the device service whether a row's sending device is admitted before it takes in a delivery from another device (5.6).

### Changed
- The delivery consumer (design 5.4) is wired beside the carrier, but it serves nothing in this build, for two reasons. The engine minimum for a woken session, `MIN_WAKE_ENGINE_VERSION`, is unset until the engine release that drops a released session's retained record (senpi#6449) exists (A8.1). The device service's local API does not carry the delivery protocol yet.
