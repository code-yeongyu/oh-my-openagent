### Fixed

- The onboarding context no longer embeds the absolute filesystem path of the installed built-in skills root, so the session context is identical for identical builds whatever the install location. The tour now names the built-in `onboarding` skill, which the skills listing resolves by name (#12150).
- When a user or project skill named `onboarding` shadows the built-in in the skills listing, the tour falls back to the built-in skill's absolute path instead of silently following the shadowing skill; the EQ goldens are re-recorded for the new pointer text (#12544 review).
- Contributed skills (computer-use, x-search) again yield to any loaded same-name skill, even when the listing carries no path for it, so no duplicate surfaces as a skill-conflict collision; with `onboarding` in `disabled_skills` the tour falls back to the built-in path instead of naming a hidden skill (#12544 review).
