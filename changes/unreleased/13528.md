### Fixed

- `migrateConfigFile` in `@oh-my-opencode/utils` no longer replaces a config file whose content already equals the migrated output. It used to skip only the backup and still ran the atomic write: a byte-identical replacement that swapped the file's inode and waited on two fsyncs. No current code path calls this function, so the visible effect is in the test suite: the `skips backup when file content is identical after migration` case no longer waits on disk flushes, which is what let it pass the 20 s limit on a host with stalled storage (#11839).
