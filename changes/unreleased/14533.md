### Fixed

- Memory sync: a sign-out now retires the trust pin of the account it signs out of, so `omo account show --account <id>` no longer answers `joined` once that sign-in's keys are gone. Plain `omo account forget` (the desktop's sign-out of a CLI-item session) used to retire nothing. It now reads the stored sign-in first to find its account. A stored sign-in that cannot be read is still deleted and its pin is left; one warning line is printed only after the delete succeeds. A forget that fails on a locked store reports only that error (#12308, #12384). ([#13642](https://github.com/code-yeongyu/oh-my-openagent/pull/13642))
- Memory sync: some sign-ins earned their pin before `omo sync` recorded their account. On a refused refresh, plain `forget`, `forget --device` and `adopt --replace`, omo now asks the service for that account, as `omo logout` already did, and retires the pin when the service names it. It asks only while a live pin exists and the access token has not expired; on a refused refresh, the token may still be valid in the 30 s before expiry, when the refresh runs. An expired token is never sent. A pin whose account stays unknown is kept, and omo prints one line naming `omo account retire-sync --account <id>` to clear it, because `omo account show` keeps answering `joined` for it (#12383, #13662). ([#13642](https://github.com/code-yeongyu/oh-my-openagent/pull/13642))

### Added

- `omo sync status` (and `--json`) shows this device's memory sync state: the signed-in account, whether this device has joined and whether its sync switch is on, the account's devices with their sync membership and last-seen time, pending join requests, and whether an engine is running on this machine. It writes no sync state, prints no key material, and each section reports its own failure instead of failing the command. ([#14437](https://github.com/code-yeongyu/oh-my-openagent/pull/14437), fixes [#14435](https://github.com/code-yeongyu/oh-my-openagent/issues/14435))

## 2026-11-20 - omo sync status (#14437)

- `sync-status-cli.ts` collects the report (`collectSyncStatus`, one typed section per source) and renders it (`syncStatusLines`). Joined = a live trust pin under `trustAnchorDir`; switch = `isDeviceSyncOff`; devices come from `service-auth/devices.ts` `listLiveDevices` (the same read and schema `omo account devices` uses; it parses `syncing`), exposed on `SyncContext.listDevices`.
- `sync-engine-status.ts` reports engine presence only: the operator socket (`resolveTaskHostSocket`) is read with senpi-task's shared `probeSocket` (the host liveness probe): `no_engine` when absent, not a socket, or refused; `running` when a connect succeeds; `unreadable` with the reason for a permission error or a host that does not answer within 2 s. The probe closes without sending a request, so it neither authenticates nor attaches; on POSIX the supervisor still counts the connection as activity, so it resets an idle engine's idle-exit clock. The engine answers `omo.memory.sync.status` only inside a session, and attaching to read it would resume and re-park another surface's session, so the engine's sync details are not read here: code-yeongyu/senpi#7107 tracks the session-less read and #14456 wires it into this command.
- `sync-cli.ts` (399 lines) is split by verb: `sync-recover-cli.ts`, `sync-approve-cli.ts` and `sync-void-notice.ts`.

## 2026-11-20 - a typed socket probe shared with omo sync status (#14437)

`runners/rpc-host/busy-host.ts` gains `probeSocket` (`accepts` / `refused` / `unknown` with a reason): ECONNREFUSED and ENOENT are `refused`, a permission error or no answer within the timeout is `unknown`. `socketAcceptsConnection` is now `probeSocket(...).kind === "accepts"`, so the liveness path is unchanged, and `omo sync status` uses the same probe instead of a copy.
