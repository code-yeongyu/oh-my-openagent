### Fixed

- A thread addressed by its bare id is no longer taken by a stale session file on this device when the account listing names another device that holds the session, online or offline: `thread_send` and `thread_read` go to that holder (an offline one answers `device_offline`, nothing is queued for the file). When no single live holder decides (the other device holds it ended), the call is refused `ambiguous_target` naming every device; when the account listing cannot be read or a device missed it, it is refused `host_unavailable` instead of falling back to the file. A thread only this device knows still resolves here, as does one whose holder's rows the account listing no longer carries at all (#15246).
