### Changed

- OmO now runs on senpi 2026.11.19-2. A message one session sends to another that is paused only because nobody is watching it (an unattended hold) now continues that session instead of waiting silently. ([#14287](https://github.com/code-yeongyu/oh-my-openagent/pull/14287))

### Fixed

- `thread_send` to a session held by a person's Stop, an interrupted run or its parent's run hold no longer answers `idempotency_uncertain`. It answers `queued` with `waiting_on: { kind: "hold" }`: the message is kept and runs once the hold is released, so do not send it again. ([#14287](https://github.com/code-yeongyu/oh-my-openagent/pull/14287))

## 2026-11-19 - the held admission kind (#14287)

senpi 2026.11.19-2 (senpi#7014) answers `admit_external_message` and `wake` with `kind: "held"` and `holds[]` when an idle session sits under a hold a peer cannot release. `gateway/adapter.ts` `ExternalAdmissionKind` and `gateway-replies.ts` `EXTERNAL_ADMISSION_KINDS` gain `held`. `remote/relay-transport.ts` maps it, on the live admit path and on the wake path, to `queued` with `waiting_on: { kind: "hold", device }` instead of `idempotency_uncertain`; `gateway/result.ts` maps a same-device row whose `admission_kind` is `held` the same way. No new `ThreadDelivery` kind.
