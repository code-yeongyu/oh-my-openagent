**The desktop session's actionability wait test no longer fails on a busy host.** The battery's wait now runs on an injectable clock: the host's monotonic time in a session, as before, and the fake backend's own clock in the test. So `the_battery_waits_for_an_element_that_appears_enabled_after_500_ms` checks the 500 ms wait in fake time instead of wall-clock bounds that host load could break. Runtime behaviour does not change.
