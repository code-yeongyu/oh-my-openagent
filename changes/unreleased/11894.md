**Live job widgets use your `quick` category model, and background tasks feed them.** When the running senpi supports job widgets, the model that writes a widget for a long background job is the one your `quick` category resolves to (the session model when `quick` has no usable model; an explicit `jobWidgets.model` setting still wins). Each running background task also offers its subagent's finished tool calls to its widget and settles the widget when the task ends. When the subagent starts a command in the background (a render, a training run, a benchmark), that command becomes what the widget watches, so a widget appears for it with no setup; a task that only reads and edits files gets no widget and costs no extra model calls. On a senpi without job widgets nothing changes. (part of [code-yeongyu/senpi#4677](https://github.com/code-yeongyu/senpi/issues/4677)) ([#11919](https://github.com/code-yeongyu/oh-my-openagent/pull/11919))

Desktop clients can now drive memory sync setup and device approval over the engine's RPC connection. Each request is tied to the connection that started it, so another window or client cannot see, confirm or take over a setup it did not start, and a closed connection cancels its pending work. Sync settings come only from the signed-in account, never from the request. ([#11802](https://github.com/code-yeongyu/oh-my-openagent/pull/11802))

A memory change made during a sync that was already running now syncs right after that sync, without waiting for the next trigger. A device's own pushed change, echoed back by the live update stream, no longer starts an extra sync. ([#11754](https://github.com/code-yeongyu/oh-my-openagent/pull/11754))

**A memory sync failure you are already shown keeps its original "since" time through a brief offline period.** The failure's history used to reset while the device was briefly offline, so the notice restarted its age instead of reporting how long the sync had really been blocked. ([#11748](https://github.com/code-yeongyu/oh-my-openagent/pull/11748), fixes [#11053](https://github.com/code-yeongyu/oh-my-openagent/issues/11053))

**A memory sync failure that began while only a background session was open is now announced when you return to a session.** The failure used to be marked as announced without any notice being shown, so its reason and recovery action stayed silent until the next engine transition; binding a session now reads the current sync status and shows the warning once. ([#11739](https://github.com/code-yeongyu/oh-my-openagent/pull/11739), fixes [#11059](https://github.com/code-yeongyu/oh-my-openagent/issues/11059))

**OpenCode agents use the same model-specific prompt bodies as OmO Native.** The plugin builds each agent's model core with senpi's shared prompt builders, translates host tool names, and appends each agent's role explicitly, so every model in Native's catalog, Kimi K3.1 included, gets Native's prompt under OpenCode. Switching models also switches the prompt body without losing task mode or Hephaestus's model restriction. Session tool permissions are read once per session and then follow its update and delete events, and the OmO Native recommendation toast appears only in interactive launches and records each show. The prompt sent to the model lists each tool by a one-line snippet and carries no internal frame data. ([#9856](https://github.com/code-yeongyu/oh-my-openagent/pull/9856), fixes [#9851](https://github.com/code-yeongyu/oh-my-openagent/issues/9851))

## 2026-10-28 - Job widget author on the quick category and task widget sources

The task component reads senpi's job-widget exports off the loaded `@code-yeongyu/senpi` module (`job-widget-host.ts`, feature-detected: `setJobWidgetAuthorResolver`, `registerJobWidgetSource` + `TextTap`) and wires nothing on a senpi without them. `job-widget-author.ts` installs one process-wide author route that resolves `quick` through `resolveCategory` against the asking session's model registry, using the omo.json of the session whose cwd matches; an unknown cwd or an unresolvable `quick` answers `undefined`, so senpi falls back to the session model. Each registering session holds the route until its `session_shutdown`; the last release withdraws it. `job-widget-sources.ts` registers a `task` job for each running background task (`notify_on_terminal`) of the current session: id = task id, brief `task` = the spawn prompt (capped at 4 KiB) and `intent` = the description, one `tools` TextTap fed `\n» <tool> <first argument>\n<result text>\n` per finished child tool call (the last 64 KiB of each result), `notify()` per call, `settle()` on a terminal status, and `dispose()` on record removal, a session change, a revived run, or `session_shutdown`. A child `bash` call with `run_in_background: true` sets the job's `watch` hint through `update()` to `background command: <command>` (secret shapes redacted with omo's mirror of senpi's `sensitive-output` patterns plus flag, `sk-`, AKIA and JWT shapes, then cut to 300 characters); the newest background command wins and a finished one leaves the hint in place. Without one, senpi's request policy authors no task widget.

## 2026-10-29 - Recover corrupt account credentials (#11832)

Unscoped forget clears the stored credential under the session lock without a read. Scoped forget compares the current device under that lock and reports unreadable ownership as a JSON refusal. Only a well-formed target argument can select scoped deletion; malformed flags are rejected before store access. Explicit adopt replacement tolerates invalid data but not OS storage failures.

## 2026-10-29 - Confirm a host-session child's end before recording a cancel (#11783)

A cancel of a daemon-hosted child this process holds no handle for is written durably, then cancelled only after `endHostSessionChild` confirms the end: a close the host answered, or the three-part proof that the generation the record names is gone (serving listing without the path, no handover-parked entry, a second listing). The pending-cancel finish and the TTL sweep no longer read "not listed on the recorded socket" as ended. A retry driver re-drives an unconfirmed cancel on the deferred backoff with explicit exits, all entrants share one in-flight pass per task, and a handle's end counts only when its port's close was answered (`HostSessionPort.close(): Promise<boolean>`).
