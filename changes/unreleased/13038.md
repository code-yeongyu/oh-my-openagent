**`omo remote send` now goes through the same delivery pipeline as every other send, and `--steer` reads the session once.** A person's message to a session on another device enters `createDeliveryPipeline` with the relay address book's reference for the `<device>/<session>` address, so the CLI no longer builds its own transport call; the relay transport reads the running turn once and steers it, where the CLI used to read it a second time first. A `--steer` to a session that is running nothing still sends nothing. The unused second prompt implementation (`promptRemote`) and its argument check are removed. Which sender kinds each device admits is unchanged.
