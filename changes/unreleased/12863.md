**An agent that messages a session on another device now gets the answer back without asking for it.** When the receiving session finishes the run that read the message, its answer is delivered into the sender's session as a message from another agent, and the sender picks it up the way it picks up a message from a session on the same device. No monitor is needed. The receiving device delivers the answer only to engines that can admit it as an agent message; an older engine is reported in the log by name instead of being sent a plain prompt. ([#12863](https://github.com/code-yeongyu/oh-my-openagent/pull/12863), part of [#12852](https://github.com/code-yeongyu/oh-my-openagent/issues/12852))

## 2026-11-08 - A cross-device peer send is answered back into the sender's session (#12863, part of #12852)

`thread/remote/remote-ops.ts` `promptRemote` stamps a peer send with a reply route as senpi's `clientMessageId` (`remote/reply-route.ts` `replyRouteToken`: `omo-peer.v1:` + base64url JSON of the sending device, session, delivery id, root and hop; refused `invalid_arguments` before sending when it would pass 256 characters). `remote/lazy-ops.ts` `wireReplyRoutes` (registered by `component.ts`) runs `createReplyRouter` over the session's own `message_start` / `message_end` / `tool_execution_start` / `agent_settled` / `session_shutdown` events. A run that consumed a routed input sends its last assistant text back at `agent_settled` through `remote-ops.ts` `admitReplyRemote`: senpi#6233 `admit_external_message` to the located sender session, with `deliveryId` `reply-<delivery>`, `sender: { kind: "agent" }` only, `deliverAs: "followUp"`, `chainCount` = hop + 1, and the #12858 peer text with the answer capped at `THREAD_MESSAGE_MAX_BYTES`. An engine that refuses the record (`unknown_command` and kin) is logged as `remote_reply_unavailable`, and no prompt is sent instead. Each delivery is answered once per session (a bounded routed list), a reply carries no route, and a run that already answered the sender with `thread_send` is not answered again.
