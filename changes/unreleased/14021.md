### Fixed

- `omo account show` reports `refreshState: "expired"` when a stored `uncertain` refresh can no longer be recovered: there is no refresh attempt, the attempt is exhausted, or the recovery clock rejects it (deadline passed, reboot, or no clock). A protocol-2 attempt that is still eligible on this boot stays `uncertain`. `signedIn` and the exit code are unchanged. ([#14021](https://github.com/code-yeongyu/oh-my-openagent/pull/14021))
- `omo logout` and `omo account forget` can delete a helper-owned keychain item on an unlocked Mac even when the item's access list names an older helper path. The helper is pinned at a path derived from its bytes instead of a new random name on every launch. An access-list refusal no longer says the keychain is locked. ([#14021](https://github.com/code-yeongyu/oh-my-openagent/pull/14021))

## 2026-11-17 - account show names an unrecoverable refresh, and forget deletes it (#14021)

`account-show.ts` `reportedRefreshState`: `uncertain` with no `refreshAttempt`, an attempt whose `state` is `exhausted`, or one `eligibleAttempt` rejects is reported as `expired`. An eligible attempt stays `uncertain`. `docs/reference/cli.md` documents the value. `keychain-helper` `verb_remove` deletes a marked item without a successful decrypt, then `/usr/bin/security delete-generic-password` if the ACL still refuses this binary. `pin.ts` keeps the verified helper at a content-hash path and does not delete it on exit.

## 2026-11-17 - keychain ACL denial is not a locked keychain (#14021)

`keychain-helper/pin.ts` pins the helper from a hash of its bytes under the user temp dir. `darwin-read.ts` / `darwin-backend.ts` map helper error `acl` to a credential-store error that says the keychain is unlocked and the program is not on the item's access list. The legacy pre-request `uncertain` write in `session.ts` still has no `refreshAttempt`: that shape is terminal, and account show reports it as `expired`.
