**The desktop can ask OmO which model each category and agent runs.** A new read-only extension request, `omo.modelRouting.resolve`, answers the model every category (under its canonical name) and every task agent would spawn on, using the same resolvers a `task` call uses against the session's project config, model registry and sign-ins, and says whether that model came from your omo.json or from OmO's defaults. ([#11357](https://github.com/code-yeongyu/oh-my-openagent/pull/11357))

## 2026-10-26 - omo.modelRouting.resolve (#11357)

`components/task/model-routing-rpc.ts` registers `omo.modelRouting.resolve` (no request data). It loads the session cwd's config with the task engine's own loader and answers `{ schemaVersion: 1, rows }` from `model-routing-rows.ts`: one row per builtin and configured category, then per task agent, each from `resolveCategory` / `resolveAgent` as the planner calls them, with `effective` (`provider/model` or null), `source` (`override` / `provider-fallback` / `unresolved`) and the thinking level as `variant`. A missing cwd, an unreadable config layer and a session without a model registry answer typed errors (`cwd_unavailable`, `config_invalid`, `registry_unavailable`). The desktop consumer is sisyphuslabs/omo-desktop-app#4507.

## 2026-10-26 - resolvers report who chose the model (#11357)

`resolveCategory` now sets `modelSelection.source` and `resolveAgent` sets `modelSource` (`"user" | "builtin"`): `user` when the selected model came from omo.json (`model`, `models`, `fallback_models`, an agent's own model or a user category it runs through, or a call-site pin), `builtin` for a builtin default, chain rung or system default. Selection itself is unchanged.
