**`/extended-context` toggles ChatGPT subscription models between the shipped windows and the window the subscription reports.** The backend publishes two numbers per model: `context_window`, which it budgets by default and senpi ships, and `max_context_window`, the largest window the model accepts. Running the command once reads that catalog with the OAuth credential the session already holds, resolves each model to its owning slug (the catalog's own `-fast`/`-ultrafast` variant suffixes only, so an unrelated sibling is never given its parent's window), and writes `providers["chatgpt-subscription"].modelOverrides[id].contextWindow` in `models.json`. Running it again removes the keys it wrote and nothing else: the command keeps a record of the values it set, so a hand-set override on another model survives a restore.

The value is the prompt budget, `max_context_window - maxTokens`, not the raw maximum: the Responses API rejects a prompt above the window minus its output reserve, which is the same subtraction senpi's `applyOpenAiInputCap` already applies to generated catalogs. Windows only ever rise, because senpi's own tier budgets (`gpt-6-astra` at 600,000, `gpt-6-luna` at 922,000) sit above what the endpoint advertises for those slugs. Requests identify the client honestly: `client_version` is the running engine's `hostVersion` and the User-Agent is `omo/<hostVersion>`, so the command only uses the catalog that identity is served. When the engine reports no version, the command refuses rather than inventing one.

`models.json` is read before anything is written: a file that exists but does not parse is reported and left untouched, and writes go through a temporary file and a rename. `on` and `off` are explicit; a bare invocation toggles.
