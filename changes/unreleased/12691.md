**`/extended-context` toggles ChatGPT subscription models between the shipped windows and the window the subscription reports.** The backend publishes two numbers per model: `context_window`, which it budgets by default and senpi ships, and `max_context_window`, the largest window the model accepts. Running the command once reads that catalog with the OAuth credential the session already holds, resolves each model to its owning slug (longest match, so `gpt-6.1-sol-ultrafast` belongs to itself and `gpt-6.1-sol-fast` to `gpt-6.1-sol`), and writes `providers["chatgpt-subscription"].modelOverrides[id].contextWindow` in `models.json`. Running it again removes exactly those keys.

The value is the prompt budget, `max_context_window - maxTokens`, not the raw maximum: the Responses API rejects a prompt above the window minus its output reserve, which is the same subtraction senpi's `applyOpenAiInputCap` already applies to generated catalogs. The command only ever raises a window, because senpi's own tier budgets (`gpt-6-astra` at 600,000, `gpt-6-luna` at 922,000) sit above what the endpoint advertises and must survive a run. The endpoint listing is gated on `client_version` — below 0.160.0 it omits every `gpt-6.1` model — so the version is pinned rather than read.
