### Fixed

- Memory sync says why the service refused it (#12123). Settings -> Memory -> Sync across devices showed "The service refused this sync request." for every refusal. A refusal whose code is on the service contract's closed list (`not_available`, `entitlement_required`, `access_not_open`, `device_revoked`, `reauth_required`, `account_deleted`, `client_update_required` and its aliases `client_upgrade_required` and `update_required`) now carries that code on the `refused` problem with OmO's own wording, so the app can tell "not available yet" from an account or device problem. Any other code keeps the generic refusal with no code, and the service's message text never reaches the app. ([#12155](https://github.com/code-yeongyu/oh-my-openagent/pull/12155)) ([#14144](https://github.com/code-yeongyu/oh-my-openagent/pull/14144))
- Memory sync keeps the service's refusal code on an approval that fails after the pending device was answered (#13659). Approving a device that the service then refused (`device_revoked`, `reauth_required`, and the rest of the list from #12155) ended with the generic "The sync service could not complete this operation."; the approval's outcome now carries the same `code` and OmO wording as the other sync verbs. Any other error keeps the generic outcome. ([#13675](https://github.com/code-yeongyu/oh-my-openagent/pull/13675)) ([#14144](https://github.com/code-yeongyu/oh-my-openagent/pull/14144))
- A crash after a delete has landed for an NFD-named file, but before staging, no longer leaves a stale tree: the render record now carries the on-disk spelling it landed at, so the resumed cycle stages the delete at the spelling HEAD tracks. ([#12742](https://github.com/code-yeongyu/oh-my-openagent/pull/12742), refs [#12158](https://github.com/code-yeongyu/oh-my-openagent/issues/12158)) ([#14144](https://github.com/code-yeongyu/oh-my-openagent/pull/14144))
- Memory sync: if the outbox's `pending/` folder cannot be read (for example a permission error), the push now reports the error instead of silently skipping cleanup, which let old segment files pile up again. While pushes are frozen by the service, the freeze stays the status shown, whether or not anything is waiting to be sent, and the cleanup error goes to the memory log. ([#12828](https://github.com/code-yeongyu/oh-my-openagent/pull/12828), part of [#12506](https://github.com/code-yeongyu/oh-my-openagent/issues/12506)) ([#14144](https://github.com/code-yeongyu/oh-my-openagent/pull/14144))
- Memory sync: a working-tree file replaced by a FIFO no longer blocks a sync cycle. Landing and capture judge the file on the opened descriptor and refuse a FIFO, socket, device or directory as `non-regular-file`. ([#12850](https://github.com/code-yeongyu/oh-my-openagent/pull/12850), fixes [#12575](https://github.com/code-yeongyu/oh-my-openagent/issues/12575)) ([#14144](https://github.com/code-yeongyu/oh-my-openagent/pull/14144))
- Memory sync no longer rewrites its engine state file on every cycle while a file is held back for being too large, and no longer rewrites an unchanged event cursor: an idle cycle with a held file now writes the state once, for its sync time, instead of three times. The held status still names the file, when the hold began and how many cycles it has lasted (#12393). ([#13657](https://github.com/code-yeongyu/oh-my-openagent/pull/13657)) ([#14144](https://github.com/code-yeongyu/oh-my-openagent/pull/14144))
- Memory sync tells the desktop why it is paused or unavailable (#11056). The `sync` field of the `omo.memory.status` snapshot now carries, for `paused`, the refused entry as `refused: { seq, code }` (the verifier's closed refusal code), and for `unavailable`, `unavailable: { code, reason, variable? }` with a closed code (`engine_unavailable` or `config_invalid`) and OmO's own wording. Both fields are optional and add no new state, so an older desktop reads the status as before; the runner's error text stays in its log. ([#13658](https://github.com/code-yeongyu/oh-my-openagent/pull/13658)) ([#14144](https://github.com/code-yeongyu/oh-my-openagent/pull/14144))
- A memory sync failure of the same kind but with a different action, such as a stranded git lock that moved to another path, now starts a new failure with its own start time and an attempt count of 1, instead of inheriting the previous one's. The sync status also hands each caller its own copy of the failure, so a caller that changes it no longer changes what the engine reports next (#11759). ([#13665](https://github.com/code-yeongyu/oh-my-openagent/pull/13665)) ([#14144](https://github.com/code-yeongyu/oh-my-openagent/pull/14144))

### Changed

- Memory sync: tests now pin the 2,000-line bound where a body edit switches from whole-line merging to the character merge, and the in-code note states the line diff's real memory ceiling (about 32 MB). No behavior change. ([#12820](https://github.com/code-yeongyu/oh-my-openagent/pull/12820), fixes [#12526](https://github.com/code-yeongyu/oh-my-openagent/issues/12526)) ([#14144](https://github.com/code-yeongyu/oh-my-openagent/pull/14144))
- Memory sync: if you go back from 5.1.64 or later to an older release, the older release cannot push while any edit that was waiting to be sent when 5.1.64 or later last ran is still unsent. It still records new edits, but every push attempt fails until you upgrade again; the waiting edits are kept and go out then. Once those edits have been sent, the older release pushes normally (#12506). ([#13661](https://github.com/code-yeongyu/oh-my-openagent/pull/13661)) ([#14144](https://github.com/code-yeongyu/oh-my-openagent/pull/14144))
