**Two new shipped skills: `security` and `repo-map`.** `security` makes a threat model the first step of any change that crosses a trust boundary and vets the agent's own supply chain: MCP servers pinned to a version with no `npx -y` and no inline secret, skills read for exfiltration URLs and instruction overrides before install and pinned to a commit with a recorded content hash, AI-suggested dependencies checked against the registry before they are added. `repo-map` prints a ranked map of an unfamiliar codebase within a token budget: `bun "$SKILL_DIR/scripts/repo-map.ts" .` tags definitions per file, weights cross-file references, runs PageRank and lists the definitions other files pull from most, with `--focus` and `--mention` to steer the ranking. ([#12728](https://github.com/code-yeongyu/oh-my-openagent/pull/12728), fixes [#12721](https://github.com/code-yeongyu/oh-my-openagent/issues/12721))

**`git-master` cleans up branches by PR state and names what a release claim owes.** The new `GC` mode runs `scripts/branch-gc.ts`, whose merge truth is the forge's pull-request state, so squash- and rebase-merged branches that `git branch --merged` never sees are found; protected lines, checked-out, locked and dirty worktrees, open PR heads and bases, and `wip/`, `backup/`, `archive/` branches are never deleted, a `for-each-ref` snapshot is written before the first deletion, and the dry run is the default. The `RELEASE` mode lists the five facts a release claim needs: artifact digest, builder identity, target, smoke evidence, rollback evidence. ([#12728](https://github.com/code-yeongyu/oh-my-openagent/pull/12728))

**`review-work` checks its own QA evidence and accounts for every changed file.** `scripts/validate-evidence.ts` validates the QA matrix as `qa-matrix.json`: a PASS needs a non-empty artifact inside the evidence directory, a web or GUI capture must be a whole PNG, an NA carries its reason, and the matrix is bound to the checkout by commit SHA and dirty-tree hash so a fix landed after a capture stales it. The gate reviewer now returns a coverage ledger (reviewed, skipped, out-of-scope per changed file; an unaccounted file makes the verdict INCOMPLETE), tags each finding verified or unverified, and re-reviews an interdiff anchored to both heads. ([#12728](https://github.com/code-yeongyu/oh-my-openagent/pull/12728))

**`frontend` understands Korean design briefs; `ulw-research` has a rung for plain lookups.** `references/korean-design-vocabulary.md` maps words such as 깔끔하게, 모던하게 and 고급스럽게 to spacing, radius, weight and palette tokens, asks the one question that separates each word's two readings, and carries Hangul typography defaults plus KRDS and KWCAG 2.2 notes for Korean public-sector and fintech work. `references/light-search.md` is the lookup discipline for a question that needs a fact from outside the repository: classify web, official docs or this repository, rewrite the ask into one to three keyword queries, open the source behind the snippet, and never escalate a lookup into a research run on its own. ([#12728](https://github.com/code-yeongyu/oh-my-openagent/pull/12728))
