### Fixed

- A thread made by `thread_create` with a permission preset that asks (for example `read-only`) no longer hangs its turn when it calls a tool the preset would ask about. Nobody answers prompts in such a thread, so `thread_create` now opens every session with the engine's refusal label, here and on another device: the call returns a refusal the model can read and the turn completes. Needs a senpi engine with code-yeongyu/senpi#7270; an older engine ignores the label. ([#14674](https://github.com/code-yeongyu/oh-my-openagent/pull/14674))
- Peer thread tools now answer `cancelled` when the host cancels a call. Cancelling during endpoint discovery, local authentication or attachment, or alias-token lookup sends no mutation and leaves the idempotency key reusable. The local host releases any attachment it acquired. If a remote open was already sent, the caller stops waiting but the run keeps its connection and records the result. A retry with the same key reports the open in progress or replays that result; it never opens a second thread. ([#14634](https://github.com/code-yeongyu/oh-my-openagent/pull/14634), fixes [#13426](https://github.com/code-yeongyu/oh-my-openagent/issues/13426))
- A local `thread_create` whose thread host never registers the new session with this omo's gateway (a host still running an older omo than the caller) no longer answers `ok` with its first prompt stuck queued: it takes the prompt back, ends the session, removes the session file and the worktree and branch it made, claims no alias (an alias is claimed only once the create stands), and refuses `host_unavailable` with `details.reason: "control_endpoint_unregistered"`. ([#14648](https://github.com/code-yeongyu/oh-my-openagent/issues/14648))
- `thread_close` on a thread nothing live holds, with messages this device's gateway holds for its wake, names them and drops nothing on a plain close, and drops and lists them in `dropped_deliveries` with `force` or `graceful`. ([#14648](https://github.com/code-yeongyu/oh-my-openagent/issues/14648))
- `thread_read` of a thread with no live host scans at most 1 MiB from the end of its session file, with the window fixed before opening it. If a partial tail contains no displayable message, even when it ends in session bookkeeping, pass `error.details.next_cursor` as `cursor` to scan forward in bounded pages past oversized records. The tool, SDK, and `omo thread read` reject malformed cursors before looking up the thread. Status reads only file metadata. Tail cursors preserve the requested window and skipped-line counts, and reject file replacement or changes to the window content and parent links. ([#14452](https://github.com/code-yeongyu/oh-my-openagent/pull/14452))
- `thread_create` on another device whose open was lost on the way (`idempotency_uncertain`, `request_gone`) no longer stays uncertain on every retry. The answer now names the thread the call's `idempotency_key` derives (`details.thread`, `details.device`) and, for a call that passed a key, says a retry under that key is safe (`details.retry_same_key_safe`). The retry adopts a session an earlier open did make (naming it and sending its prompt once), and when that device's engine creates sessions under the asked id and answers that it holds nothing under it, the retry opens the thread under the same id; the engine refuses a second session under one id, so a late-landing first open is adopted, never doubled. A retry whose first run left a worktree on that device still answers uncertain. (fixes [#15002](https://github.com/code-yeongyu/oh-my-openagent/issues/15002))
- `thread_send` to a live thread on a busy device no longer answers `not_resumable` ("not running") when that device's host merely failed to route it: when the device says an engine runs the thread but routes no key to it, or does not answer whether it runs it, the send answers `host_unavailable` (`reason: "route_unlisted"`) with a retry, since nothing was sent and nothing shows the thread stopped. A send the device refused before any engine took it (`route_unlisted`, `host_not_answering`) no longer holds its `idempotency_key`: the advised retry under the same key is a fresh send, with or without its optional fields, instead of a replay of the refusal or `idempotency_conflict`. (fixes [#15004](https://github.com/code-yeongyu/oh-my-openagent/issues/15004))
- Thread tools classify each lost-answer reason one way. A reason that says an answer from another device was lost after the request left this device (`request_gone`, `delivered_unconfirmed`, `reply_lost` and the rest of the device service's uncertain reasons) never says "this call changed nothing there" again: a `thread_send` whose state read before sending lost its answer is `idempotency_uncertain` with `details.sent: false` (read the thread before sending again), as a lost answer to the message itself is, and a `thread_read` whose answer was lost is `host_unavailable` with `details.effect: "unknown"`. `host_unavailable` with "changed nothing" (`details.effect: "none"`) is kept for refusals given before the request reached the device. (fixes [#15093](https://github.com/code-yeongyu/oh-my-openagent/issues/15093))
