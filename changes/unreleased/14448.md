### Added

- A session that ends 10 runs in a row with an error now raises an operator alert. Configure the targets under `operator_alerts.error_streak` in your user config (`~/.omo/omo.jsonc`; a project's `.omo/omo.json` cannot set them): `threads` (thread addresses that receive it through `thread_send`, sent as the failing session) and `webhook_url_env` (the name of an environment variable holding a JSON webhook URL; the body has a one-line `text`, so a Slack incoming webhook accepts it as is). The alert carries only metadata: the session, the device, how many runs failed in each error class (`rate_limit`, `auth`, `overloaded`, `network`, `unknown`), the first and last failure time, and the provider and model. It never carries prompt text, tool output or message content. While the streak lasts, a "still failing" alert repeats at most every `realert_minutes` (default 60). The first normal stop sends one "recovered" notice. Aborted runs never alert. Sending never holds the session. ([#14448](https://github.com/code-yeongyu/oh-my-openagent/pull/14448), fixes [#14430](https://github.com/code-yeongyu/oh-my-openagent/issues/14430))
