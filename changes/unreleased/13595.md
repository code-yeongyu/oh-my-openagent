### Added

- `omo remote bootstrap` and `omo remote enable` install and start one fixed, always-on per-user unit beside the OmO device service that runs the omo session host: the systemd user unit `omo-session-host.service` on Linux (enabled, restarted after every exit) and the LaunchAgent `ai.omo.session-host` on macOS (run at load, kept alive). It runs `omo daemon run --pinned` for the registered agent dir, and the device service's `OMO_RELAYD_SERVICES` table names it (entry `"omo"`) as the only unit it may start for a cold wake. The table keeps its other entries, and the device service restarts only when the table changed. `omo remote disable` disables and removes both, and while remote sessions are off a bootstrap removes them instead of installing them (#13594).
- `omo daemon run --pinned` starts the operator host with no idle exit; a task host started from one of its sessions still idles out as usual (#13594).
