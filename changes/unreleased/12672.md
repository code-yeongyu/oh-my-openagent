Thread ops on another device spend fewer relay round trips: the session's attach is kept across ops, and the session's model catalog is held on it, so a model switch to an exact `provider/id` that catalog lists is one `set_model`. A set that may have run is still reported as `idempotency_uncertain`; a refused one re-reads the catalog and answers as a fresh catalog would. Status and transcript reads (`get_state`, `get_messages`) still go to the device every time, because the engine's in-memory state changes without a record on the attach.
