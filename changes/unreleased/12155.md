## 2026-11-02 - Memory sync refusals carry the service's code (fixes #12123)

`serviceProblem` (`components/memory/sync-rpc-operation.ts`) mapped every `AccountHttpError` 4xx to one generic refusal, so `not_available` and the account/device codes were indistinguishable. `sync-service-refusal.ts` now maps a code from the service contract's closed list (`not_available`, `entitlement_required`, `access_not_open`, `device_revoked`, `reauth_required`, `account_deleted`, `client_update_required` with its two aliases) to our own copy and sets `code` on the `refused` problem (`SyncServiceCode` in `sync-rpc-contract.ts`). Unknown codes keep the generic refusal with no code. Must not break: the service's message text never crosses the RPC boundary, and the problem kinds stay `refused`/`unavailable` so an older client still renders `reason`.
