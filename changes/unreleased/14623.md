### Fixed

- `thread_create` on another device no longer answers `idempotency_uncertain` (`reply_lost`) for a session that device did create. The create is opened under the id its `idempotency_key` derives; when the open's reply is lost (a busy device answering after the call's budget), the session that device lists under that id is answered as the created thread, on the spot or on a retry under the same key, and no second session is opened. An engine that ignores the id still answers uncertain. A retry of an uncertain create now runs the create again instead of replaying the uncertain answer. ([#14564](https://github.com/code-yeongyu/oh-my-openagent/pull/14564), fixes [#14560](https://github.com/code-yeongyu/oh-my-openagent/issues/14560))

- A session that received a message from a session in another workspace on the same device can now answer it with `thread_send` without `all_scope`, as the delivery tells it to; before, the reply was refused `scope_denied`. A reply by the name the message stated reaches the sender even after it renamed itself or when only its session file lists it. Only the sender of a message this run took in is reachable this way; every other session outside the workspace still needs `all_scope`. ([#14542](https://github.com/code-yeongyu/oh-my-openagent/pull/14542))

- `thread_list` rows for threads on another device show when the thread was created. They showed the time the holder last synced its listing, the same value as `updated_at`. ([#14479](https://github.com/code-yeongyu/oh-my-openagent/pull/14479))

- Reading a thread from its session file now returns the latest messages even when bookkeeping follows them. The window and byte budget count message payloads, as on a live read. Re-read without a cursor to restart a page begun on an older version.

- A short-lived SQLite client that opens, commits to and closes the live gateway store (`~/.omo/agent/gateway/gateway.sqlite`) no longer deletes its `-wal` and `-shm` files under running omo sessions, which left every thread tool failing with `disk I/O error` until restart and lost later writes. Opening a second store in one process no longer drops the process's SQLite locks. A store whose WAL files were removed or replaced anyway, or that hits an SQLite I/O error, now reopens its connection and retries the call once by itself. ([#14566](https://github.com/code-yeongyu/oh-my-openagent/pull/14566), fixes [#14562](https://github.com/code-yeongyu/oh-my-openagent/issues/14562))

- The thread SDK refuses an argument key an operation does not read (a misspelt `allScope`, say) as `invalid_arguments` naming it, instead of ignoring it (#14316).

- A local thread reopening after a daemon handoff now lists as `opening` instead of `idle`. Closing it before it is ready reports `session_opening`, not `not_live`. ([#14426](https://github.com/code-yeongyu/oh-my-openagent/pull/14426))

- A retained thread delivery can now report its outcome separately from its original admission. Same-key retries reconcile the receiving gateway's application or refusal, and `thread_read` with `delivery_id` queries an existing receipt without sending or waking a session. Unreachable or older peers report an unavailable outcome instead of guessing expiry. Refusal notices respect the original sender's current access. ([#14449](https://github.com/code-yeongyu/oh-my-openagent/pull/14449))

- `thread_send` and other commands to a session on another device no longer answer "unsupported, update omo and senpi" when that device refuses with `engine_capability_missing` and a cause that passes on its own. When the device answers `attach_required` (it lists the session on a route that takes no delegated connections, such as a terminal, and does not count an attach of this device to it), omo drops its attach, attaches again and sends the command once more. That lands an attach-less send. A re-attach can rejoin an attachment the device service still shares but the other device no longer counts; then, as for `daemon_unavailable`, the result is `host_unavailable` with the cause in `details.cause` and a retry hint, and nothing ran. Only an engine that will never take the command stays `unsupported`. ([#14359](https://github.com/code-yeongyu/oh-my-openagent/pull/14359))

- A retry of an uncertain `thread_create` on another device now answers the worktree the first run made there, names the first uncertain answer's cause (`first_cause`), ends an adopted session the device's route does not reach, and never replays a retry's failure as the final answer. ([#14623](https://github.com/code-yeongyu/oh-my-openagent/pull/14623), fixes [#14569](https://github.com/code-yeongyu/oh-my-openagent/issues/14569))

### Changed

- Listings of another device's sessions now ask its device service for listing rows 7 first and step down one version at a time to rows 2 when it refuses. A service at relayd 0.1.46 or later then sends each row's holder retry wait (`waiting`, rows 6) and engine version (`engine_version`, rows 7). An older service answers as before. ([#14511](https://github.com/code-yeongyu/oh-my-openagent/pull/14511))

- `thread_list` rows from another device show the holder's retry wait (`waiting_on`, running rows only) and `engine_version` once that device's listing carries them (rows 6 / rows 7). A cached row, and a row without the fields, show neither; nothing is inferred.

### Removed

- Thread bindings are gone (#14312). `omo thread` keeps `list`, `send <target> <text>`, `read` and `close`; `bind`, `unbind`, `rebind`, `bindings`, `report`, `answer`, `outbox`, `ack`, `send --binding` and the `--author-*` flags are unknown now. The thread SDK (`runtime/thread-sdk/sdk.js`) loses the same methods, and `send` takes exactly `{ thread, text, mode?, expected_turn_id?, all_scope?, idempotency_key?, collapse_key? }`. The agent tools `thread_report`, `thread_outbox`, `thread_outbox_ack` and `thread_answer` are gone, as are the store-extension helpers `bind`, `unbind`, `rebind`, `bindingsForSession`, `enqueue`, `outboxAck` and `outboxPending`. The gateway keeps the `bindings`, `outbox`, `outbox_cursors` and `completion_arms` tables, empty and unread, so an omo still running gateway schema 14 keeps working through the upgrade; an extension reads its old routes from `bindings` through the read-only `bindingFor`. Dropping the tables is deferred to #14859. A connector keeps its own chat-thread-to-session map and sends by session id.

### Added

- `thread_create { fork_from }` forks a thread, on this device or another, when the engine that holds the source advertises `open_session_fork` (senpi#7085). The answer is a new thread with the source's history. On an engine without it, `fork_from` is still refused `unsupported` (`fork_unsupported`) before anything opens. A source the engine does not hold answers `not_found` with `details.reason` `fork_source_not_local` or `fork_source_not_found`, and the next action names the device that holds it. ([#14403](https://github.com/code-yeongyu/oh-my-openagent/pull/14403), fixes [#13031](https://github.com/code-yeongyu/oh-my-openagent/issues/13031))
