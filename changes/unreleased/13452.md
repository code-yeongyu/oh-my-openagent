### Fixed

- Thread tools (`thread_list`, `thread_read`, `thread_send`, `thread_create`, ...) and `omo thread` no longer run `host status --all` on every call. They read the endpoint registry on disk instead, so a local `thread_list` that took about 9 s on a host with 50 endpoints answers in well under a second.
- Listing a thread endpoint that stopped answering reads its leftover session claims asynchronously, so an endpoint with many stale claims no longer blocks the engine's event loop while `thread_list` runs (fixes #13551, folded from #13573).
