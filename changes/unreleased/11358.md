**A category or agent model change in omo.json applies to the next delegated task without restarting the session, and a broken omo.json stops the spawn instead of switching models.** The task engine reads omo.json once at every spawn, so an edited category chain or agent reaches the next child even while other children run and `/reload` is held. When an existing omo.json layer cannot be parsed or read, or any field that decides which model a child runs on is invalid anywhere it can be written (the user layer and every project layer; in each, the base config, its `[native]`/`[senpi]` block, and every profile and its `[native]`/`[senpi]` block, active or not; in each, category and agent `model`, `models`, `fallback_models` and reasoning selectors, and `exclude_models`), that spawn fails with an error naming the file and the position (`line:column`, or the JSON path of the field). Invalid means a wrong type, `null`, an empty value, or a model id that is neither `provider/model` (the legacy `model (high)` and `model high` suffixes still count) nor a catalog name the location can resolve. It never routes on the rest of the file, another layer, the built-in defaults or the session's startup config. A profile that is requested but does not exist keeps today's behaviour (the base config); an invalid field that does not route a Senpi child (for example `task.default_concurrency` or a `[codex]` block) is dropped with a warning, as before. Still read once at session start: the `task` settings (state dir, runners, residency), the plan-gate and DAG spawn policy, and the agent list in the task tool's description.
