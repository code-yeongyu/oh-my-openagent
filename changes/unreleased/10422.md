### Fixed

- A message sent to a background task right after a slow start reaches the running task at once. When a task's start took longer than a quarter second (common on Windows), a `task_send` sent the moment it came up could be reported as `queued` and reach the task only later, behind an empty queue. It now steers the running task directly; messages queued while a task is really still starting are delivered once, in order, as before. ([#10399](https://github.com/code-yeongyu/oh-my-openagent/issues/10399), [#10422](https://github.com/code-yeongyu/oh-my-openagent/pull/10422))

## 2026-11-22 - A message sent right after a slow launch steers the live child instead of queueing behind nothing (#10399)

- `steering/pending-steering.ts`: `notifyStarted` registers no drain when the persisted queue has nothing to deliver. Every launch calls it; an empty drain still read as "draining" for a few ticks, and a `task_send` landing in that window was queued behind nothing by the #9861 ordering guard and reached the host only on a later background drain. A message enqueued afterwards still starts its own drain from `enqueuePending`.
- `steering/pending-steering-empty-drain.test.ts`: after `notifyStarted` on an empty queue the task is not draining (fails without the fix). The slow-launch rows in `runners/rpc-host-input-identity.test.ts` use the existing `holdReply` fixture.
