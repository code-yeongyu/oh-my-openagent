## 2026-11-27 - DAG cancel stops every owned child; a superseded attempt is never adopted (#11381)

Run cancel stops each live child the run owns, scanned by run (nodes an amendment removed included), not only the ones attached to the current scheduler. An attached child keeps its deferred in-process teardown, any other is cancelled outright, and stop completion is re-read from each record: a child still live (`cancel_pending`, or a noop on a live record) fails the cancel with `DagRunChildrenLiveError` after the run is durably cancelled, and cancelling a settled run stops its still-live children again. An owned start refuses to start while any live claim of the node has another fingerprint (`owner_conflict`); one classifier (`owned-attempt.ts`) shared by admission, the re-entry sweep and recovery decides the claim: an earlier attempt's child is stopped and its node fails with the retryable `stale_attempt_alive`, a current one (a legacy owner included, identified by the run's definition fingerprints) is adopted, and a newer one is left running. Recovery validates the attempt before it attaches, folds or starts. The record store keeps `owner.execAttempt`. Port of #11385.
