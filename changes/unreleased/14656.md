## 2026-11-22 - TypeScript 7 projects get post-edit diagnostics from their own tsc (#14656)

`findServerForExtension` in `@oh-my-opencode/lsp-core` swaps the builtin `typescript` server for `node_modules/.bin/tsc --lsp --stdio` when the `typescript` package beside it has no `lib/tsserver.js` (TypeScript 7 dropped it, so typescript-language-server cannot start there). The lookup takes an optional target path: the LSP tools pass the file being served, so the compiler is taken from the edited file's project (walking up from the file to the `.git` boundary) rather than the session cwd. The target and the session cwd are compared by real path, so a target whose real location is outside the real session cwd (for example through a symlinked directory) keeps the cwd, as does `lsp_status`, while a symlinked session root still works. The walk accepts a `tsc` only from a real `node_modules/.bin` directory: npm, yarn, bun and pnpm link entries inside `node_modules` but never `node_modules` or `.bin` themselves, so a linked one fails closed to the cwd fallback. Directory diagnostics resolve each scanned file with the same lookup, cache it per directory for the scan, group files by resident client key and acquire one client per group; a group with no server reports that for its own files, and the file cap and concurrency stay per request. `LspManager` keys resident clients by workspace root, server id and resolved command, so packages of one repository that resolve to different TypeScript servers never share a client, and the same command under one root still shares one. Only a repo-local `tsc` counts (`resolveServerBinary(..., { localOnly: true })`). The config merge records whether the `typescript` command is the inherited builtin default; a configured command, even one equal to the default, is never replaced, and project overrides and disabled settings keep their precedence. The tsserver-specific builtin initialization is not sent to `tsc`; initialization a config file supplied is. `lsp_status` reports `typescript` installed in such a project. `omo.js` is regenerated. Fixes #14642.
