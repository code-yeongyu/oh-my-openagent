## 2026-11-12 - Thread recovery hints name the eval cell (#13240)

Thread tools are eval-only since #12903; the recovery hints across `thread/` (`reader.ts`, `addressing.ts`, `tools.ts`, `remote/*`, `control/*`, `gateway/*`, `tools/*`) and the two tool descriptions in `metadata.ts` that name a sibling tool used the `tool.thread_*` eval forms only partly, and two hints wrote a call with an argument the tool does not take (`tool.thread_send({ to, message })`, `tool.thread_interrupt({ thread_id })`; both take `thread`). They all name the eval form now, and a hint writes a call only when it gives the arguments. `thread/eval-cell-hints.test.ts` reads the string literals of every thread source file and fails on a thread tool named without `tool.`, on an eval form of a tool that does not exist, and on a call argument the tool's schema does not have; the parameter schemas under `contracts/` are left as they are, because the `omo thread` CLI shares them and they say which tool produced a value. The fused-equivalence observer keeps the first running snapshot per eval cell reduced to its status line and cell statuses and drops later wall-clock ticks; the linux-x64 and darwin-arm64 E22 goldens are re-recorded with `--repeat 2`. QA scratch sandboxes chmod their agent dir to 0700 for senpi's key-dir check under umask 002; the layout lives in `scratch-layout.mjs`, so its test loads without the engine version `gateway.mjs` requires. Follow-up to #12915; tracked by #13239.
