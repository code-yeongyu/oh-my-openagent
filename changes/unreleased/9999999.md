### Changed
- `omo remote send` in wait mode handed its message to the session only after the answer-follow's attach completed, putting the whole attach handshake on the pre-delivery path (measured 7-9 s CLI-side while the relay hop itself is 0.2-0.3 s). The message is now delivered first and the follow attaches in parallel; the follow marks the send's reply and recovers the turn's own records from whatever the attach replays, so a slower attach delays neither the hand-off nor any answer text. ([#9999999](https://github.com/code-yeongyu/oh-my-openagent/pull/9999999))
