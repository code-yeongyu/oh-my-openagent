### Changed
- Thread gateway: waking a session that is not running needs no setting (#13037). A `thread_send` from this machine to a session here that is not running now starts it by default, and the answer is `queued` with `waiting_on: { kind: "wake" }`. `session_wake.same_device` stays in the configuration schema only as an explicit opt-out (`false`). Removing the key would make the strict schema refuse every configuration that already sets it.
- Thread gateway: a delivery from another device is no longer gated on the device service's wake switch being told on. While this engine's delivery consumer is served, the carrier opens the session. The consumer itself still serves nothing until the engine minimum (senpi#6449) and the device-service release that carries the wake mark are named.
