## 2026-11-16 - Sign-out names an access-control refusal instead of a locked or disabled keychain (#13762)

`keychain-helper/darwin-store.ts` `clear()`: when the helper answers `remove` with `not-owned` and this process's own delete (`ownDelete`) is refused too, it throws `HelperItemNotOwned`. `keystore.ts` maps that to the new `KeychainItemNotOwnedError` (a `CredentialStoreError`), whose message names the `omo-cli` item and the Keychain Access step; when the refusal is really a locked keychain (`-25308`) it stays `KeychainLockedError`. Before this, the refusal (`-25244`, a delete by a non-owner) fell through to the generic "Unlock or enable the OS credential store" text. `session-relogin.test.ts` adds the case on the fake keychain (RED at dev 587f207165 with only the mapping removed: the generic `CredentialStoreError` with that exact text). Part of #13757; why a later `omo` run is not the item's owner (the per-run helper path) is tracked there and needs a security design first.

Must not break: a locked keychain still reports `KeychainLockedError`; an item the helper owns is still removed silently; every retired `.old` slot is still attempted on sign-out.
