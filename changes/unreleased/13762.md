**An `omo remote disable` typed while the background enable after `omo login` finishes is never erased by that enable, and remote ends off even when the disable lands at the moment that enable switches remote on.** A compiled omo started inside an npm-installed omo session now starts that background enable under bun or node instead of trying to run the npm launcher script as a compiled program, and the remote-sessions reference now describes both things `omo login` can print: remote on at once, or turning on in the background.
