### Fixed

- A background child no longer stays shown as running forever after a follow-up it refused: the finished run is restored when a warm revival prompt is refused, while a stop accepted meanwhile still ends it cancelled and messages queued meanwhile are kept. A reused process id is no longer mistaken for the child's live owner, a child its own run paused reads as paused instead of held by another host, a paused orphan is parked for its run instead of being disposed or marked lost by any startup sweep, and a session that stops while a child's owner is being checked no longer has that child revived (#12077, #12080).

## 2026-11-27 - Stranded children: refused warm revival, reused owner pid, paused orphans (#12077, #12080)

A refused warm revival restores the finished record instead of leaving it `running` with no outcome tracker; it keeps the current steering queue, and neither it nor the cold rollback takes back a run whose stop was accepted (`cancel_requested`). Host claims carry a start-identity stamp so a reused pid is told from the live claimant; records written before this keep the signal-0 check. A child paused by its own run defers as `run_paused`, and both the scoped and the legacy reconcile sweep park a paused orphan for its run. The deferred scoped retry, the legacy owner retry and live-parent recovery recheck for a stopped session after observing the owner process. Port of #12078 and #12086.
