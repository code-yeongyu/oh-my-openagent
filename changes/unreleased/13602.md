### Changed

- `omo remote enable` now sets the device up in one command after `omo login`. It installs the OmO device service when none runs, registers this omo's agent dir with it, turns remote sessions on, and installs and starts the always-on session host unit. If you signed in before the device service was installed, it also links that sign-in to the service, so `omo login` then `omo remote enable` leaves the device connected. Running it again changes nothing that is already in place (#13594).
- `omo remote status` also shows this device's own units as the service manager reports them: the session host unit (running, enabled, pinned host), the device service's unit, whether the cold-wake entry is in place, and the agent dir omo registers. With `--json` these are a `local` object beside the status fields (#13594).
