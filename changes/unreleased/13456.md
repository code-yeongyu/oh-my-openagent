### Changed
- Thread gateway: waking a session that is not running needs no setting (#13037). A `thread_send` from this machine to a session here that is not running now starts it by default, and the answer is `queued` with `waiting_on: { kind: "wake" }`. `session_wake.same_device` stays in the configuration schema only as an explicit opt-out (`false`), read for the target session's own project. The wake still starts only on an engine at or above the wake engine minimum (senpi#6449), which is not cut yet.
- Thread gateway: when no operator host is running, a session that is not running still starts (#13037). Before it opens the session, the carrier asks the engine's own `host ensure --policy never`, from omo's daemon launch spec, on the socket `thread_create` uses. A running host is reused whatever its build; one is started only when nothing answers. The ensured host runs with `omo daemon`'s own host environment: the agent directory is named (`OMO_AGENT_DIR`) and the configured `task.host_idle_exit_ms` rides along (`SENPI_RPC_HOST_IDLE_EXIT_MS`) instead of the launch spec's default, and from a source tree the launch spec resolves to the plugin's tracked copy so the CLI is always handed a file that exists.
- Thread gateway: a delivery from another device is no longer gated on the device service's wake switch being told on. While this engine's delivery consumer is served (from its serving acknowledgement, before its startup pending sweep, so a remote row that sweep wakes is never told the gate is off), the carrier opens the session. The consumer itself still serves nothing until the engine minimum (senpi#6449) and the device-service release that carries the wake mark are named, and the consumer no longer reads the wake the service tells: the wake switch it tracked (`wakeAllowed`, the `delivery.wake` event) had no production reader left.
