**Plain `omo login` signs a computer in from the terminal while OmO accounts are closed.** A computer with no OmO desktop app — a server over SSH, a fresh Linux box — runs `omo login`, gets a device code to approve on another device, and stores the credential in the OS credential store; the attach-before-mint refusal (#13096) answers a computer that already has its device before anything is asked of the service. The success line names the signed-in account (`Signed in to OmO as <email>.`), and `omo whoami` names it too; a failed account read still says how to see it. `omo logout` and `omo whoami` run while closed, so no message names a command that refuses. `login --help` describes the route (the command stays hidden from `omo --help`), every other closed `login` form refuses with a message that names the route, the closed hints name both routes, and the compiled entry classifies bare `login`, `logout` and `whoami` as one-shot launches with the same shared parse the command uses (`login --` included). The damaged-item message names the terminal route too instead of a desktop-app-only dead end. Tests run the flow through the npm launcher (against a service-auth bundle built from this source into a temp copy of the launcher tree), the compiled entry and the toolkit CLI, with an isolated HOME and runtime dir, no inherited session bus, an injected store, and a refusal-text assertion on every zero-mint case. ([#13281](https://github.com/code-yeongyu/oh-my-openagent/pull/13281))

### Changed

- `omo login --new-device` is gone. The OmO service keeps one device per computer, so registering another device over an unreadable stored sign-in either failed after approval or left two live devices. When the stored sign-in cannot be read, `omo login` gives one recovery: remove this computer's device on the Devices page if it is still listed, then run `omo account forget` (which also has the device service forget the device), then sign in again. When the device service holds the device, it also names that device and says these steps sign out the device service, and the OmO desktop app if it is installed, on this computer. ([#13276](https://github.com/code-yeongyu/oh-my-openagent/pull/13276))
- When the credential store is locked, `omo login` says to unlock it and try again. ([#13276](https://github.com/code-yeongyu/oh-my-openagent/pull/13276))
- When the device service is installed but does not answer, `omo login` names the service's leftover endpoint file and says that opening the OmO desktop app starts the service. ([#13276](https://github.com/code-yeongyu/oh-my-openagent/pull/13276))
- `omo login`'s refusals no longer suggest `omo logout`, which does not work while OmO accounts are closed. A sign-in with an unknown refresh outcome first points to sharing the sign-in from the OmO desktop app when a device service holds this computer's device, and gives the start-over steps only as the fallback, with what they also end. When no device service holds the device, it gives the start-over steps directly. ([#13276](https://github.com/code-yeongyu/oh-my-openagent/pull/13276))
- The standalone omo binary stages every package its eval extension needs that the engine does not provide, so the eval tool loads in the binary on senpi 2026.11.13 and later (#13358). ([#13358](https://github.com/code-yeongyu/oh-my-openagent/pull/13358))
- The EQ.omo linux-x64 goldens are re-recorded at senpi 2026.11.13 (follow-up to #13328) (#13341). ([#13341](https://github.com/code-yeongyu/oh-my-openagent/pull/13341))
