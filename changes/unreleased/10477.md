**Changelog entries live in per-PR fragments, so pull requests stop conflicting on the changelogs.** A pull request that changes what ships adds exactly one file, `changes/unreleased/<pr-number>.md`: the paragraph that used to go under `## [Unreleased]` (or `### Fixed`-style bullets), plus a `<!-- changes-log: <path> -->` block for each entry it used to prepend to `changes.md` or `packages/<name>/changes.md`. Only the release pull request edits those files: the release workflow writes every fragment into the release section and the logs, and deletes the fragments. What counts as shipped is unchanged, and `bun script/changelog-fragments-cli.ts from-diff --base origin/dev --pr <n>` converts a branch that still edits the changelogs.
