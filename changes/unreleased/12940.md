**A crashed prune no longer leaves an old runtime copy on disk for good.** When a launch that was removing an old runtime under `~/.omo/binary-runtime/` crashed, and its process id was later reused, that runtime (~250 MB) could stay forever; one renamed more than an hour ago is now removed, including one left by the previous release. ([#12940](https://github.com/code-yeongyu/oh-my-openagent/pull/12940), follow-up to [#12770](https://github.com/code-yeongyu/oh-my-openagent/pull/12770))

## 2026-11-09 - Age ceiling for leftover prune trees (#12770 follow-up)

Review notes on #12770. `runtime-prune.ts`: the rename target is `.prune-<version>-<ms>-<pid>` (rename time, then pid), and the leftover sweep keeps a tree only while its pid is alive and it was renamed less than `PRUNE_TREE_MAX_AGE_MS` (one hour) ago. The pid stays the last segment so #12770's pruner, which reads the trailing number as the owner, still finds a live owner in a tree this version renamed; the time takes 13 digits, which no pid reaches. A name without `<ms>` (#12770) is aged by the tree's `ctimeMs`, which a rename updates; `mtime` is not used because it keeps the provisioning time and would read a fresh rename as old. `pruneProvisionedRuntimes` takes an optional `now`. `ENOENT` on the first rename skips the runtime instead of counting it in `removed`, because the pruner that took it may still rename it back. `compile-entry.ts`: `launchPrunesRuntimes` returns a type predicate, so `main()` no longer repeats `launch.launcher !== undefined`; no behavior change.
