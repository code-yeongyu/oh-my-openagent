**A crashed prune no longer leaves an old runtime copy on disk for good.** When a launch that was removing an old runtime under `~/.omo/binary-runtime/` crashed, and its process id was later reused, that runtime (~250 MB) could stay forever; one older than an hour is now removed. ([#12940](https://github.com/code-yeongyu/oh-my-openagent/pull/12940), follow-up to [#12770](https://github.com/code-yeongyu/oh-my-openagent/pull/12770))

## 2026-11-09 - Age ceiling for leftover prune trees (#12770 follow-up)

Review notes on #12770. `runtime-prune.ts`: the rename target is `.prune-<version>-<pid>-<ms>` (rename time), and the leftover sweep keeps a tree only while its pid is alive and it is younger than `PRUNE_TREE_MAX_AGE_MS` (one hour); a name without `<ms>` (#12770) is still judged by its pid. `ENOENT` on the first rename skips the runtime instead of counting it in `removed`, because the pruner that took it may still rename it back. `compile-entry.ts`: `launchPrunesRuntimes` returns a type predicate, so `main()` no longer repeats `launch.launcher !== undefined`; no behavior change.
