### Fixed
- `omo remote send` in wait mode printed the previous turn's answer and returned before its own turn settled: the follow printed every `text_delta` it received and settled on the first `agent_settled`, including the attach's replayed history, which over the relay arrives only after `onEvent` returns. A send that started or steered a turn now streams its deltas from the aim on (whatever the attach replayed before the aim is dropped) and settles only at its run's `agent_settled`, so retries and queued follow-ups stream through; a queued send's answer is read from the session's transcript, anchored on the send's own user entry, final when a later message's turn supersedes it or a run settled with it as the tail. A waiting send carries its own `clientMessageId`, which senpi stamps on the user entry it stores, so the anchor holds when a prompt template or skill expansion rewrote that entry's text and never lands on an older send of the same text; an engine that stores no id falls back to the text match.
