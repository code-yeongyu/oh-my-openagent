### Fixed

- Prometheus checks and executes the same authorized planning-file path, including relative symlink/`..` paths, aliased project roots, hashline renames, and patch moves. Patch headers must round-trip through the supported executor parser without changing authorized operations or targets. Rename/delete preserve named final links; content writes follow only allowed targets. The physical planning directory may have any name the user chose (for example `.omo -> docs/plans`) but must be strictly inside the real project root, never the root itself or an ancestor; a `.omo` path segment matches with filesystem-native casing. Every denial is logged with its specific reason. Nested plans and parent-folder Windows paths remain supported; required argument rewrites fail closed if the host's retained arguments cannot receive them ([#11424](https://github.com/code-yeongyu/oh-my-openagent/pull/11424))

### Security

- Capture the host execution arguments before the complete before-hook chain, rejecting detached or subsequently changed Prometheus approvals. Tests also cover aliased temporary roots rather than assuming temporary paths are canonical.
- Known and not fixed here: a hard link already under `.omo` can share an inode with a file outside `.omo`; realpath does not provide inode isolation.
- Known and not fixed here: TOCTOU between `tool.execute.before` and the tool's open. Closing this race requires tool-side `O_NOFOLLOW` and directory-handle confinement.
- Known and not fixed here: the patch round-trip trusts the vendored parser pinned to OpenCode 32f278b4; if the host parser changes, checked and executed targets can diverge again.
