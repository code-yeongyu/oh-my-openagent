**The memory status line no longer flickers through repeated identical updates.** Footer refreshes from a memory write, a settle and the reflection backlog land in whatever order their async work finishes, and several could publish the same line one after another; the line looked the same, but the number of updates depended on timing. An unchanged line is now published once, while every change and every clear still goes through. (#13046)

**A slow memory status refresh can no longer put an outdated line back on screen.** Each refresh now takes its place in line before it reads anything, and a line read earlier never replaces one read later; the uncommitted-changes marker is read only between memory writes, so it no longer flashes while a write is being committed. (#13046)
