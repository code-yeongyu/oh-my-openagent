### Changed

- The browser skill's bundled runtime is omowright 0.3.8 (was 0.3.4, #15088). No API change.
  - A failed `fill()` no longer returns the entered value in the error it rejects with, in these places: a cause that is not an `Error`, an `AggregateError`'s members, a field a transport adds to its error, a getter, a boxed string, and an error that cannot be rewritten in place. A value of four characters or more is removed even where it touches a letter or digit; a shorter one is removed only as a whole token, so `fill("a")` on `locator a a7` leaves `a7` readable. Among what is not reached (the full list is in omowright's 0.3.8 release note): property names, private fields, and text that only a method of an object computes (a `URL`, `Headers`).
  - An `Error` nested in a payload keeps its class and identity, except one that cannot be rewritten in place (frozen, or with a field that is neither writable nor configurable): that one is replaced by a scrubbed copy of the same class. The command's own parameters are never rewritten.
  - An orphaned browser left on a profile is killed only while it is still the recorded process, and a launch fails with an error naming the pid when a process the reap could not end is still running; before, the launch went ahead.

### Fixed

- Every example in the `browser` skill parses and accounts for the names it uses: each name is declared in its document's examples, is a platform global, or is listed in a `// given:` line that says what the reader supplies. The `Humans` example in `references/commands.md` passes concrete options where it used undeclared ones.
