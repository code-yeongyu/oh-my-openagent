### Fixed
- A waiting `omo remote send` no longer reports its turn as interrupted because an earlier run in the same session was interrupted.
- A waiting `omo remote send` no longer prints the turn's answer twice when the answer is both streamed and already stored in the transcript: the transcript read is not printed once the stream printed this turn's text.
- A waiting `omo remote send` no longer prints an earlier identical message's answer as its own when that earlier run finished just before the send was answered: only a finish that follows this send's own prompt ends its wait.
- A waiting `omo remote send` no longer prints an earlier identical message's answer when that earlier message carried no client message id (a send without `--wait`, text typed in the TUI), and a send whose interrupted turn was followed by a later message still prints its partial answer after the later turn's text.
- A waiting `omo remote send` to an engine that stores no client message id prints a turn that finished before the send was answered and exits, instead of waiting until the session closes; an interrupted turn whose partial answer only partly streamed prints the rest of it.
