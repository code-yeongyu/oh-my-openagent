### Fixed

- `omo --session <id>` attaches to a session the multi-session host (the desktop app) holds again, once the engine includes the matching senpi change. It exited 1 with "--extension cannot be applied to a session another process already runs" because the launcher's own plugin flag looked like one the user had given. Every omo launcher now names that plugin in the brand profile it hands the engine. ([#14467](https://github.com/code-yeongyu/oh-my-openagent/pull/14467))

## 2026-11-20 - the brand profile names the plugin the launcher prepends (#14467)

`bin/lib/engine-environment.js` `brandProfile()` and `compiled-environment.ts` add `extensions: [<plugin dir>]` to `SENPI_BRAND`: the exact path `spawnSenpi` / `buildSenpiArgs` pass with `--extension`. senpi's attach plan (senpi#6914) refuses every `--extension` on a start that attaches to a host-held session, and the brand field is how it tells the distribution's own plugin from a user flag (#14465). Older engines ignore the key.

## 2026-11-20 - the local launcher names its plugin in the brand profile (#14467)

`src/install/local-launcher.ts`: the generated launcher sets `SENPI_BRAND` to the brand plus `extensions: [plugin]`, the same runtime value (`OMO_PLUGIN_ROOT` or the install path) it passes with `--extension` (#14465).
