### Added

- When `omo login` is told this computer already has an OmO device, it names that device and offers to replace it. An interactive terminal asks (default No), and a script passes `omo login --replace`. You approve the replacement on the sign-in page, and omo then reports that the earlier device was signed out. If the device picked on the page isn't this computer's, nothing is replaced, and omo says to start over. If the OmO service doesn't support replacing yet, omo points you to the Devices page instead. ([#14055](https://github.com/code-yeongyu/oh-my-openagent/pull/14055))

## 2026-11-17 - omo login replaces this computer's earlier device on machine_exists (#14055, fixes #14032)

`device-flow.ts` `loginDevice`: on `machine_exists` it calls the new `replaceDevice` option with the refusal's `detail` (`deviceId`, `deviceName`, both optional, parsed in `protocol-request.ts`). If that returns true, it mints a new device code with `replace: { deviceId }` and polls it with the same keys. A second `machine_exists` (an older service that ignores `replace`) is reported as unsupported. `invalid_grant` with `detail.reason = "replace_mismatch"` is terminal. `grantSchema` accepts an optional `replacedDeviceId`, which is stripped before the credential is saved and returned to the caller. `replace-device.ts` `decideReplace` holds the three modes (`--replace`, interactive confirm with default No, a non-interactive refusal that names the flag). `commands.ts` adds `--replace` to the open command and the closed help, and `closed-device-login.ts` accepts `--replace`. The client revokes nothing.
