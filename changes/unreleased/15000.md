### Fixed

- `omo thread close` no longer fails with a TypeError on every call; it closes the thread and honours `--force` and `--graceful` (#14992).
- A thread control call repeated under the same `idempotency_key` now acts once and answers the first outcome on every surface: the thread SDK and `omo thread` used to close, interrupt or rename a second time (#14995).
- The remote module's `sessions.interrupt` now stops the interrupted turn's background jobs and reports them, as the thread tools do (#14951).

### Added

- `threads.read` (and `thread_read`) items carry a durable `id` (`<entry id>:<index>`), the same in every read and on every device, and take `after: <id>` to return only the newer items, oldest first; `seq` is the item's position in that one answer only. `threads.messages` stays the engine's whole list, with no ids (#14951).
