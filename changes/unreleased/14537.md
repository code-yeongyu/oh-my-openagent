### Added

- `thread_send` `collapse_key` (`omo thread send --collapse-key`, SDK `send`): a repeated message replaces the sender's earlier undelivered one under the same key, so a notifier that re-sends an alert every few minutes leaves at most one undelivered message. Sessions on this device only. `thread_list` rows show each thread's undelivered `backlog`. ([#14431](https://github.com/code-yeongyu/oh-my-openagent/pull/14431))
- The omo SDK signs a machine in by device code and renames a device: `account.signIn({ onUserCode })` shows the code once through the caller's callback, waits for approval and answers the new device, or a typed refusal such as `device_limit` (with the live devices; nothing is removed) or `machine_exists`. `devices.rename({ id, name })` renames one device. `omo account sign-in` drives the same function and prints JSON lines only, so an enroll call on a new machine can read the code before the approval it waits for. ([#14513](https://github.com/code-yeongyu/oh-my-openagent/pull/14513))

### Changed

- On Linux with no keyring (no Secret Service on the session bus, or a Bun without `Bun.secrets`), `omo login` and `omo account` keep the shared sign-in in a private file, `~/.omo/account-state/omo-cli-<id>.json` (directory 0700, file 0600), instead of failing with `store-unavailable`. A locked keyring or a keyring whose store fails still reports its own error and never falls back to the file. When a keyring runs later, the sign-in moves into it only when the keyring holds no sign-in or an older copy of the same one, and the file is deleted only after the keyring returns exactly what was written. A keyring that holds another sign-in keeps it, the file is left as it is, and one line says so. A sign-out removes only the sign-in in use. On Linux, the errors no longer say "Credentials are never saved to a file."; macOS and Windows are unchanged.
- `omo account show` and `omo account adopt` answer an additional `storage` field, `"keyring"` or `"file"`, naming where the shared sign-in is kept.
- The device and fleet keyword hint in OmO Native now points the agent at the `omo-relay` skill, instead of repeating the fleet client's import and shell details. It also fires when the user names their other machines or devices ("run this on my other machine"). The two warnings that keep a JS cell from exiting the kernel stay in the hint.

### Fixed

- Thread tools: closing a session's gateway store no longer fails a store call that was still running. The close used to reach the store between the call's open and its request, so the call answered `the gateway store is not open`; it now waits for running calls to finish first. ([#14536](https://github.com/code-yeongyu/oh-my-openagent/pull/14536), fixes [#14535](https://github.com/code-yeongyu/oh-my-openagent/issues/14535))
- A thread that is not running no longer stays `queue_full` for good. Messages waiting for it now expire after 24 hours even while it is down, and they stop counting against its 128-message backlog, so later sends are accepted again. A refused send now says the target is not running (`target_running`) and when its oldest message frees a slot (`frees_at`). ([#14469](https://github.com/code-yeongyu/oh-my-openagent/pull/14469), fixes [#14466](https://github.com/code-yeongyu/oh-my-openagent/issues/14466))
- A session that stops taking its thread messages no longer cuts itself off from every sender: steers have their own reserve (16 messages / 256 KiB), so they are admitted even when 128 undelivered follow-ups fill the target's backlog, and `queue_full` now says how many messages are held, how many the session took without writing them, how old the oldest is, and why they are not draining. ([#14431](https://github.com/code-yeongyu/oh-my-openagent/pull/14431), fixes [#14428](https://github.com/code-yeongyu/oh-my-openagent/issues/14428))
- The Linux keyring probe reports a missing Secret Service only when gdbus says so: no session bus socket and no way to start one, or nothing owns `org.freedesktop.secrets`. Every other gdbus failure (a bus that refuses this process, a refused connection, a timeout, a Secret Service with no default collection) keeps asking libsecret.
- Advice that forbids ultrawork no longer starts it. "avoid ulw", "no ultrawork", "skip ulw-loop", "without ultrawork" and "don't ulw" are read as advice, the same as "do not use ulw", so pasted guidance and rule lists don't arm the mode. This re-lands #14392, which release train #14415 reverted before it reached dev. ([#14514](https://github.com/code-yeongyu/oh-my-openagent/pull/14514), fixes [#14389](https://github.com/code-yeongyu/oh-my-openagent/issues/14389))
- OmO Native now reads `keyword_detector` from `omo.jsonc`. `"keyword_detector": { "disabled_keywords": ["ultrawork"] }` in a project's `.omo/omo.jsonc` or in `~/.omo/omo.jsonc` turns the `ulw`/`ultrawork` keyword off for every launch, and the key is no longer reported as unknown. The `--omo-senpi-ultrawork-disabled` flag still works for a single launch. ([#14514](https://github.com/code-yeongyu/oh-my-openagent/pull/14514), fixes [#14389](https://github.com/code-yeongyu/oh-my-openagent/issues/14389))
- The DAG e2e ordering and missing-skill test cases journal to the in-memory store, and that store builds its paths with the file store's own path builder, so host disk latency no longer times them out. ([#14502](https://github.com/code-yeongyu/oh-my-openagent/pull/14502))
- A Mac first signed in through the desktop app before device names became machine names keeps its `OmO Desktop on <host>` label no longer: the next sign-in refresh renames the device to its machine name, so `<host>` resolves in thread tools and the device mesh. A name you chose is never changed. ([#14480](https://github.com/code-yeongyu/oh-my-openagent/pull/14480))
- When reopening a thread, name devices whose lookup timed out separately from devices that did not answer, and suggest retrying the lookup. ([#14487](https://github.com/code-yeongyu/oh-my-openagent/pull/14487))
- Switch live threads with a thinking suffix such as `:max`. If the target catalog has no models from the requested provider, `thread_set_model` now names the provider and lists the providers available there.
- A `thread_send` (or any send path) to a thread whose device left the account no longer resolves the row's stale device id onto a different device that shares its id prefix or carries it as a name: listing-row device ids now resolve as exact ids, answering `not_found` like an unknown device. ([#14521](https://github.com/code-yeongyu/oh-my-openagent/pull/14521))
- An unnamed thread on another device is named after the folder its `path` names (the same folder its cwd and refusal candidates use), not the `project` field, so `thread_list`, the row's cwd and its refusal candidate cannot disagree. ([#14521](https://github.com/code-yeongyu/oh-my-openagent/pull/14521))

## 2026-11-20 - Apply thinking suffixes when switching thread models (#14482)

`thread_set_model` matches against the target catalog and applies a recognized thinking suffix to the target session after the model switch. On an unsupported level, it restores the previous model and level before returning `thinking_level_unsupported`, or returns `partial_commit` if it cannot confirm restoration. A switch the target does not show as active returns `partial_commit` with `model_switch_unconfirmed`, and a target that reports no current model state refuses a suffix with `unsupported` / `model_state_unavailable`. If the requested provider has no available models on the target, `model_not_found` includes `provider_not_configured` and the available providers.
