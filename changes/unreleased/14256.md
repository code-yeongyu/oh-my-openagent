### Fixed

- `omo update` now updates the install your PATH actually runs when omo lives in a side-by-side versions layout (`~/.omo/omo-versions/<version>` with `current` pointing at the live one). It installs the new version beside the old one with bun, checks it runs, switches `current` in one step and keeps the previous version for rollback. It no longer runs `npm i -g` into a copy PATH never uses and then reports a false "update failed". If another omo earlier on PATH still answers with the old version, `omo update` says which install it updated and which path PATH still resolves, and exits non-zero.
