### Changed

- Hephaestus on GPT-6.2 models sends one prompt instead of two: the GPT-6.2 core stands alone there, so the Hephaestus role is no longer appended after it. Other models keep the role, and switching models in a session drops or restores it. On a real request the system prompt goes from 9,211 to 4,300 tokens (`o200k_base`). The refusal-is-final rule is now stated once inside the model-core frame for every agent that carries it instead of at the end of the role, so it survives without the role and is never doubled by a model core that states it. ([#14219](https://github.com/code-yeongyu/oh-my-openagent/pull/14219), part of [#14186](https://github.com/code-yeongyu/oh-my-openagent/issues/14186))

### Fixed

- `omo remote send` that waits on a turn now settles inside a bound: `--timeout <seconds>` (1..600, default 120) answers a typed `{kind:"timeout", waited_ms, ...}` JSON value instead of hanging when the turn never settles; a session that ends before settling answers `{kind:"session_ended", end}` as one JSON value under `--json` (both were a silent hang or stderr-only), and the queued notice rides that same JSON value instead of being dropped (#13425). ([#14213](https://github.com/code-yeongyu/oh-my-openagent/pull/14213))
- `thread_create` reopens a closed thread on another device again. It failed with `EISDIR`: the account listing names a session's working folder, never its session file, and that folder was sent to the other device as the file to open (a row with no path sent its working folder too). The reopen now opens the file the close was told by that device, or else asks the device which file carries the thread's id; a device that cannot say answers a typed refusal naming it (`unsupported` for an engine without the lookup, `not_found`, or `ambiguous_target`). A thread this device closed no longer lists as `live` while the listing catches up, and a reopen answers `ok` only once the reopened session can be reached, so the next tool call no longer answers `not_resumable`. ([#14179](https://github.com/code-yeongyu/oh-my-openagent/pull/14179), fixes [#14170](https://github.com/code-yeongyu/oh-my-openagent/issues/14170))
- `thread_send` to a thread on another device that is not running answers at once instead of waiting about 60 seconds for `unsupported` (`daemon_unavailable`). The device holding it is asked first, whether or not this device can wake it there: a thread it holds no session file for is `not_found` (as the refused reopen says), one it runs is delivered to (also when it was reopened elsewhere since this device last listed it, under whatever key it runs under now), and one it only has on disk is woken when this device can wake it there, else `not_resumable`, naming the reopen as the next step. A device without the wake capability counts as unable to wake. ([#14179](https://github.com/code-yeongyu/oh-my-openagent/pull/14179), fixes [#14184](https://github.com/code-yeongyu/oh-my-openagent/issues/14184))
- `thread_send`, `thread_read` and `thread_create` aimed at another device no longer wait past what an eval tool call allows: the command waits, wakes, creates and attaches of one call now share one 50 s budget, and a `thread_read` wait on another device leaves the read after it enough time to return the transcript. A message the relay accepted for the other device but whose answer was lost is reported as the new `delivered_unconfirmed` (it may have run: read the thread before sending again). ([#14185](https://github.com/code-yeongyu/oh-my-openagent/pull/14185))
- `thread_create` (and `omo remote open`) on another device now opens the thread only on that device's own engine (the primary engine endpoint its device service names), never on the first endpoint listed. Before this, a thread could land on an owner shard or on another registered agent dir's older engine, which then refused every cross-device `thread_send` as unsupported (`method_unclassified`). When the device names no primary, because its own engine is not listed, the create now fails `host_unavailable` with reason `no_primary_endpoint` before anything opens, even if only one other endpoint is listed. The next action says to start or restart omo on that device, and to update the device service on both devices if that does not help (a device service older than 0.1.11 cannot name a primary; behind such a local service a device's lone endpoint is still used). ([#14200](https://github.com/code-yeongyu/oh-my-openagent/pull/14200), fixes [#14195](https://github.com/code-yeongyu/oh-my-openagent/issues/14195))
- `thread_send` no longer answers `not_found` for a thread that `thread_list` shows live while the other device's service is restarting for an update, or when that device missed one account listing round. It now answers a retryable `host_unavailable`, so the sender can try again instead of treating the thread as gone. ([#14174](https://github.com/code-yeongyu/oh-my-openagent/pull/14174), fixes #14172; this entry was missing from the #14196 train's notes) ([#14203](https://github.com/code-yeongyu/oh-my-openagent/pull/14203))
- A newer gateway store schema of an extension is no longer reported as the gateway's own schema with that extension's migration counts. ([#14221](https://github.com/code-yeongyu/oh-my-openagent/pull/14221))
- When a thread created on another device cannot be named because this device is signed out, the warning now names this device's sign-in instead of telling you to update omo on that device. ([#14221](https://github.com/code-yeongyu/oh-my-openagent/pull/14221))
- `thread_create` with an alias held by a thread on another device no longer opens a copy of that thread's session file on a third device as if it were the holder. ([#14221](https://github.com/code-yeongyu/oh-my-openagent/pull/14221))
- The remote wake's engine minimum now also holds back a compiled omo or dev build when a caller sets a stricter minimum, and an omo prerelease no longer counts as its release. ([#14221](https://github.com/code-yeongyu/oh-my-openagent/pull/14221))
- A reply's route and the listing it takes are decided from one read of this device's id, and a late endpoint listing no longer replaces a terminal's kind that another session's newer listing recorded. ([#14221](https://github.com/code-yeongyu/oh-my-openagent/pull/14221))

## 2026-11-18 - Thread train 2 top: thread tool fixes and the senpi 2026.11.18-2 pin (#14225)

- **Reopen a closed thread on another device from its file (#14179)**
  - **Never open a listing row's path (#14170)**
    - `src/components/thread/remote/ports.ts`: `RemoteSessionRow.path` is the session's working folder as relayd lists it (`cwd`, else `"unknown"`), never its file; the new `session_file` carries a file the device itself named.
    - `src/components/thread/remote/find-session.ts` `sessionFileOf`: a remote reopen opens `session_file`, else asks the device `find_session { durableSessionId }` (senpi#6429) and opens the file it names. `method_unclassified` or an unknown command is `unsupported`, `unknown` is `not_found` and `ambiguous` is `ambiguous_target`, each with `device` and `thread`; nothing is opened.
    - `src/components/thread/remote/plan-create.ts`: every remote reopen of a thread that is not live checks the device online and takes that file. `tools.ts` drops the old `ended`-and-no-path guard.
  - **The listing lags a close and a reopen**
    - `src/components/thread/remote/closed-rows.ts` `withClosedRows`: one ledger per sessions port. A thread these tools closed lists `ended` with the file its `unload_session` reply named (`control/relay-control.ts`) until the listing shows newer activity; a thread they reopened lists under the key its device located it by. `remote/ports.ts` gains the optional `closed` / `reopened` members.
  - **A reopen is ok only when the session can be reached**
    - `src/components/thread/control/relay-session-host.ts`: a reopen asks for and locates the reopened session's key, as a create does, instead of keeping the cached row's key; a key that does not resolve is `not_resumable`.
  - **A send to a thread that is not running fails fast (#14184)**
    - `src/components/thread/remote/relay-transport.ts` `addressOf`: a row that is not live (ended, or a cached snapshot) has its device asked `find_session` (`remote/find-session.ts` `holderView`) before any path is chosen, the wake path included: no file is `not_found`; running is located (`remote.sessions.locate`) and sent to under its current key (a held session that cannot be located is `not_resumable`); on disk takes the wake path when there is one (a port without `canWake` has none), else `not_resumable`. A device that cannot answer (an engine without `find_session`, or no reply) counts as holding it on disk: an `ended` row takes the wake path when there is one, anything else is `not_resumable`.
