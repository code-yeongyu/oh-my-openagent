## 2026-10-28 - Reflection slot reclaim tolerates a concurrent release (#11654)

memory-core's `recoverStaleOwner` (bundled into the extension) now removes a proven-dead lock only if it still holds the record it read, using the rename-then-inspect step the recovery lock already used. A slot retained for a supervisor's child carries the child's pid under the supervisor's nonce, so when that child exits the waiting FIFO head can prove the record dead while the live supervisor releases the same file. The plain unlink then threw `ENOENT` (the Windows `supervisor-slot.test.ts` failure) or deleted a lock a rival had just published. A vanished file now means the slot is free and the publish is retried; a different record is handed back untouched.
