### Changed

- `task_cancel` now cancels only tasks of the calling session (the task's parent or root session), the same rule `task_send` uses. A task outside the caller's own reads as not found, and a name is looked up among the caller's own tasks first; `task_send`'s name lookup does the same (#15195).

## 2026-11-27 - task_cancel applies the caller's scope (#15195)

The `task_cancel` tool always passes the calling session to the engine as `CancelOptions.caller`. With a caller, one resolver (`steering/scope-resolver.ts`) resolves an id or a name only among the tasks that session owns as parent or root, and a caller without a session id resolves nothing; whatever does not resolve gets the existing not-found answer. `interruptTask` accepts the same option. Callers inside the engine pass no caller and keep the store-wide lookup: workflow cancel and recovery, workpools, the team runtime, a spawn's own abort, run pause, `/tasks kill` and eval handles. `task_send` resolves a name among the caller's own tasks first and is otherwise unchanged.
