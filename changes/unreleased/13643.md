### Fixed

- A computer signed in before OmO accounts knew machine identity now binds its device to that machine. After a token refresh in `omo account token` (the desktop app's token path), `omo login|logout|whoami`, memory sync's CLI account session or the thread tools' service access, omo signs this machine's hardware digest with the device's own key and sends it to `PUT /v1/devices/current/machine`, if the service advertises `hardware-digest-v1`. A later sign-in on the same computer is then refused as a second device instead of being added beside it. The binding starts after the token read has answered and never changes its result: it is limited to 5 seconds, and any failure is one log line. A command that exits waits up to that limit after printing its answer. A machine with no validated hardware id sends nothing. The service's final answer is kept in `~/.omo/account-state/<credential>.machine-binding.json` and not asked again: bound, another device already holds this computer, or a refusal of this device. An answer that is not final, such as a service without the capability, a missing route, an unknown refusal or a second clock skew, is asked again after a day, not at every refresh. When another device holds the computer, omo names it and changes nothing. ([#13643](https://github.com/code-yeongyu/oh-my-openagent/pull/13643))
