### Fixed

- `thread_create` on another device no longer answers `idempotency_uncertain` (`reply_lost`) for a session that device did create. The create is opened under the id its `idempotency_key` derives; when the open's reply is lost (a busy device answering after the call's budget), the session that device lists under that id is answered as the created thread, on the spot or on a retry under the same key, and no second session is opened. An engine that ignores the id still answers uncertain. A retry of an uncertain create now runs the create again instead of replaying the uncertain answer. ([#14564](https://github.com/code-yeongyu/oh-my-openagent/pull/14564), fixes [#14560](https://github.com/code-yeongyu/oh-my-openagent/issues/14560))
