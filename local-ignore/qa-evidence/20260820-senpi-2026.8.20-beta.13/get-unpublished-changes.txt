A settled DAG run is no longer terminal: `reenterDagRun` journals a synchronous `dag.run.resumed` and builds a **fresh** scheduler from the current record (the old instance's cancellation deferreds and admission latches are single-shot, so reusing it would inherit a spent state machine), then `retryDagNodes` returns `failed`/`cancelled`/`skipped` nodes to a pending attempt and hands the skip-cascade back to the wave loop. **Why a user cares:** a 12-node graph where one node flaked used to mean re-running the whole graph and paying for all 12 children again. ## 3. Breaking Changes

**None.**

- The three new DAG event types and the new snapshot fields are explicitly additive: `schemaVersion` stays `1`, every added field is optional and *absent* (never `null`) when inapplicable, and no existing field was renamed, reordered, or removed. Consumers that ignore unknown event types and unknown fields are unaffected. This stance is now written into `docs/reference/mass-ulw-protocol.md`.
- `dag` tool actions `start`/`attach`/`snapshot`/`wait`/`cancel` keep their existing argument shape and semantics; `retry`/`send`/`amend` are new alternatives.
- `checkReflectionHealth` gained an optional `{ now }` parameter; omitting it is byte-identical to previous behavior.
- Two behavior *sharpenings* worth knowing, neither a contract break: `/dag` node rows now show `x<attempt>` where they previously printed `attempt <n>`, and node error rows now prefix the error code before the message.

## 4. Highlights

**A failed DAG run is now recoverable one node at a time.** This is the release's center of gravity. Before, a graph that lost a single node to a flaky tool call or a bad prompt was effectively a total loss: you re-ran the definition and paid for every child again. Now `retry` hands just the failed, cancelled, and skip-cascaded nodes a fresh attempt while every completed node keeps its cached result; `send` steers a running child in place or revives a finished-but-resident one with its context intact; and `amend` accepts an edited definition against the same run, fingerprint-diffs it, and re-runs only what actually changed plus its transitive dependents. Editing only a node's `load_skills` re-runs nothing at all, by design. For anyone driving multi-node work through mass-ULW, this converts the most expensive failure mode in the system into a targeted, cheap fix.

**`/btw` gives you a side conversation that doesn't cost you your main context.** `/btw <question>` (or `/side`) opens a temporary session on the same model and agent, `Ctrl+/` toggles between it and the main conversation, and `Ctrl+C` on an empty side composer closes it. The side thread sees your recent main-conversation context as read-only background — capped at 64 messages and 64 KiB, injected behind a boundary that instructs the model not to mutate files or delegate to subagents — and its question and answer never enter the main transcript. The main agent keeps working the whole time. The lion's share of the PR after the initial feature was lifecycle hardening: parent deletion, orphaned nesting, crash re-adoption, and cancellation ordering are all explicitly handled, which is what keeps this from leaking abandoned sessions into your session list.

**The repeated-error stall in model fallback is fixed, and fallback now respects your variant.** This was issue #6579: the retry-dedupe key didn't include the failing model, so the same error arriving on a *different* model looked like a duplicate and got dropped — the session simply went quiet. The key is now scoped per model, the dedupe store is a set per session, a skipped retry gives its key back instead of burning it, and internal fallback retries are routed by an explicit marker so they stop being discarded as synthetic traffic. Alongside it, model identity is now carried as provider/model **plus variant** through the entire fallback path, so a reasoning-effort selection survives a fallback and a recovery instead of quietly degrading, and fallback watchdog timers are generation-scoped so a timer from an abandoned attempt can no longer force a spurious model switch later.

**The transcript reads like one product instead of several.** Fallback-architect notices, task-completion cards, team-member liveness warnings, and the memory reflection/health/soul/write notices all render through one shared padded notice box now. Completion cards lead with a tone-mapped glyph and the task name, keep identity and cost metadata (`id · target/model · duration · tokens · tools · tps`) on a dim second row, and hold the continuation hint and result-file path behind expansion. `/dag` and the status widget add an `x<attempt>` badge on re-run nodes, an `amended x<n>` marker on the run header, and the error *code* alongside the error message — so at a glance you can tell what was retried, what was replanned, and what class of failure you're looking at.

**`/doctor`'s reflection-health verdict stopped depending on when you ran it.** Reflection-health severity is derived from a trailing failure streak that ages out after a staleness window, which meant `[warn]` silently decayed to `[ok]` with nothing but the passage of time and no test could pin the boundary. The check now reads its clock from the same injected seam the rest of the doctor checks use, so the verdict is a pure function of your reflection data. Behavior with no clock supplied is unchanged.

**CI stops lying about your changes.** Three Windows-slow suites got honest timeout ceilings (with the real sub-second local runtimes recorded in-comment and every wait left event-driven), memory-test teardown gained a narrowly scoped `EFAULT`-only retry that still fails loudly if the fault is real, and two DAG `wait`-hang classes — resident-child cap saturation and terminalization during subscription setup — are now covered by bounded regression tests rather than discovered in production. On top of that, the Senpi adapter is now a first-class mandatory-QA surface with a machine-enforced evidence path, so changes to the native engine are held to the same "drive the real binary, write the proof to disk" bar that OpenCode and Codex changes already were.
