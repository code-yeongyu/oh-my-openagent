# omo-agent-toolkit-rename - Work Plan

## TL;DR (For humans)
<!-- Fill this LAST, after the detailed plan below is written, so it summarizes the REAL plan. -->
<!-- Plain English for a non-engineer: NO file paths, NO todo numbers, NO wave/agent/tool names. -->

**What you'll get:** The new release renames every command the CLI family ships to ONE new name, `omo-agent-toolkit`, on every edition (npm installs and Codex installs alike) - and removes the old `omo` command in the SAME release. After upgrading, `omo` no longer exists on your PATH: scripts and muscle memory switch to `omo-agent-toolkit`. Existing Codex installations clean up their old `omo` wrapper automatically at the next session start or installer run. This frees the `omo` name so the future native senpi-based product can ship as `omo-ai` and own `omo`.

**Why this approach:** The user picked a clean hard cutover over a staged deprecation: one short name lives, the old name is gone, and the one function that the installer and the session-start relinker share performs the migration for existing machines with zero manual steps (marker-guarded, so user-owned files are never touched).

**What it will NOT do:** It ships nothing of the omo-ai native product (no new package, no publish pipeline changes beyond the rename smoke, no beta channel). It does not rename npm package names, config files, env vars, directories, or the Codex marketplace identity. It does not keep any `omo` alias, forwarder, or deprecation notice.

**Effort:** Medium
**Risk:** Medium - removing `omo` is a breaking change for anything still invoking it (scripts, muscle memory, stale shells), and a removed command cannot print its own deprecation notice, so the migration message lives in postinstall + CHANGELOG + docs; this ships as a MAJOR release (recommended v5.0.0 - the repo declares SemVer adherence at CHANGELOG.md:6 and removing a published bin entry is a breaking public-interface change). Regression risks (byte-identical stdout for surviving aliases, untouched user-owned files in the Codex bin dir, silent stale-wrapper execution) are pinned by characterization baselines and marker-guarded reclamation.
**Decisions to sanity-check:** (1) ONE unified name `omo-agent-toolkit` for humans AND agents on all editions (user-decided); (2) `omo` is REMOVED in this same release (user-decided hard cutover, not a staged deprecation); (3) npm package names unchanged.

Your next move: high-accuracy review runs automatically; after that, start execution in a worker session via `$start-work omo-agent-toolkit-rename`. Full execution detail follows below.
