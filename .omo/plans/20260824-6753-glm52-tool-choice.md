# Plan: Fix #6753 - zai glm-5.2 sends tool_choice with empty/absent tools

## Root cause (file:line)

The `@ai-sdk/openai-compatible` provider bundled inside opencode builds the wire
body unconditionally: when the effective function-tool list is empty (or
`tool_choice` names a function absent from `tools`), it still serializes
`tool_choice`, and Z.AI/GLM rejects it with HTTP 400 code 1210
(`AI_APICallError: API 调用参数有误`). OMO triggers this via Atlas/Sisyphus turns
that force `tool_choice:"required"` while MCP/provider-defined tools leave the
function list empty.

OMO cannot patch the vendored SDK, but opencode's provider pipeline gives us an
in-process hook point (verified against opencode 1.18.16 source + binary):

- `packages/opencode/src/provider/provider.ts:1420-1424` - plugin `config()`
  hook runs BEFORE `cfg.provider` is read; mutations land.
- `provider.ts:1462-1471,1559` + `1628-1634` - config provider entries are
  deep-merged over the models.dev entry (`mergeDeep`), models preserved, so a
  plugin-created `{ options: { fetch } }` entry for `zai-coding-plan` survives.
- opencode binary, openai-compatible loader:
  `t = typeof e.options.fetch === "function" ? e.options.fetch : void 0; ...
  createOpenAICompatible({...e.options, ..., fetch: ma(t)})` - our wrapper
  becomes the transport fetch for that provider.

## Change set

1. NEW `packages/omo-opencode/src/features/zai-tool-choice-guard/index.ts`
   - `stripInvalidToolChoiceFromBody(body)` - pure sanitizer: delete
     `tool_choice` when `tools` is missing/empty or when
     `tool_choice.function.name` is not in `tools[].function.name`. Mirrors the
     issue's proxy semantics; valid requests untouched.
   - `createZaiToolChoiceFetch(inner?)` - fetch wrapper: parses JSON request
     bodies (cheap `"tool_choice"` substring pre-check), sanitizes, forwards to
     `inner ?? globalThis.fetch`; responses (incl. SSE) pass through untouched.
     Idempotent via brand property; composes with user-set fetch instead of
     replacing it.
   - `applyZaiToolChoiceGuard(config)` - mutates `config.provider` for the
     Z.AI/GLM family ids (`zai`, `zai-coding-plan`, `zhipuai`,
     `zhipuai-coding-plan`), creating the entry if absent and injecting
     `options.fetch`. Idempotent.
2. NEW co-located `index.test.ts` - failing-first regression tests
   (given/when/then): tool_choice stripped when tools absent / empty / named
   function missing; preserved when tools present and choice valid; non-JSON
   and choice-less bodies byte-untouched; inner-fetch composition; response
   passthrough; wiring idempotency + non-zai providers untouched.
3. EDIT `packages/omo-opencode/src/plugin-handlers/config-handler.ts` - call
   `applyZaiToolChoiceGuard(config)` next to `applyOpenGatewayProviderConfig(config)`.

- If a future opencode drops `options.fetch` support the guard becomes inert
