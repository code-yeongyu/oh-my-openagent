# The Codex installer spawns a script that was deleted with CodeGraph

## What was tested

`runCodexInstaller` / `installMarketplaceLocally`, both through the unit suites and through a real
packaged install against an isolated `CODEX_HOME`.

- `bun test packages/omo-codex/src/install/install-codex.test.ts packages/omo-codex/src/install/install-codex-packaged.test.ts`
- `node --test packages/omo-codex/scripts/install-packaged-local.test.mjs` (after `bun run build:codex-install`)
- Packaged install driven from this worktree with `CODEX_HOME` and `CODEX_LOCAL_BIN_DIR` pointed at temp dirs.

## What was observed

RED, from `red-installer-spawns-missing-script.log`: the installer spawns a `.mjs` that is not in the
tree.

```
- []
+ [
+   ".../packages/omo-codex/plugin/scripts/migrate-omo-sot.mjs",
+ ]
```

| Input | Before | After |
| --- | --- | --- |
| `install-codex.test.ts` + `install-codex-packaged.test.ts` | new assertion fails (1 missing spawned script) | 13 pass / 0 fail |
| `node --test install-packaged-local.test.mjs` | asserted 2 spawned commands incl. the missing script | 1 pass / 0 fail, 1 command |
| packaged install log | `Warning: skipped OMO SOT seed/migration: ... exit code 1` | warning gone, `RESULT: ok installed=1` |

The only remaining warning in the GREEN install log is the expected
`skipped the omo-agent-toolkit runtime wrapper` line, because this worktree has no built `dist/cli`.

## Why it is enough

The new assertion is behavioral rather than name-based: it fails for any installer step that spawns a
repo script the payload does not carry, so it also covers the next deletion of this shape. The
packaged install shows the user-visible warning disappearing on the real surface.

## What was omitted

Follow-up in the same PR: the inline assertion was extracted into
`packages/omo-codex/src/install/spawned-script-targets.ts` with its own suite (3 pass), and the
integration test now calls it. The helper's missing-path branch was mutated away to confirm the suite
fails without it, then restored.

`packages/omo-codex/scripts/install-dist/install-local.mjs` is regenerated by
`bun run build:codex-install` and committed, because
`script/codex-install-bundle-freshness.test.ts` compares the tracked bundle's source-digest marker
against the installer sources and fails when they diverge. The regenerated body also carries bundler
churn (import aliases, vendored dependency internals) that the previous committed copy predates; that
churn comes from the build, not from hand edits. No secrets or credentials appear in the captured
logs.
