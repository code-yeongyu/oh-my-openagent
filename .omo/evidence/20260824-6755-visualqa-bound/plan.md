## Root cause

`packages/shared-skills/skills/visual-qa/SKILL.md` line 229 (`### Completion gate`, lines 221-229):
the completion contract mandates "Loop until the independent reviewer passes on the current build"
with no round ceiling. Each fresh reviewer may report a different valid lower-priority defect,
so the review chain is unbounded. PR #6069 reduced evidence-vs-product churn but left the
fresh-review loop itself uncapped.

## Change (minimal, prose + machine-consumed sentinel only)

1. `packages/shared-skills/skills/visual-qa/SKILL.md` (ONLY file with product content):
   - Retitle completion gate to bounded semantics.
   - Add explicit review-budget state tracking: `review_round`, `max_review_rounds`,
     `blocking_findings`, `non_blocking_findings`.
   - Budget policy per issue: low-risk surface = 1 round; normal product surface = initial
     review + at most 2 focused re-review rounds; blocker fixed inside budget earns a focused
     fresh reviewer; non-blocking polish NEVER starts another round; on exhaustion STOP and
     report `needs-human-review` with remaining blockers visible; continue only on explicit
     user acceptance or a new request.
   - Append machine-consumed sentinel `<!-- visual-qa-review-budget-contract -->` + json fence
     encoding that policy (mirrors `ulw-plan/references/full-workflow.md:212-234` precedent
     from issue #6128).
2. NO TS changes: `skill-file-loader.ts` reads SKILL.md from disk at runtime; frontmatter
   untouched so `shared-skill-extraction.test.ts` byte-equality/description lockstep holds.

   no visual-qa).
