# F2 Code Quality Review

## Verdict

REJECT

The branch has release blockers under the stated verdict rules. Passing typecheck and focused tests do not clear the duplicated privacy allowlist, swallowed errors, banned Unicode in the changed generated artifact, or tautological test. The default OmO Native PostHog key is also still a placeholder, so the documented on-by-default pipeline does not deliver production telemetry without an undocumented environment override.

## Blocking findings

### 1. The production telemetry key is a placeholder

- `packages/omo-senpi/src/components/telemetry/product-identity.ts:13`
- `packages/omo-senpi/src/components/telemetry/product-identity.ts:80`
- `packages/omo-senpi/src/components/telemetry/product-identity.test.ts:42`

`OMO_NATIVE_POSTHOG_API_KEY` is `phc_REPLACE_ME_OMO_NATIVE`, and that value is installed as `defaultApiKey`. The test pins the placeholder instead of requiring a deployable project key. The branch's own prior evidence states that PostHog drops native events unless `POSTHOG_API_KEY` is supplied. This contradicts `docs/reference/senpi-telemetry.md:5`, which says the pipeline is on by default. The real-surface QA passes only because `script/qa/omo-native-telemetry-qa.mjs:247-248` injects `POSTHOG_API_KEY=phc_test` and a local host.

### 2. The property allowlist is duplicated outside the required source of truth

- `script/qa/omo-native-telemetry-qa.mjs:32-39`
- Canonical definition: `packages/omo-senpi/src/components/telemetry/product-identity.ts:15-35`

The QA script hand-copies every event and property list into `propertyAllowlists`. This is the exact latent privacy bug the review instructions prohibit. If production expands or changes the canonical allowlist while this copy drifts, QA can validate the wrong policy. The script must consume the canonical allowlist or a generated artifact derived from it.

### 3. Config resolution errors fail open and are swallowed

- `packages/omo-senpi/src/components/telemetry/omo-native-session.ts:138-145`
- `packages/omo-senpi/src/components/telemetry/omo-native-notice.ts:98-105`

Both `configEnabled` implementations catch every config-loading failure without a diagnostic and return `true`. A malformed or unreadable configuration can therefore turn telemetry on even when the user's intended config cannot be read. This is both dishonest error handling and the wrong privacy default. The error must be reported, and config resolution failure must not silently enable telemetry.

### 4. The QA driver contains swallowed errors

- `script/qa/omo-native-telemetry-qa.mjs:556`
- `script/qa/omo-native-telemetry-qa.mjs:579`
- Embedded generated fixture at `script/qa/omo-native-telemetry-qa.mjs:210`

Line 556 has an empty catch while parsing transcript events. Line 579 discards capture-server cleanup failures with `.catch(() => {})`. The embedded mock provider also attaches an empty rejection handler to its result promise. These catches neither handle nor report the errors, violating the explicit error-handling rule. Cleanup failures are especially material because the driver claims cleanup proof.

### 5. A changed generated artifact adds banned Unicode

- `packages/omo-senpi/plugin/extensions/omo.js:2269`

The diff adds a generated line containing literal U+26A1 and U+2014 characters. The repository rule says no emojis and no em/en dashes anywhere. The authored telemetry source is clean, but the committed generated artifact is part of `origin/dev...HEAD` and fails the required diff scan.

### 6. The builtin inventory test re-derives its expected values from the implementation inputs

- `packages/omo-senpi/src/components/telemetry/product-identity.test.ts:99-104`
- Implementation: `packages/omo-senpi/src/components/telemetry/product-identity.ts:63-65`

The test compares `CURATED_AGENTS` directly with `CURATED_READONLY_AGENT_NAMES`, even though `CURATED_AGENTS` is defined as a spread of that same imported value. It similarly computes category names with the same `BUILTIN_CATEGORY_DEFAULTS.map(({ name }) => name)` expression used by production. These assertions do not independently pin the privacy-safe inventory and cannot catch an upstream inventory expansion. This is an expected-value re-derivation of the kind called out in the review instructions, so it is a verdict blocker.

## Re-review

### Final verdict

REJECT

The two accepted F2 fixes are real and complete, and I accept the orchestrator's reasoning on all three rejected findings. However, commit `8d4b1be14` introduced a new release blocker in the reviewed build script scope: it invalidates all three extension build markers but commits a rebuild of only `omo.js`. The tracked `omo-member.js` and `omo-memory-mcp.js` artifacts are stale.

### Accepted fix 1: QA allowlist single source of truth

Verified complete.

- `script/qa/omo-native-telemetry-qa.mjs:16-21` imports `KNOWN_MODELS`, `KNOWN_PROVIDERS`, and `OMO_NATIVE_PROPERTY_ALLOWLISTS` directly from `packages/omo-senpi/src/components/telemetry/product-identity.ts`.
- The former hand-maintained `propertyAllowlists` object is gone.
- `assertAllowlistCoverage` at lines 38-45 rejects missing and extra native events, and the module asserts the imported schema at initialization on line 47.
- `script/qa/omo-native-telemetry-qa.test.ts` verifies the exact seven-event inventory and proves both missing-event and extra-event divergence fail.
- The focused QA source tests passed: 2 pass, 0 fail.

I also performed the required real captured-payload mutation. I temporarily changed the capture parsing path to add `undocumented_probe: true` to parsed event properties, ran the real QA driver, and restored the script from a byte-for-byte backup under a shell trap. The run exited 1 with:

### Accepted fix 2: config failures fail closed with diagnostics

Verified complete in both paths.

- `omo-native-session.ts:143-146` checks `loaded.diagnostics.length`, emits a `telemetry_capture_failed` diagnostic, and returns `false` when config loading returns diagnostics.

- `omo-native-notice.ts:113-116` also diagnoses thrown failures and returns `false`.
- Missing config remains enabled by default because a clean load delegates to `isOmoTelemetryEnabled(loaded.config)`.

Both session and notice tests cover absent config, explicit `true`, explicit `false`, malformed config, and an unreadable existing config path. The malformed and unreadable cases assert disabled behavior plus a diagnostic. The required focused telemetry run passed all 79 tests with 0 failures and 314 assertions.
