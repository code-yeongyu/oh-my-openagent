# F1 Plan-Compliance Audit - omo-native-telemetry

## Verdict

**REJECT**

The branch reproduces most functional acceptance criteria, including all named high-risk behavior checks, but it is not plan-compliant:

1. **Todo 5 / plan-wide payload contract:** the real built plugin emits `package_version: "0.0.0"` on all OmO Native events although both package manifests are `5.0.0-beta.5`. The source-relative package lookup is wrong after bundling.
2. **Todo 13a:** the generated schema block enumerates property names only. It does not enumerate property types or bucket/enum values as explicitly required.
3. **Todo 11 / structural privacy invariant:** `omo-native-component.ts` directly calls `transport.capture(...)` at two sites, bypassing the telemetry-core event wrapper for post-session emitters. This fails the plan's wrapper-only capture-path invariant and its executable F4 sweep.
4. **Todo 11 / deviation 2:** `BUDGET_BYTES` was raised from 880,000 to 900,000 and the committed bundle is 891,384 bytes. The comment, purity proof, dependency proof, and source-freshness marker exist, but the plan repeatedly and explicitly says the ceiling must never be raised and todo 11 requires staying below 880,000. The justification does not supersede that guardrail.

Any one of these is sufficient for REJECT under the stated verdict rules.

## Plan deviations

### Deviation 1 - content-suffix guard changed to reject only string values

**Judgment: acceptable; does not block.**

The change is the smallest coherent resolution of the plan's conflicting requirements: `is_real_user_prompt` is an allowlisted boolean whose key ends in `_prompt`, while content-bearing string values must remain impossible.

Independent wire probe used an allowlist containing `prompt_text`, `file_path`, `user_prompt`, and `is_real_user_prompt`, then captured all four values:

```json
{
  "properties": {
    "is_real_user_prompt": true,
    "platform": "x",
    "product_name": "x",
    "package_version": "1",
    "schema_version": 1,
    "$process_person_profile": false
  },
  "rejected": 3
}
```

Thus string `prompt_text`, string `file_path`, and string `user_prompt` were rejected even while explicitly allowlisted; the boolean survived. The privacy invariant for content values remains intact.

### Deviation 2 - budget raised 880,000 -> 900,000

**Judgment: unacceptable; blocks.**

Verified supporting claims:

- The justification comment exists and records the measured 891,384-byte artifact, attempted trim, existing `posthog-node`, and purity result.
- `bun test packages/omo-senpi/src/bundle-size.test.ts packages/omo-senpi/src/bundle-purity.test.ts` reports `3 pass, 0 fail` under the raised ceiling.
- `packages/omo-senpi/package.json` is byte-unchanged from base; no package manifest or lockfile dependency diff exists; no opencode/codex source diff exists. `posthog-node` was already present through telemetry-core.
- The committed artifact marker source digest is `cb9259fee86de081b71f916716567e54b674e6a196869c85727625bc9412501d`, and fresh direct rebuilds produced the same source digest. Bun's minified body is nondeterministic across rebuilds, so raw body SHA changes are not a stale-source signal. The standard `build-extension.mjs --check` could not complete because the pre-existing staged agent-toolkit runtime does not match its built source; this source/runtime mismatch is unchanged by this branch.

Nevertheless, the deviation conflicts with explicit non-negotiable plan text in three places:

- Must-NOT: `MUST NOT raise BUDGET_BYTES`.
- Todo 11: final bundle must remain under `880_000`; if over, trim/lazy-load and `NEVER raise the budget`.
- Success criteria: budget unchanged.

Current facts:


The bundle does not satisfy the planned 880KB acceptance. The rationale explains the decision but does not make it plan-compliant.
