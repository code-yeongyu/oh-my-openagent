PR #6500 live Codex app-server QA, Stop hook enforced - 2026-08-03

WHAT WAS TESTED

The AGENTS.md-mandated first-party Codex surface for this change: a real
`codex app-server` turn against an isolated `CODEX_HOME` and a LOCAL mock model,
with the driver configured to FAIL unless the `stop` lifecycle event completes.

  CODEX_BIN=<native-codex.exe> \
  bash .agents/skills/codex-qa/scripts/app-server-drive.sh --plugin --expect stop

`--expect stop` is passed as a FLAG, not as an environment variable. This is the
correction described in `app-server-plugin-20260731.txt`: the script resets
`EXPECT=""` at line 57 and reads it only from `--expect` at line 62, so an
exported `EXPECT` is discarded and the default
`sessionStart,userPromptSubmit` assertion is used instead.

The verbatim captured output is committed alongside this file as
`app-server-plugin-expect-stop-20260803.raw.txt`.

WHY IT IS ENOUGH

The AGENTS.md Codex gate asks for proof that the changed hook fires in a real
`codex app-server` session under an isolated `CODEX_HOME`. The assertion is now
enforced by the harness rather than asserted in prose: the driver was told the
run is a failure unless `stop` completes, and it exited 0 having recorded a
`hook/completed` for the changed component's own Stop registration.

The DECISION the hook makes (returning empty when the last assistant message
carries the external-blocker marker on line 1, or on line 2 after the mandatory
`ULTRAWORK MODE ENABLED!` opener, and continuing otherwise) is pinned separately
by the component tests in `green-component-vitest.txt` and by the before/after
CLI smoke in `cli-smoke-before-fix.txt` / `cli-smoke-after-fix.txt`. This file
covers live execution; those cover the branch decisions.

RESIDUAL RISK

The mock model ends the turn immediately, so the Stop hook here runs against a
session with no continuation state on disk, which exercises the hook's early
return path rather than a full resume decision. The resume decisions are covered
by the component tests and the CLI smoke rather than by this live turn.

WHAT WAS OMITTED

The absolute native Codex binary path, the temporary sandbox path (shown as
`<ISOLATED_CODEX_HOME>`), the repository path (`<REPO_ROOT>`), and the raw
stderr tail were redacted or summarized. The redacted stderr tail contained only
two benign notices: codex declining to create PATH aliases under a temp
`CODEX_HOME`, and project-local config/hooks being untrusted inside the sandbox
so that only the installed plugin-cache hooks load, which is precisely the
isolation this case relies on.
