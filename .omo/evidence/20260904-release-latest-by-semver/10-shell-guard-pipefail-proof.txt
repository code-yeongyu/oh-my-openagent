# Why the resolve step needs `set -euo pipefail`, proven with stubs on mengmotaMac (bunshin).
#
# The hole: `LATEST_FLAG="$(gh release list ... | bun script/release-latest-flag.ts "$VERSION")"`.
# If `gh release list` fails (auth/network), the pipeline still yields an EMPTY tag list, which
# resolveLatestFlag legitimately answers `--latest` for (the "first release ever" case its unit
# test pins). The step would then create the release with the WRONG badge and still exit 0 -
# silently restoring the behaviour this PR exists to remove. The resolver cannot tell a failed
# query from an empty repo, so the SHELL must fail loudly instead.
#
# Under test here is the SHELL GUARD, not the resolver, so the resolver is replaced by an awk
# stand-in reproducing its empty-list branch (`NR==0 -> --latest`). Env isolated with `env -u`.

leak_check GH_LIST_FAILS=[1]        <- see NOTE below
healthy pipeline, env isolated:     healthy_flag=[--latest=false]
CASE C2 healthy upstream + guard:   PROCEEDED_TO_CREATE flag=[--latest=false]   C2_EXIT=0
CASE A2 failing upstream, NO guard: PROCEEDED_TO_CREATE flag=[--latest]         A2_EXIT=0   <- the hole
CASE B2 failing upstream + guard:   (no PROCEEDED line)                          B2_EXIT=1   <- closed
workspace swept: CLEANED=yes

# Conclusion: the guard aborts the step on a failed upstream query (B2) and does not disturb the
# healthy path (C2). Without it the step ships a wrong Latest badge and reports success (A2).
