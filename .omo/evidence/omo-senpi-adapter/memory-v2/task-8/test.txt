HOW WATERMARK MONOTONICITY WAS PROVEN DETERMINISTICALLY (no racing, no sleeps)
  The dangerous interleaving is scripted EXPLICITLY, not raced:
    batch A (through m2) is queued, then batch B (through m4) is queued;
    B is marked consumed FIRST, then the older A is marked consumed LATE.
  Assertions: enqueued_through_message_id stays "m4" after BOTH consumptions, and
  consumed_through_message_id also stays "m4" - the late older batch never rolls either
  watermark backward. A follow-up test then runs the NEXT settle and asserts the only
  republished range is ["m5","m6"], i.e. nothing overlapping the retained newer entry.
  Ordering frame: message ids are opaque and carry no lexical order, and a late batch's
  OWN entry list does not contain the newer batch's endpoint, so positions inside one
  batch cannot order two endpoints. Each watermark therefore persists the producing
  batch's end_snapshot_line (journal length at publication, comparable across batches),
  and an advance requires a STRICTLY greater boundary. Clocks are injected (no Date.now).
