## Tests written (given/when/then style)
1. resolved_model provider+model_id exist in registry -> ok with exact model + registry context
2. resolved_model provider was removed from registry -> model_unavailable, never drifts to substitute
3. display differs from canonical provider/model_id -> still resolves correctly (keys on provider+model_id)
4. display matches a DIFFERENT model in the registry -> resolves the provider+model_id match, never display match
5. no live parent registry available -> model_unavailable, never silently drifting to default
6. no resolved_model on spec -> model_unavailable
