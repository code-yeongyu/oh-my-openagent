## Flow

1. **All five launch tools require and forward `handoff`.** The TypeScript facade defines one required, non-empty `handoff` argument for `Execute`, `Explore`, `Plan`, and `Research` in the shared action factory, and separately for `Dispatch` (`packages/omo-opencode/src/tools/agentcontrol/tools.ts:52-69`, `packages/omo-opencode/src/tools/agentcontrol/tools.ts:105-121`). The caller forwards the complete input unchanged as MCP `arguments` (`packages/omo-opencode/src/tools/agentcontrol/tools.ts:39-49`, `packages/omo-opencode/src/tools/agentcontrol/tools.ts:73-75`, `packages/omo-opencode/src/tools/agentcontrol/tools.ts:120-122`). The Python MCP schema independently requires `handoff` for the four direct actions and Dispatch (`tools/agent_control/mcp_server.py:300-335`, `tools/agent_control/mcp_server.py:352-370`). The facade test enumerates all five as required and verifies each path reaches the runtime unchanged (`packages/omo-opencode/src/tools/agentcontrol/agentcontrol.test.ts:52-63`, `packages/omo-opencode/src/tools/agentcontrol/agentcontrol.test.ts:139-167`).

2. **Validation precedes creation.** `call_tool` validates direct actions before calling `spawn`, and validates Dispatch before calling `dispatch` (`tools/agent_control/mcp_server.py:548-564`). Consequently, direct worker insertion cannot occur until `spawn` reaches `ledger.add_worker` (`tools/agent_control/mcp_server.py:649-704`), while Dispatch cannot mark its workflow running or insert pending rows until `dispatch` begins (`tools/agent_control/mcp_server.py:816-856`). A missing direct handoff is tested to return `HANDOFF_REQUIRED` with an empty ledger (`tests/agent_control/test_mcp_v3.py:2143-2151`). Source ordering gives the same guarantee for Dispatch: an invalid handoff returns from `call_tool` at lines 560-562, before `set_workflow_running` at lines 839-840 or pending insertion at lines 847-856.

3. **Trusted metadata propagation.** Successful validation returns an ID, resolved absolute `Path`, raw-byte SHA-256, and source revision; its public response intentionally exposes only ID/path/digest (`tools/agent_control/handoff.py:36-45`, `tools/agent_control/handoff.py:137-143`). Direct launches persist those three fields in the worker row and inject them as `AGENT_CONTROL_HANDOFF_ID`, `AGENT_CONTROL_HANDOFF_PATH`, and `AGENT_CONTROL_HANDOFF_SHA256` (`tools/agent_control/mcp_server.py:696-704`, `tools/agent_control/mcp_server.py:722-737`). Dispatch stores the same metadata on every pending item (`tools/agent_control/mcp_server.py:847-856`), then reconstructs each process environment from that ledger row when the item is actually launched (`tools/agent_control/mcp_server.py:936-951`). The SQLite schema and migration path include all three columns (`tools/agent_control/ledger.py:29-60`, `tools/agent_control/ledger.py:82-105`), and `add_worker` writes them atomically with the worker row (`tools/agent_control/ledger.py:124-170`). Tests confirm direct response/environment propagation and per-item Dispatch ledger/environment propagation (`tests/agent_control/test_mcp_v3.py:2184-2203`, `tests/agent_control/test_mcp_v3.py:2206-2229`).

4. **Worker prompt behavior.** Agent finalization refuses to construct the contract unless the selected kind, worker name, report path, handoff ID, path, and digest are all present; it serializes those values into `<runtime-json>` and appends the contract to the selected preset's system prompt (`packages/omo-opencode/src/plugin-handlers/agent-config-finalizer.ts:16-44`, `packages/omo-opencode/src/plugin-handlers/agent-config-finalizer.ts:47-61`). The contract orders the worker to read the handoff before any other work, revalidate claims and decisions independently against authoritative sources, follow scope/acceptance/mutation/verification constraints, and report a blocker once if unreadable (`packages/omo-opencode/src/plugin-handlers/agent-config-finalizer.ts:41-44`). Focused tests parse the injected runtime JSON and pin the read-first/revalidation/blocker language (`packages/omo-opencode/src/plugin-handlers/agent-config-finalizer.test.ts:102-143`).

## Rejection

`validate_handoff` applies these checks in order:

- **Path:** nonblank string; `~` expansion; relative paths anchored to resolved project root; strict resolution/existence; confinement under project root; regular-file requirement; stat/read errors; UTF-8 decoding (`tools/agent_control/handoff.py:93-118`). Strict resolution also prevents a project-local symlink from escaping after resolution.
- **Size:** maximum 128 KiB, checked from `stat()` before reading (`tools/agent_control/handoff.py:10-15`, `tools/agent_control/handoff.py:108-115`).
- **Frontmatter/metadata:** opening and closing `---`, valid scalar metadata lines, no duplicate keys, and all six required keys: `schema`, `id`, `action`, `projectRoot`, `sourceRevision`, `status` (`tools/agent_control/handoff.py:13-15`, `tools/agent_control/handoff.py:48-70`).
- **Semantic metadata:** exact schema `agentcontrol-handoff/v1`; ID matching `^[a-z][a-z0-9_-]{0,63}$`; declared action equal to requested action; status exactly `ready`; declared project root resolving to the launch root (`tools/agent_control/handoff.py:119-135`).
- **Sections:** unique, present, and non-empty `Goal`, `Done when`, `Workspace`, `Scope`, `Source map`, `Claims and decisions`, `Acceptance atoms`, `Verification`, and `Deliverable`; `Execute` and `Dispatch` additionally require `Mutation boundary` (`tools/agent_control/handoff.py:16-26`, `tools/agent_control/handoff.py:73-90`).
- **Digest:** SHA-256 is computed over the exact raw bytes only after all checks pass (`tools/agent_control/handoff.py:136-143`).

The MCP converts each typed validation failure into `REJECTED` with its stable error code and detail (`tools/agent_control/mcp_server.py:582-590`). Focused tests exercise empty required sections, action mismatch, project escape, and oversize rejection (`tests/agent_control/test_mcp_v3.py:2154-2181`).

## Dashboard

Each Dispatch snapshot exposes the persisted handoff ID, path, digest, integrity status, and verified content beside worker/process/prompt metadata (`tools/agent_control/monitor.py:86-147`). The wide inspector displays `handoff <id> · <status>` (`tools/agent_control/monitor.py:393-437`), and both complete and active footers advertise `H handoff` (`tools/agent_control/monitor.py:459-475`). Pressing `H` selects the handoff view (`tools/agent_control/monitor.py:803-812`); that view renders worker name, ID, status, SHA-256, path, and scrollable document body (`tools/agent_control/monitor.py:511-545`).

The viewer does not trust current path contents. `_load_handoff` re-resolves the path inside the project, requires a regular file, rechecks the 128 KiB and UTF-8 bounds, hashes current raw bytes, and returns content only when the digest equals the launch-time ledger digest (`tools/agent_control/monitor.py:63-83`). A mismatch yields status `changed` and an empty body, preventing substituted content from rendering. The focused monitor test proves verified metadata/body rendering, then overwrites the file and proves status `changed`, empty content, and absence of the substituted text (`tests/agent_control/test_mcp_v3.py:2232-2260`).

The shared-handoff optimization is explicitly **per refresh**: `snapshot` creates a local `handoff_cache` once per call, keyed by `(handoff_path, handoff_sha256)`, and all rows sharing that pair reuse one read/hash result (`tools/agent_control/monitor.py:86-104`, `tools/agent_control/monitor.py:130-144`). A later refresh creates a fresh cache and therefore rechecks disk integrity.

## Risks

- `sourceRevision` is mandatory and returned internally in `HandoffMetadata`, but it is not compared with the current Git revision and is not among the three fields persisted/injected (`tools/agent_control/handoff.py:36-45`, `tools/agent_control/handoff.py:137-143`). It is provenance, not freshness enforcement.
- Validation and worker reading are separated in time. The worker receives the launch digest, but the system contract instructs reading/revalidation rather than implementing a runtime-enforced digest check before worker use (`packages/omo-opencode/src/plugin-handlers/agent-config-finalizer.ts:16-44`). The dashboard detects later substitution and suppresses it, but that monitor defense does not itself prevent a worker from reading changed bytes.
- The core `spawn`/`dispatch` methods still type their handoff parameter as optional for internal compatibility (`tools/agent_control/mcp_server.py:649-661`, `tools/agent_control/mcp_server.py:816-824`). Mandatory enforcement is at both public schemas and `call_tool`; future internal callers must not bypass that boundary.
