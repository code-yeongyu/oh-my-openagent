# P1: synchronous continuation of a completed background task

Base HEAD: `6ada7212a696770a5f8f5f3041db343f38f85610`. Local uncommitted fix.

## Fix and failing-first proof

Terminal recording now runs before background-task error routing. It accepts
untracked sessions and current sync-attached sessions, including retained
completed/error tasks. Historical attempts are excluded. Ordinary background
error handling, fallback routing, and terminal task state are unchanged.

The new deterministic Date.now regressions initially failed for both completed
and error attachments: expected the terminal error after the grace, received
null. The historical-attempt regression passed. After the fix, all 246 related
tests passed together (777 assertions, zero failures). Tests also cover transient
errors, the 9,999/10,000 ms boundary, recovery clearing, and detached terminal tasks.
No sleeps or polling were added to unit tests.

## Real OpenCode cases

Both cases passed on their first P1 execution using OpenCode 1.18.30:

| Case | Actual native child history | Tool duration | Result |
| --- | --- | --- | --- |
| fresh | user, user | 10,141 ms | terminal SSE error returned to caller |
| attached | user, assistant, user, user | 13,080 ms | terminal SSE error returned to caller |

The attached case creates a real child, registers it with the production
BackgroundManager.trackTask, obtains real successful model output, and awaits
the manager's actual completion callback with a bounded timeout. It asserts
that the task is completed and still retained before invoking the production
executeSyncContinuation. That function performs the real attachSyncContinuation.
The fixture does not set task status or mock client/events/poller.

The attached child's earlier assistant has native finish=stop and no error;
its two continuation messages are user-only. Thus a prior successful model turn
or assistant-message error cannot satisfy terminal continuation propagation.
Both captures prove exact equality among child session.error, persisted native
tool output, and function_call_output in the caller's real provider request.
The real ten-second grace is retained. The attached duration also includes its
initial background completion; it is not claimed as continuation-only latency.

Lead changes to exact matching SSE wait and bounded process cleanup remain
intact. Old captures and evidence files remain unchanged. New captures are
`p1-fresh-live-result.json` and `p1-attached-live-result.json`.

roots/TMPDIR and empty sandbox cwd. No real credentials/config/private skills
are inherited; the provider is deterministic loopback HTTP with a public dummy
key. Real database counts were 8103 -> 8103 for each run. Raw requests, events,

or category dispatch QA. Error-status attachment is covered by fake-clock unit
regression, not a separate live case. Windows/full-repository CI was not run.
